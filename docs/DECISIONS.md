## D1 · 课程范围聚焦 AIDC 智算网络可观测

- **状态**：已定（v0.0）
- **背景**：手上有两套课程原型——AIDC 可观测（17 课）与存储网络深水区（25 课）。
- **选项**：A 聚焦 AIDC；B 合并 42 课；C 以存储网络为主线；D 全新主题
- **决策**：选 A。以 17 课打底，扩展到 24 课。
- **理由**：单一主题边界清晰，对读者承诺明确；合并会让「这门课到底教什么」失焦，
  且去个人化工作量翻倍。
- **代价**：放弃存储网络方向的内容资产（可作后续姊妹项目）。

## D2 · 站点框架选 Astro Starlight

- **状态**：已被 D11 取代（v1.x 切到 VitePress）
- **选项**：Astro Starlight / VitePress / GitBook / 纯 HTML
- **决策**：Astro Starlight + GitHub Pages。
- **理由**：视觉更现代、内置 Pagefind 搜索、Markdown 单源便于 PR、静态部署零成本。

## D3 · Lab 分两层，L1 必须零特权可跑

- **状态**：已定（v0.0）
- **背景**：PFC / ECN 是硬件行为，纯软件仿真无法行为等价；containerlab 在 macOS 需特权或虚拟机。
- **决策**：L1 层（模拟数据面，`go run` 即跑）+ L2 层（containerlab 真拓扑，依赖 Docker/Linux）。
- **理由**：不分层会流失大部分读者；可复现性直接决定项目口碑。
- **代价**：L1 的「教学级模型」可能被质疑真实性 → 每个 lab 开头显式声明并给真机验证路径。

## D8 · L2 lab 走双模式：剧本锁 expected，注入需特权

- **状态**：已定（v0.4）
- **背景**：L2 的两个 lab 要真拓扑（Docker + containerlab），但 CI 无特权，多数读者本机也没有。
  若 L2 只能真跑，等于既进不了 CI，也进不了大部分人的工作流。
- **选项**：A 只做真跑，CI 跳过；B 只做模型，不做真拓扑；C 双模式拆开
- **决策**：选 C。每个 L2 lab 分两层能力：
  - 默认模式（仅 Go）：生成注入剧本、生成遥测指纹样本、给出判读结论，产出锁进 `expected/`
  - 真跑模式（`make deploy` / `make inject` / `make collect`）：需要 containerlab 与特权
- **理由**：判据、剧本、散列分布都能被 CI 校验，也能被 diff 住；真拓扑留给有环境的机器。
  读者不会卡在第一条 `docker` 命令上，这是 D3 分层承诺的延续。
- **代价**：容器里造不出真 pause 帧，样本里的 `pause_pct` 是模型补的。
  每个 L2 lab 开头必须声明哪几列来自模型，并在 README 给真机验证路径。
- **配套约束**：拓扑文件与注入计划的一致性靠单测守住（`topo_test.go` 解析 `topo.clab.yml`
  再核对命令里的接口名），因为接口名写错这类问题只有真跑才暴露。

## D9 · v1.0 冻结课程结构，只接受纠错类 PR

- **状态**：已定（v1.0）
- **背景**：23 课的结构经过三个版本迭代（v0.1 迁移、v0.3 补八篇、v0.4 补 lab），
  已能覆盖「看什么、为什么、怎么看」的完整链路。继续加课会把维护成本推过收益。
- **决策**：v1.0 起冻结课号、模块划分与每课六段结构。新增内容走三条路：
  - 机制纠错：随时接受，需带可验证来源
  - 判读补充：并入现有课的「判读与实操」段，不新开课
  - 新主题：先开 issue 讨论，够一个模块的体量才立 v2 分支
- **理由**：结构一变，链接、锚点、lab 的课程映射、附录索引全要跟着动。
  v0.3 与 v0.4 已经付过两次这种代价。
- **代价**：读者提的「能不能讲讲 XX」类需求，多数会被并进现有课而不是单独成课。

## D10 · 文风体检分硬项与观察项，不追求三条标点指标同时达标

- **状态**：已定（v1.0）
- **背景**：`style-check.py` 长期报三项红（≤10 字分句占比、整句 P90、逗号占比），
  而 COURSE-STYLE §2.1 已经论证它们与「句短、分句成串」在几何上互相牵制。
  脚本口径没跟上文档，导致 CI 永远红，红着红着就没人看了。
- **决策**：按 §2.1 拆两档：
  - **硬项**（阻塞）：分号 0、感叹号 0、超 60 字句 ≤3%、分句均长 12–16、中位 11–14、
    逗号 ≥30%、冒号 ≤20%、顿号 ≥8%
  - **观察项**（只打印）：≤10 字分句占比、整句 P90
- **理由**：一个永远红的检查等于没有检查。把「不能兼得」的指标降级为观察项，
  硬项才有约束力。
- **代价**：放弃把 ≤10 字分句占比从 41% 拉到 45%。这个改动要逐句重写 25 篇，
  收益是 4 个百分点，代价是内容风险。

## D11 · 站点底层从 Astro Starlight 切到 VitePress

- **状态**：已定（v1.x）
- **背景**：站点只需要「Markdown 单源 + 侧边栏 + 搜索 + 静态部署」四件事，
  而 Starlight 带来的 Astro 分层（.astro 组件、content collections、MDX 编译链）在维护上偏重：
  改一处首页版式要动 Astro 组件与 TS schema，贡献者还得懂 Astro 语法。
- **选项**：A 继续 Starlight；B 切 VitePress；C 纯 HTML 模板
- **决策**：选 B。内容改为纯 Markdown + 容器语法，配置收敛到 `.vitepress/config.mts` 与 `theme/`。
- **理由**：
  - 内容不再需要 MDX：Aside → `::: tip/info/warning`，折叠答案 → `::: details`，
    PR diff 更接近纯文本，贡献门槛从「会 MDX」降到「会 Markdown」
  - 侧边栏在 `config.mts` 里按目录 + frontmatter 自动生成，仍是「新增课不改配置」
  - 部署链更短：`pnpm build` + `upload-pages-artifact`，不再依赖 `withastro/action`
  - 首页仍是自定义视觉（hero 光晕/指标条 + 7 张模块卡），只是从 `.astro` 换成 Vue 组件
- **代价**：
  - URL 从 `/00-intro/00-what-problem/` 变为 `/00-intro/00-what-problem`（`cleanUrls`），
    旧外链需要靠 404 兜底
  - 搜索从 Pagefind 换成 minisearch 本地搜索，中文分词都一般（D7 的结论不变）
  - 一次性迁移成本：79 处 Aside、95 处 `<details>` 的语法改写，脚本可完成
- **被否决**：C —— 无搜索、无侧边栏，回归到要自己维护站点的状态。

## D12 · 全部 23 课按 TCP 小册的叙事重写

- **状态**：已定（v1.1）
- **背景**：v1.0 冻结的是**课号与模块划分**（D9），不是每讲的段落骨架。原骨架
  （本节目标 / 机制拆解 / 判读与实操 / 练习 / 本课要点）判断准确，但读者从头读到尾
  记不住重点，且开篇一律是「上一课确立了结论：……」，冷得像内部周报。
- **样本**：《深入理解 TCP 协议：从原理到实战》前 3 篇（开篇词、历史与分层、TCP 概述）。
  拆解见 `corpus/style/NARRATIVE-DIGEST-tcp-book.md`。
- **决策**：23 课全部按新骨架重写，规则落进 `corpus/style/COURSE-STYLE.md` §3 与 §14：
  开场一句总括句并在结尾原样再现、`0x01` 连编号、新增 `## 小结`、习题末尾留一道
  不给答案的题、机制课先给一条能跑的命令。
- **理由**：
  - 一句能被背下来的总括句，比六条并列的要点更接近读者合上页面后剩下的东西
  - `0x01` 编号便于口头与文档互相引用（「回到 0x03」）
  - 晴一两处自己的经历能让读者站到同一侧。原骨架通篇正确但没有入口
- **代价**：
  - 课号与 URL 不变，但**锚点变了**：`#本节目标` → `#学完这一讲，你应该能`，
    `#练习` → `#习题`。外部链接若指向旧锚点会落到页首
  - 每讲平均篇幅 +15%，因为多了开场总括句与 `## 小结`
  - 文风检查的三个观察项（≤10 字分句占比、整句 P90）从达标退回「放行」区，
    这是口语化叙事的必然代价（§2.1 已论证不可兼得）
- **不采纳的部分**：小册的设问式小标题、结尾口号与 emoji、截图承载关键信息、
  句号偏少。这些在 §9 黑名单里，重写时一处未取。

## D13 · 篇名去编号、课标题改小册式两段式

- **状态**：已定（v1.2）
- **背景**：D12 把课内叙事对齐了 TCP 小册，但**标题层没跟上**。侧边栏与首页挂着
  `M0`–`M6`，课名是「PFC：无损网络怎么做到不丢包」这类单段式说明书命名。
  两处都是读者第一眼看到的东西，`M1`、`M2` 对读者没有信息量，还得靠副标题解释。
- **样本**：《深入理解 TCP 协议》的课名一律两段——「一个神奇的状态 —— TIME_WAIT」
  「繁忙的贸易港口 —— 聊聊端口号」。篇名不带 M，用「网络工具篇（一）」这种中文序号。
- **决策**：
  - 篇名改中文序号加一句判断：开篇 · 认识这门课 / 第一篇 · 两套世界观 /
    第二篇 · 不丢包的代价 / 第三篇 · 流量与连线 / 第四篇 · 把现场变成数据 /
    第五篇 · 从数据到结论 / 第六篇 · 路线与收口
  - 课标题统一写成 `主标题 —— 副标题`：主标题给一句能记住的判断或画面，副标题给技术点
  - 正文提到篇章处称「第 X 篇」，不再出现 `M<数字>`
  - 里程碑表同步去掉 `M0`–`M5` 前缀，只留版本号，避免和篇号撞号
- **理由**：主标题承担记忆，副标题承担检索，两段各干一件事。`M<数字>` 两者都不承担。
  课号、文件路径、URL、锚点全部不动，所以这次改动不产生外链成本。
- **代价**：篇名里的判断句会随时间变旧（比如第四篇的「把现场变成数据」偏修辞），
  改一次就要同步 OUTLINE、config.mts、首页卡片三处。
  三处目前都以 OUTLINE 的「篇名对照」表为准。
- **不做**：小册那种问句式课名（「兄弟你还活着吗」）。COURSE-STYLE §7 规定标题类问号 0。
