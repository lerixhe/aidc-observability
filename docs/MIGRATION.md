# 原型迁移与脱敏规则

> 适用对象：`reference/archive-aidc/`（17 课私有原型）→ `site/`（公开课程）。
>
> 该目录已在 `.gitignore` 中排除。任何内容在**未按本文规则处理前，一律不得进入版本库**。

---

## 一、迁移流程（每课四步）

1. **结构转换**：`scripts/html2mdx.py` 解析原 HTML 的 `.card` 结构，产出 MDX 骨架
   （脚本只解决 70% 的机械转换，语义改写必须人工做）
2. **叙事重写**：按第三节规则逐块改写，特别是 `link-exp`（经验映射）与练习说明
3. **脱敏扫描**：按第四节白名单 grep 核查通过
4. **补参考资料**：每课 `## 参考资料` 不得为空，机制类断言须有可验证来源

### 结构映射表

| 原 HTML | MDX / Starlight |
|---|---|
| `<header class="hero">` + `.lesson-no` + `<h1>` | frontmatter `title` + `description` |
| `div.breadcrumb` | 删除（Starlight 自带面包屑） |
| `div.card` + `<h2>` | `##` 小节 |
| `div.compare`（old / new 双栏） | Markdown 表格 |
| `div.link-exp` | `<Aside type="note" title="经验映射">` |
| `div.warn` | `<Aside type="caution">` |
| `div.goal` | `<Aside type="tip">` 或列表 |
| `div.keycard` | `<Aside type="tip" title="本课要点">` |
| `quiz-item` + `<details>` | 保留 `<details>`，改标题为「参考答案 + 评分维度」 |
| `div.nav` 上下课链接 | 删除（Starlight pagination） |
| 内联 `<style>` | 删除（Starlight 主题） |
| `<code>` / `<pre>` | 原生 Markdown 代码块（带语言标记） |

## 三、脱敏红线（硬性）

以下内容**任何情况下不得进入公开内容**：

- [ ] 前雇主的内部系统名、平台代号、内部项目名
- [ ] 真实集群规模、机房位置、网络架构图、设备型号清单
- [ ] 内部指标口径、告警阈值、SLA 数字（若来自内部资料）
- [ ] 任何同事姓名、组织结构、内部汇报关系
- [ ] 未公开的事故报告细节与客户信息
- [ ] 内部代码片段（重写为最小复现示例）

**可保留的**：
- 公开可查的协议规范、RFC、论文、厂商公开文档
- 公开技术博客/会议演讲中已披露的实践
- 抽象后的方法论（「路径级覆盖比设备级聚合更早发现劣化」）
- 个人能力层面的描述（不绑定具体雇主内部资产）

## 四、脱敏扫描脚本（迁移后必跑）

```bash
# 词表维护在 scripts/sensitive-words.txt（不入库，仅本地）
grep -rniE '京东|蚂蚁|阿里云|谛听|阿福|阿宝|灵光|薪资|面试官|一面|二面' site/ \
  && echo "❌ 发现敏感词，请修正后再提交" || echo "✅ 脱敏扫描通过"
```

`scripts/sensitive-words.txt` 加入 `.gitignore`（本地维护，避免词表本身泄露信息）。
