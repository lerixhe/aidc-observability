# 写作规范

> 两条硬约束：不用 emoji（D22），不用下面这十五类句式（D23）。
> 只管新写的内容与正在改动的段落，存量不追溯。
> 不设脚本检查。写完自己读一遍，命中就改。

## 1. 禁用句式

这些句式的共同点是没有信息，只承担转折、铺垫、递进。删掉之后句子短了，意思没少。

| 禁用 | 改法 |
|---|---|
| 不是A，而是B / 这不是关于A | 直接说 B，不立靶子 |
| 为了……， | 删「为了」，目的改成条件或结果 |
| 如果说A，那么B | 两句并列，删「如果/那么」 |
| 无论是A还是B | 让步压成一个词，或整句删 |
| 直到A，才B | 换成经验陈述，主语放人 |
| 不仅……而且/更 | 后项用逗号接，删「而且」 |
| 当……时 | 删时间从句，直接上动作 |
| 事实上 / 实际上 | 直接删，它只在暗示「你可能以为错」 |
| 有一种A，就是B | 主宾换位，一句话说完 |
| 值得注意的是 / 需要注意的是 | 直接说事 |
| 随着……的发展 / 在当今……时代 | 删背景句，直接给事实 |
| 从……角度来看 | 换成「对后端来说，……」 |
| 让我们…… / 在这个过程中 / 综上所述 | 全删 |
| 之所以……是因为 / 看似……实则 / 与其说……不如说 | 只留后半句或判断 |
| 首先 / 其次 / 最后（三连） | 用编号列表或直接并列 |

「值得多看一眼」「值得单独说一句」这类提示语，按「值得注意的是」同一条处理，直接说事。

「最后」作时间副词不算三连（「省得读到最后来骂人」「最后这些判据汇总成选型」），它给的是先后，不是结构胶水。真需要排步骤，用编号列表。

## 2. 自测四问

写完一节，自己过一遍：

1. 有没有一句能当标题的硬判断？
2. 有没有一个具体数字或单位？
3. 长句里每个「这/其」都能一眼对上指代吗？
4. 结尾是动作还是感慨？

四条里缺两条以上，这节大概还没写完。

## 3. 边界

代码、标识符、API 名、错误信息、精确的技术陈述保持原样，不受文风约束。

引用第三方原文（RFC、论文、别人的文章）照抄，不改写法，包括原文里的禁用句式。

本规范与 ADR 条目在列举禁用句式时，拿它们当例子不算命中。黑名单本身就是一张用例表。

真实的条件分支照写。「缺 Docker 时降级，不是失败」这类句子留着，它给的是事实。黑名单针对的是「如果说 A，那么 B」这种只为铺路搭出来的假前提。

用户用英文提问就用英文回答，节奏不变：短句、结论在前、不铺垫。

## 4. 适用范围

适用：课程正文、开篇、习题解析、说明容器、README、`docs/` 下除 ADR 历史条目以外的文档、commit message。

不适用：代码块里的终端输出与错误信息；第三方引用；`docs/DECISIONS.md` 的历史条目（属历史记录，不回改）。

`site/`、`labs/`、根 README 中存量文字的 emoji 与句式的清理不在本规范承诺内（D22 范围外二）。

## 5. 检查方式

无脚本，靠读完自查。

理由在 D21：把语感写成阈值（分句字数、感叹号个数），写作时多一道自我审查，成本高于收益。黑名单不属于阈值，它判有无，而且表足够短，眼睛能过一遍。

## 6. 小标题不带序号

`### 0x01` / `### 0x02` 这类编号不再用，直接写断言或内容名。理由与存量处理见 D24。

| 不要写 | 写成 |
|---|---|
| `### 0x03 差异三：故障代价` | `### 差异三：故障代价` |
| `### 0x05 一张能贴在值班台前的对照表` | `### 一张能贴在值班台前的对照表` |

标题里已经写着「差异三」，外面再套一层 `0x03`，读者得先把两个序号对一遍才知道说的是同一件事。

指代前后小节用标题文字（「差异二：丢包语义」），不用编号。存量 148 处保持原样，哪讲重写就顺手清掉。
