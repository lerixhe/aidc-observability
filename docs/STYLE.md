# 写作规范

> 三条硬约束：不用 emoji（D22），不用下面这十五类句式（D23），不用第 7 节的比喻与报幕（D25）。
> 只管新写的内容与正在改动的段落，存量不追溯。
> 不设脚本检查。写完自己读一遍，命中就改。

## 1. 禁用句式

这些句式的共同点是没有信息，只承担转折、铺垫、递进。删掉之后句子短了，意思没少。

| 禁用 | 改法 |
|---|---|
| 不是A，而是B / 这不是关于A | 直接说 B，不立靶子 |
| 为了……， | 删「为了」，目的改成条件或结果 |
| 如果说A，那么B | 两句并列，删「如果/那么」 |
| 无论是A还是B | 让步压成一个词，或整句删 |
| 直到A，才B | 换成经验陈述，主语放人 |
| 不仅……而且/更 | 后项用逗号接，删「而且」 |
| 当……时 | 删时间从句，直接上动作 |
| 事实上 / 实际上 | 直接删，它只在暗示「你可能以为错」 |
| 有一种A，就是B | 主宾换位，一句话说完 |
| 值得注意的是 / 需要注意的是 | 直接说事 |
| 随着……的发展 / 在当今……时代 | 删背景句，直接给事实 |
| 从……角度来看 | 换成「对后端来说，……」 |
| 让我们…… / 在这个过程中 / 综上所述 | 全删 |
| 之所以……是因为 / 看似……实则 / 与其说……不如说 | 只留后半句或判断 |
| 首先 / 其次 / 最后（三连） | 用编号列表或直接并列 |

「值得多看一眼」「值得单独说一句」这类提示语，按「值得注意的是」同一条处理，直接说事。

「最后」作时间副词不算三连（「省得读到最后来骂人」「最后这些判据汇总成选型」），它给的是先后，不是结构胶水。真需要排步骤，用编号列表。

## 2. 自测六问

写完一节，自己过一遍这六条：

1. 有没有一句能当标题的硬判断？
2. 有没有一个具体数字或单位？
3. 长句里每个「这/其」都能一眼对上指代吗？
4. 结尾是动作还是感慨？

再补两问，专治修辞：

5. 有没有比喻？它算不算技术领域内的术语解释？
6. 这一节开头两句，是在交代本讲结构，还是在讲内容？

六条里缺三条以上，这节大概还没写完。

## 3. 边界

代码、标识符、API 名、错误信息、精确的技术陈述保持原样，不受文风约束。

引用第三方原文（RFC、论文、别人的文章）照抄，不改写法，包括原文里的禁用句式。

本规范与 ADR 条目在列举禁用句式时，拿它们当例子不算命中。黑名单本身就是一张用例表。

真实的条件分支照写。「缺 Docker 时降级，不是失败」这类句子留着，它给的是事实。黑名单针对的是「如果说 A，那么 B」这种只为铺路搭出来的假前提。

用户用英文提问就用英文回答，节奏不变：短句、结论在前、不铺垫。

## 4. 适用范围

适用：课程正文、开篇、习题解析、说明容器、README、`docs/` 下除 ADR 历史条目以外的文档、commit message。

不适用：代码块里的终端输出与错误信息；第三方引用；`docs/DECISIONS.md` 的历史条目（属历史记录，不回改）。

`site/`、`labs/`、根 README 中存量文字的 emoji 与句式的清理不在本规范承诺内（D22 范围外二）。

## 5. 检查方式

无脚本，靠读完自查。

理由在 D21：把语感写成阈值（分句字数、感叹号个数），写作时多一道自我审查，成本高于收益。黑名单不属于阈值，它判有无，而且表足够短，眼睛能过一遍。

## 6. 小标题不带序号

`### 0x01` / `### 0x02` 这类编号不再用，直接写断言或内容名。理由与存量处理见 D24。

| 不要写 | 写成 |
|---|---|
| `### 0x03 差异三：故障代价` | `### 差异三：故障代价` |
| `### 0x05 一张能贴在值班台前的对照表` | `### 一张能贴在值班台前的对照表` |

标题里已经写着「差异三」，外面再套一层 `0x03`，读者得先把两个序号对一遍才知道说的是同一件事。

指代前后小节用标题文字（「差异二：丢包语义」），不用编号。存量 148 处保持原样，哪讲重写就顺手清掉。

## 7. 修辞黑名单

第 1 节管连接词，这一节管修辞。判据同一条：

**把这句话删掉，读者掌握的技术事实少了吗？**

少了就留。没少，它只是给内容换了个门牌，删。

### 7.1 跨界比喻

拿工程以外的东西解释协议行为，是最容易写脱缰的一类。它读起来像洞察，读者得到的却是一个和协议无关的联想。

| 不要写 | 写成 |
|---|---|
| 把 RDMA 那台发动机，装到以太网这副底盘上 | RoCE 是把 IB 传输层原样搬到以太网上，外面套一层封装 |
| RDMA 丢包像补牙，哪颗坏补哪颗；TCP 像重贴一整面墙的墙纸 | RDMA 走 Go-Back-N，丢一个包从窗口早期整段重发，一次丢包可能触发几十个包重发 |
| 有损网络里丢包像下小雨，出门带把伞；无损网络里丢包像水管爆了 | 有损网络里丢包由协议栈重传补上，应用无感；无损网络里重传粒度是窗口级的，代价被同步放大 |
| 一万个人同时把材料塞进同一个窗口 | 上万个源在同一时刻朝一组端口发送，出口队列在几毫秒内打满 |
| 一万张卡像一个人齐步走 | 一条链路卡住几个 Rank，其余上万张卡停在屏障上等 |

允许的一类：**同一技术领域内的术语解释**。用「字节流」解释 SACK、用「队列对」解释 verbs，属于定义，不在此列。分界线是同行读者不需要额外联想就能对上；如果要先在大脑里跑一遍那个比方，才算理解协议，就已经越界。

### 7.2 商业与金融隐喻

把协议机制写成账、债、利息、责任转嫁，语气上很像有洞察，但读者拿不到新东西。技术文里够用的词只有那几个：代价、开销、成本、复杂度、故障面。

| 不要写 | 写成 |
|---|---|
| 无损这个责任转嫁给以太网，转嫁要付利息 | 以太网默认会丢包，要靠 PFC / ECN 加全 Fabric 一致配置把它补出来 |
| RoCE 的负债四笔 | RoCE 的代价四笔：配置量、故障面、抓包边界、手工调参 |
| 账单按 GPU 小时开 | 一次故障的损失按卡时计：卡数 × 回退时长 × 单卡时成本 |

### 7.3 报幕

正文不是大纲。把「上一讲讲了什么、这一讲讲什么、分几层讲」写进正文，读者要多读一段不包含信息的话。承接只需要一句，作用是接上前一讲的结论，不是交代本讲结构。

| 不要写 | 写成 |
|---|---|
| 这一讲回答「为什么」的第一层，先把结论摆出来 | 直给结论，前面不绕 |
| 往下走一层：…这一讲把利息算清楚 | 上一讲讲完 RDMA 依赖无损网络，以太网天生没有这个能力 |
| 这一讲不教你任何新工具，只把这四条假设逐条拆开。拆完你才知道后面每一讲在看什么 | 这一篇不引入新工具，只拆四条假设（或直接进入内容） |
| 四条假设，逐条来。每条配一个生活里的对照，记对照比记术语管用 | 删。怎么记是读者的事 |

### 7.4 一句一段

一句一行的断句节奏，在技术文里只降低信息密度。段落写回正常长度，一个自然段做完一件事。

| 不要写 | 写成 |
|---|---|
| 发动机没换，底盘换成你天天摸的那一副。／麻烦全在底盘上。 | 合并成完整句子，一句讲一个事实 |
| 两条约束合起来，需要的是一条时延低的路径。／它就是 RDMA。 | …需要一条时延低而稳、不吃 CPU、不做多余拷贝的路径，这就是 RDMA |

例外：一节末尾的判断句可以单独成段用于收束，一节不超过一次。

### 7.5 排比与金句

对称、押韵、反问结尾都不产生信息。它们让文章读起来完整，代价是让读者以为自己学到了东西。

| 不要写 | 写成 |
|---|---|
| 四条换完，你手上的工具一个没扔，看问题的角度已经换了 | 删，或换成一句技术结论 |
| 四条假设，换掉的就是这四条 | 删 |
| 砍到这一步，「网络必须从机制上不丢包」就不是一句口号了，它是前提 | 网络必须从机制上保证不丢包，这是 RDMA 的前提 |
| 两种命 | 影响差一个量级 |

### 7.6 教学旁白

告诉读者该怎么读、怎么记、怎么想，属于旁白。课程正文只负责给事实和判断。

| 不要写 | 写成 |
|---|---|
| 这一节是本讲最要紧的地方，读慢一点 | 这一条是四个差异里最要紧的，后面几乎所有口径调整都从这里来 |
| 还有一条是心法：把因果链自己推一遍，推得出来就不用背了 | 删。因果链已经在正文里 |
| 别把两者混着算 | 删，或者把不能混算的理由写出来 |
| 面试问到，答这条链，别背定义 | 删。课程不用面试语境（见 OUTLINE） |
| 这组数字比什么都直接 | 典型值 1.4 微秒，最差 4.9 微秒 |

「值得多看一眼」这类提示语，按第 1 节的「值得注意的是」处理，直接说事。

### 7.7 什么可以留

- **数字与单位**：1.4 微秒、4096 条流、`1e-5`、xoff / xon 水线值
- **命令与典型输出**：判读必须有参照物
- **同行共用的技术比方**：门限、水线、窗口、屏障、木桶效应。用一次解释清结论即可，不延伸
- **带依据的立场判断**：说明白「这套方案在运维上是两套体系」，比中立词更省读者时间

## 8. 洗稿的七个动作

按这个顺序过一遍，比从头重写省力，也不容易漏。

1. **找比喻**：搜「像」「相当于」「好比」「等于为」，逐个判断是不是同一技术领域内的术语解释
2. **找金融词**：搜「账」「债」「利息」「转嫁」「负债」「本金」
3. **找报幕**：看每节开头两句，有没有交代本讲结构
4. **找碎句**：数单句成段的地方，一节出现过两次就是节奏问题
5. **找金句**：看每节最后一句，有没有排比、押韵、反问
6. **找旁白**：搜「记住」「别」「你会发现」「读懂」「心法」「说白了」
7. **补实质**：删完之后如果一节变薄了，用数字、命令、故障现象补回去，不用形容词补

第七步是关键。只删不补，文章会变得短而空，下一轮又会长回修辞。
