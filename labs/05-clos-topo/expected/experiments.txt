== 实验一：流数怎么影响散列均匀度（policy=L4，随机 5 元组，seed=42）==
流数    leaf1     leaf2     leaf3     leaf4     最差极化度  CV     判定
8       0:2       1:1       0:1       1:1       2.00        0.71   严重不均
32      2:5       3:4       4:1       8:2       1.60        0.48   严重不均
128     16:9      11:15     18:12     21:13     1.28        0.22   明显不均
512     50:46     46:58     64:53     73:55     1.14        0.10   可接受
2048    205:215   230:239   223:195   235:225   1.07        0.04   可接受

读法：
  1. 流数是散列均匀度的第一变量。八条流时两条上行只用上一条，不奇怪
  2. 极化度 1.0 是完美均分，2.0 是「两条上行只用到一条」的极端
  3. 少流的瓶颈不是算法，是样本量：你在用八次抽样去逼近 50%

== 实验二：hash 口径（64 条流，源目 IP 固定、端口递增）==
口径                最差极化度  CV     最大链路占比  说明
L3（src/dst IP）      2.00        1.00   100%          端口不参与，同一对主机的连接全撞一条上行
L4（五元组）             1.00        0.00   50%           端口参与，连接被摊开，但流数仍决定摊得多平

读法：
  1. 三层口径下不是「散得不好」，是根本没用端口这一维，等价于只有一条路
  2. 内核里由 net.ipv4.fib_multipath_hash_policy 控制：0 走三层，1 走四层
  3. 默认值取决于发行版与内核版本，接手集群时先确认这个开关，别猜

== 实验三：同质大象流（64 条流，源目 IP 与端口全部相同）==
口径                最差极化度  CV     最大链路占比
L3（src/dst IP）      2.00        1.00   100%
L4（五元组）             2.00        1.00   100%

读法：
  1. 五元组一模一样时，两种口径都判同一条路。这不是算法问题，是输入没有新信息
  2. 训练流量恰好长这样：rail 对齐的 AllReduce，5 元组在整个训练周期不变
  3. 所以智算网络靠结构而不是靠 hash：rail-optimized 拓扑把流量预分到不同轨道
  4. hash 能做的是「多流之间摊平」，做不了「一条流自己分叉」。flowlet 与自适应路由才做后者
