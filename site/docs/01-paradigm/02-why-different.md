从 IDC 或者云网络转过来的人，手上都有一套跑了很多年的东西：链路探测、时序管道、告警收敛、根因分析。这套东西在智算中心里照样值钱，前提是先换掉四个默认假设。

这一讲不教你任何新工具，只把这四条假设一条一条拆开。拆完你才知道后面每一讲自己在看什么。

## 交付

本节的学习目标是四件事，做到了就算过关：

- 说出两边的四个差异：流量模型、丢包语义、故障代价、遥测粒度，并且讲得清每个差异的成因
- 解释「TCP 反正会重传」这句话，在 AI 训练网络上错在哪
- 把手上已有的 IDC 监控能力逐项过一遍，分清哪些能直接搬，哪些必须换
- 建立最基本的指标直觉：无损网络里，**丢包是故障信号**，日常主指标换成 PFC pause、ECN 标记率、队列水线

## 四个默认假设

四条假设，逐条来。每条配一个生活里的对照，记对照比记术语管用。

### 差异一：流量模型，小流密布撞上大象流同步突发

传统 IDC 跑的是线上业务。用户请求从南北向进出，服务之间的调用在东西向流动。这批流量好记：流很小，KB 到 MB 级，数量极多，到达随机，偶尔把某个队列顶满了，几毫秒也就排空。盯着它，看聚合、看趋势就够。

AI 训练集群里没有「用户」。一台 GPU 服务器（通常 8 张加速卡）在训练时只干一件事：和另外几百上千台机器交换**梯度数据**。单条流就能打满 200 Gbps 端口，一打就是一整个训练周期，中间不带停的。这就是典型的大象流（elephant flow）。

大象流本身还能忍，真正难办的是同步。分布式训练每算完一轮，所有 worker 在同一时刻往同一个目的地汇聚数据，这就是 AllReduce。上万张网卡同一瞬间朝同一组端口倾泻，出口队列瞬间见底，这就是 incast。

一万个人同时把材料塞进同一个窗口。塞完一轮，全体停下来算，算完再塞。每一次 AllReduce 后面跟一个全局 barrier，**每个训练步都重来一次的固定节奏**。

| 维度 | 有损 IDC（小流为主） | 智算中心（大象流为主） |
|---|---|---|
| 流向 | 南北向为主 | 东西向为主 |
| 单流特征 | KB～MB，数量极多、随机 | 单流打满端口，持续整个训练周期 |
| 负载分担 | 静态 hash 大致够用 | hash 一旦失衡，某条路径直接被单流打满 |
| 拥塞形态 | 偶发，队列很快排空 | AllReduce 周期性同步突发（incast） |

静态 hash 在随机小流下是个还行的解法，在大象流下就是一次赌博：赌输的那一次，某条路径被单条流打满，设备级聚合指标里一点水花都看不见。

### 差异二：丢包语义，从背景噪声变成事故本身

这一节是本讲最要紧的地方，读慢一点。

- **有损网络**：丢包率 0.01% 属于正常波动，TCP 静默重传补上，上层应用一点感觉都没有。丢包在你的面板上是一个数字，趋势抬头才需要看一眼，它是**排障线索**。
- **无损网络**：RDMA 把重传的活儿从内核协议栈剥走了（见 [RDMA：AI 训练为什么绕过内核](./03-rdma.md)）。内核都不知道丢了包，应用更补不上，恢复代价直接顶到毫秒级甚至更坏。整张网于是靠 PFC / ECN 从机制上避免丢包（见 [PFC](../02-lossless/05-pfc.md) 与 [ECN + DCQCN](../02-lossless/06-ecn-dcqcn.md)）。工程上普遍要求丢包率低到 `1e-5` 量级。

说白了，有损网络里丢包像下小雨，出门带把伞就过去了。无损网络里丢包像水管爆了，得先关总阀。

::: warning 关键推论

无损网络里，**丢包意味着机制性故障已经发生**：PFC 失效、配置错误、死锁前兆。它从统计量变成了信号量。

日常要盯的主指标也跟着换了一组：**PFC pause 次数、ECN 标记率、队列水线**。监控面板从此换一套口径，把老面板的阈值调紧没用。
:::

### 差异三：故障代价，从单机影响到小时 × 千卡

传统 IDC 里网络抖一下，影响的是一批请求。切个流、重试一次，用户那边多半察觉不到。

万卡集群不一样，训练是**高度同步**的。一万张卡像一个人齐步走，一条链路卡住几个 Rank，全体停下来等，谁也别想先走。

恢复手段基本只有一条：**checkpoint 回退**，从上一个存档点重跑。两次 checkpoint 之间可能隔几十分钟，一次网络故障的代价约等于「**回退时间 × 一万张卡的电费与折旧**」，按卡时结算。这相当于给整个训练任务做一次事务回滚，账单按 GPU 小时开。

所以智算网络对 MTTR 的要求从小时级压到**分钟级**。「降低智算网络 MTTR」几乎出现在每一份智算网络 SRE 的岗位描述里，原因就在这笔账上。

### 差异四：遥测粒度，从分钟轮询到秒级订阅

传统设备采集多是 SNMP 那一路：分钟级轮询端口计数器。这套粒度放在无损网络里不够用。

- PFC pause 的风暴**在几秒内**就能把队列打爆，分钟级采样整整错过。
- incast 是亚秒级事件，轮询拿到的是平均值，平均值永远正常。

智算网络于是改用 **gNMI 流式订阅**（见 [gNMI + OpenConfig 遥测](../04-telemetry/11-gnmi.md)）。交换机把秒级甚至亚秒级的队列、ECN、pause 指标推给采集端。

相当于把设备计数器接到一条消息队列上：你订阅，它推送，不用轮询去拉。这条管道跟「Kafka → 流处理 → 时序库」完全同构，**缺的只是数据源**。设备管控面这块能力，直接搬。

## 经验映射

从 IDC 转过来的人，能力不是负担。一项一项判断能不能搬，就行：

| 已有能力 | 价值 | 说明 |
|---|---|---|
| 链路级主动探测 / 五元组 hash 路径覆盖 | **更值钱** | 大象流时代，hash 极化（多条大象流哈希到同一路径）是高频事故模式，只有路径级观测能发现 |
| 时序数据管道（采集 → 消息队列 → 存储 → 查询） | 直接复用 | 与设备侧 gNMI 订阅只是数据源不同 |
| 告警收敛 / 根因分析（RCA） | 需改造 | 指标口径变了，阈值与关联规则要重做 |
| 丢包率 / 时延 / 抖动为主的面板 | 必须替换 | 主指标应为 PFC pause、ECN 标记率、队列水线、逐路径丢包 |
| 「网络故障 → 切流兜底」的处置习惯 | 不成立 | 训练流量无法切流，只能定位并快速恢复 |

::: info 经验映射（IDC → AIDC）

你过去做的「五元组哈希 ECMP 路径覆盖」，在智算网络里价值反而**更大**。大象流时代，多条大象流哈希到同一条路径（hash 极化）是高频事故模式。只有路径级观测才能发现「某条 ECMP 路径被单条大象流打满」，设备级聚合指标里完全看不见。

同理，你熟悉的「30 分钟发现 → 秒级发现」只覆盖 MTTR 的**发现**环节。智算场景要求发现、定位、恢复全链路分钟级。发现这块你已有积累，要补的是定位（设备遥测关联）与自愈（自动化处置），第五、六篇展开。
:::

## 值班台那张表

### 一张能贴在值班台前的对照表

| 观测项 | 有损 IDC 的典型做法 | 智算网络的典型做法 |
|---|---|---|
| 采集方式 | SNMP 轮询，分钟级 | gNMI 流式订阅，秒级 / 亚秒级 |
| 主指标 | 丢包率、时延、抖动、带宽利用率 | PFC pause 帧数与时长的分布、ECN 标记率、队列水线、逐路径丢包 |
| 丢包的解读 | 背景噪声，先看趋势 | 故障信号，要立刻定位到端口 / 路径 |
| 视角 | 设备级聚合 + 抽样探测 | 设备级 + 路径级 + 作业级（按训练任务归因） |
| 排障目标 | 恢复业务可用性 | 缩短停机（MTTR）并保住训练进度 |

写不出结论的卡片，说明这个指标的语义你还没搞清楚。那正好是下一步要补的功课。

## 习题

::: tip 怎么做题

先自己写答案，哪怕只有三行，再展开对照，最后按「评分维度」逐条给自己打分。写不出来不是问题，跳过自评才是问题。
:::

**必答 Q1**：用你自己的话解释：为什么 AI 训练网络要把丢包率压到 `1e-5` 量级以下？「TCP 反正会重传」这句话错在哪？

::: details 参考答案与评分维度

「TCP 会重传」在有损网络里成立，因为重传由**内核协议栈**完成，代价是一个 RTT，业务几乎无感。RDMA 恰恰绕过了内核。数据面跑在网卡上，没有协议栈兜底，丢了只能等拥塞控制算法感知再重传。代价是**毫秒级的微突发打断，外加拥塞窗口被打回起点**。

更要紧的是**同步放大**。AllReduce 每一轮都要等所有 Rank 到齐，一个包重传的延迟会传导成整个训练步的等待，一万张卡一起等。丢包吃掉的是全局同步的时间，不是一点带宽。这就是必须从机制上避免丢包的根因。

**评分维度**

- 说出 RDMA 绕过内核，丢失了协议栈的重传兜底（必需）
- 说出重传代价在同步训练里被放大到全局（必需）
- 提到 PFC / ECN 是「避免丢包」而非「丢了再补」（加分）
- 只回答「RDMA 快、TCP 慢」而没有触及重传语义（不通过）
:::

**必答 Q2**：把你维护的 IDC 监控系统原样搬到万卡智算集群，先不管能不能采到设备数据。**你能立刻发现哪类问题，又会漏掉哪类？** 各举至少两个并说明理由。这是本讲最要紧的一道题。

::: details 参考答案与评分维度

能发现的：

1. **链路彻底中断**。探测器到不了、端口 down，任何监控体系都看得见。
2. **带宽利用率异常 / 长期饱和**。端口计数器级别的现象，老体系看得见，只是粒度和阈值不一定合适。
3. **端到端时延劣化**。基于探测包的方案能感知到某条路径变慢。

会漏掉的：

1. **PFC 风暴与 PFC 死锁**。老体系根本没有 pause 帧计数与持续时长指标，风暴发生时端口利用率甚至可能是「正常」的。
2. **incast 造成的微突发与 ECN 标记**。分钟级轮询取平均，亚秒级突发被抹平。
3. **hash 极化 / 单条大象流打满某条路径**。设备级聚合指标被稀释，只有逐路径观测看得见。
4. **单个光模块的渐进劣化**，比如 FEC 纠错计数、误码上升。不在老指标集里。

**评分维度**

- 能区分「现象层面能看见」与「有指标能定位」（必需）
- 漏掉项至少覆盖 PFC / ECN / 微突发 / 光模块中的两项（必需）
- 说明「为什么漏」是无指标口径还是粒度不够，而不是只说「没做过」（必需）
- 能主动提出补救方向，比如新增 pause / ECN 指标、路径级探测、秒级订阅（加分）
:::

**自测 Q3**：AllReduce 的同步突发，和电商大促的流量洪峰，最本质的两个区别是什么？

::: details 参考答案与评分维度

① **周期性**。大促洪峰是事件驱动的偶发流量，incast 是每个训练步都发生的固定节奏。正因为可预测，才有可能通过拓扑与参数预调优，比如 rail-optimized 拓扑、拥塞控制参数。

② **同步性与木桶效应**。大促流量从大量随机入口汇聚，压力被时间与空间摊薄。incast 是上万个源在**同一时刻**朝同一目的地同步倾泻，瞬时压力远超平均负载，任何一个 Rank 慢都会拖住全体。

**评分维度**：两点各 1 分。额外指出「可预测 → 可预调优」或「木桶效应 → 单个慢节点即全局慢」加 1 分。
:::

**自测 Q4**：为什么说「路径级覆盖」在智算网络里比在传统 IDC 里更值钱？

::: details 参考答案与评分维度

大象流加 hash 分担的组合，让「某一条路径劣化」既高频又隐蔽。单条大象流哈希到某路径把它打满，或者一个坏光模块只影响个别链路。设备级聚合指标会被稀释到看不见：一台 64 端口的交换机上，1 条路径只占 1.5%，聚合指标永远「正常」。

只有逐路径观测能把「某条 ECMP 路径被单流打满」这类问题暴露出来。路径级探测观测的是**流量实际走过的那条路**，不看设备平均表现。

**评分维度**

- 说出聚合指标会稀释局部劣化（必需）
- 说出大象流使单路径饱和成为高频模式（必需）
- 能给出数量级直觉（1 条路径 / 64 端口约 1.5%）或具体观测手段（加分）
:::

## 小结

四条假设，换掉的就是这四条。

**流量模型**从南北向小流换成东西向大象流，上面再叠一层 AllReduce 周期性同步突发。**丢包语义**从背景噪声、排障线索，变成机制性故障的信号，主指标跟着换成 PFC pause、ECN 标记率、队列水线。**故障代价**从「一片请求变慢」变成「全体停摆加 checkpoint 回退」，MTTR 的要求压到分钟级。**遥测粒度**从 SNMP 分钟轮询换成 gNMI 秒级订阅，管道能直接复用，缺的只是数据源。

四条换完，你手上的工具一个没扔，看问题的角度已经换了。

::: tip 本课要点

**同一张网，四个默认假设全得换。**

- **流量模型**：南北向小流 → **东西向大象流 + AllReduce 周期性同步突发（incast）**
- **丢包语义**：丢包从「背景噪声 / 排障线索」变成「**机制性故障的信号**」。日常主指标换成 PFC pause、ECN 标记率、队列水线
- **故障代价**：网络故障等于全体训练停摆加 checkpoint 回退，MTTR 要求**分钟级**
- **遥测粒度**：SNMP 分钟轮询 → **gNMI 秒级流式订阅**。数据管道可直接复用，缺的只是数据源
- **能力映射**：路径级覆盖在智算网络**更值钱**。发现环节你已有积累，定位与恢复是学习方向
:::

::: info 关于文中那几个数字

`1e-5` 量级的丢包率要求是业界工程实践的常见目标，任何 RFC 都没有强制规定。同一个集群里，不同业务、不同厂商的口径可能有差异。遇到具体数字，以你所在环境的设计文档为准。
:::
