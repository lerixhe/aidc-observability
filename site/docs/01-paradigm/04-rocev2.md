RoCEv2 说白了就一句话：把 RDMA 那台发动机，装到以太网这副底盘上。

发动机没换，底盘换成你天天摸的那一副。麻烦全在底盘上。

上一讲把因果链推到「网络必须无损」。往下走一层：无损这个责任，本来由 InfiniBand 自己扛，现在转嫁给以太网的一堆配置。转嫁要付利息，这一讲把利息算清楚。

## 交付

- 说清 InfiniBand 与 RoCE 的关系：RoCE 是把 RDMA 移植到以太网，不是另起一套技术
- 解释 RoCE v1 与 v2 的关键差别，以及这个差别为什么决定它能不能长大
- 逐层说出 RoCEv2 报文里每个字段归谁管，优先级、ECN、可路由、可靠性各自对应后面哪一讲
- 理解 DCB 三件套里为什么「配置一致性」比协议本身更容易出事
- 在主机和交换机上各跑几条命令，确认 RoCEv2 真的按预期跑起来了

## 一台好发动机，装在别人的底盘上

RDMA 出生在 **InfiniBand（IB）**：专用交换机、专用网卡（HCA）、专用线缆，从里到外一套。它**用信用（credit）机制在链路层做到不丢包**，端到端不用为丢包写任何兜底逻辑。

即插即用，省心，封闭且贵。

以太网阵营当然不想放过这套时延能力，办法很直接：把 RDMA **原样搬过来**。这就是 **RDMA over Converged Ethernet**，简称 RoCE。

搬法有两代，差别只有一处，后果很大。

**RoCE v1** 把 IB 传输头直接塞进以太网帧，EtherType `0x8915`。它是个二层协议：**过不了路由器**。一个二层域能有多大，RoCE 集群就能有多大。

**RoCEv2** 在中间加了两层壳：UDP 加 IP，目的端口 **4791**。从此它是标准三层报文，能跨 spine，能被 ECMP 哈希，能被普通三层网络转发。

一句话记住：**v1 是一张网，v2 是一张能长大的网。**

几百卡的时候 v1 够用，上万卡就必须跨三层多级转发，v1 那条路直接封死。今天业界说 RoCE，基本都指 v2。

## 报文里每一层各管什么

一个 RoCEv2 报文从发起端出去，是这样一层层套上去的：

```text
1. 应用内存里的数据，被网卡直接读走（DMA），前面加 IB 传输头 BTH：QP 号、PSN 序号
2. 外面套 UDP 头，目的端口写死 4791
3. 外面套 IP 头，写入 DSCP 和 ECN 两位
4. 外面套以太网头，写入 802.1p 优先级（PCP）
5. 交换机看 PCP 决定进哪个队列，看 ECN 阈值决定要不要打 CE 标记
6. 对端网卡剥壳，按 BTH / PSN 检查顺序，回 ACK
7. 数据落进对端应用注册过的内存，应用根本不知道中间发生了什么
```

套了四层壳，每层都得有人负责。分工是这样的：

| 层 | 关键字段 | 它是给谁用的 | 后续课程 |
|---|---|---|---|
| 以太网头 | 802.1p / PCP 优先级（或由 DSCP 映射而来） | **PFC 按它暂停**，优先级是隔离的抓手 | [05 PFC](../02-lossless/05-pfc.md) |
| IP 头 | **ECN 两位**（ECT / CE） | 交换机拥塞时改写，源端据此降速 | [06 ECN + DCQCN](../02-lossless/06-ecn-dcqcn.md) |
| UDP 头 | 目的端口 **4791** | 只提供「可路由」这个身份，不做可靠性 | — |
| IB 传输头 | BTH、PSN | 可靠传输、乱序重排、重传，全在网卡硬件里 | [03 RDMA](./03-rdma.md) |
| Payload | 应用内存数据 | DMA 直读直写 | — |

三点要记住。

**UDP 只是外壳。** 它不做握手、不排序、不重传，可靠传输那套活全在网卡硬件里。所以这条流**丢了没人兜底**，兜底也很贵。上一讲的结论在这里落地：网络必须从机制上不丢包。

**优先级靠标记。** 报文带 PCP（或由 DSCP 映射成队列），通行做法是划出专用优先级跑 RoCE，业务流量走有损队列。同一根线、同一个交换口，逻辑上分成两条路。

**ECN 位在 IP 头里。** 交换机拥塞时直接改这两个 bit。这是「流经的设备可以留下痕迹」的唯一手段，也是以太网能做出拥塞控制闭环的基础。

::: info 经验映射（IDC → AIDC）

对 IDC 背景的人来说，这是最亲切的一讲：**RoCEv2 流量就是标准五元组的 UDP 流**。

你赖以生存的五元组哈希、ECMP、探测包、tcpdump 与 Wireshark，在 RoCEv2 网络里全部原样适用。抓包看得见 UDP 4791，IB 传输头用 Wireshark 的 RoCE 解析器就能读。

看懂流量的能力你不缺。缺的是设备侧的队列、PFC、ECN 状态，那是第四篇（把现场变成数据）的主题。

:::

## 你手上哪些能力能直接搬

| 已有的能力 | 在 RoCEv2 场景下的状态 |
|---|---|
| 五元组哈希 / ECMP | 完全适用，RoCEv2 就是 UDP 流 |
| 抓包分析（tcpdump / Wireshark） | 能用，但只看得见外层，队列级语义得靠设备遥测 |
| VLAN / 优先级 / QoS 配置经验 | 直接迁移，DCB 就是 QoS 的无损加强版 |
| 「链路通就算健康」的判断习惯 | 必须改，无损机制失效时链路完全正常 |
| 逐台设备的配置管理 | 要升级成配置一致性对账，否则一跳配错全网抖 |

最后一行是真正的转向：**配置也是被观测对象**。以前配置是变更文档里的字，现在它是影响指标的东西，得进监控。

## 无损要在以太网上重配一遍

IB 的不丢包是天生的，交换机一上电就成立。

以太网默认会丢包，要它不丢，得一层层配出来。这套配置统称 **DCB（Data Center Bridging）**，核心三件：

| 机制 | 什么时候起作用 | 干什么 | 详见 |
|---|---|---|---|
| **PFC**（优先级流控） | 队列快满 | 反向暂停上游，从机制上阻止该优先级丢包 | [05 PFC](../02-lossless/05-pfc.md) |
| **ECN**（显式拥塞通知） | 拥塞初期 | 给报文打标记，让源端网卡先降速，尽量别走到「必须暂停」 | [06 ECN + DCQCN](../02-lossless/06-ecn-dcqcn.md) |
| **一致性配置** | 部署与每次变更 | 整张 Fabric 每一跳的 PFC / ECN 参数、DSCP 映射严格一致 | [07 四大故障](../02-lossless/07-fault-modes.md) |

前两件是协议，第三件不是协议，却最容易出事。

任何一台交换机配漏、配错，一张网就可以开始抖：PFC 风暴、PFC 死锁、某条流被丢进有损队列，都从这里来。

有人会问：ECN 已经能让源端主动降速了，还要 PFC 干什么？

因为两者的时间尺度差一个量级。ECN 是闭环，交换机打标记、接收端回 CNP、发送端降速，这一圈走完队列可能已经涨满了。PFC 是开环，逐跳、就地、立刻暂停上游，快得多，代价是把压力往上游推。分工很清楚：**ECN 管常态降速，PFC 兜底不丢包**。只留 ECN，微突发下会漏；只留 PFC，pause 帧会把整张网串成一条链。

::: warning 换成隐性故障

传统 IDC 的配置错误，后果多半是**显性**的：链路不通、端口 down、路由没有。监控一眼抓到。

RoCE 的配置错误是**隐性**的。某一跳 PFC 没开、水线配错、DSCP 映射不一致，后果是「无损机制在那一跳失效」或者「无意义的暂停风暴」。链路是通的，端口是 up 的，带宽是满的，训练在变慢。

要发现这类问题，观测系统得看得见**设备队列级状态**：pause 收发计数、队列水线、ECN 标记数。端口级计数器不够用。

:::

## 四讲串成一条链

```text
同步训练要求微秒级稳定时延（02 讲）
  → 内核协议栈做不到 → 上 RDMA（03 讲）
    → RDMA 丢包恢复代价极大 → 网络必须无损
      → IB 天生无损但封闭昂贵 → RoCEv2 = RDMA over 以太网（本讲）
        → 以太网默认会丢包 → 需要 PFC + ECN 从机制上补齐
          → 这些机制自带新的故障模式 → 可观测成为刚需（07 讲起）
```

这条链背下来。篇末自测卷的主线是它，「为什么 AI 网络要无损」这类开放题的骨架也是它。

## RoCEv2 的代价

移植带来扩容能力，也带来负债。摆清四笔。

**一致性从「建议」变成「前提」。** IB 换上电就无损，你不用管参数。以太网上，任何一跳漏配，那一跳就是整条路径的短板。变更管理从「改一台」变成「改全网再对账」。

**交换机从转发设备变成故障源。** 上一讲之前，主机侧 CPU 和软中断能解释大半问题。现在队列水线、PFC 阈值、ECN 阈值都成了要盯的配置面，配错就是事故。

**抓包只能看到外层。** 工厂外的视角止于 UDP 头。丢了哪个 PSN、哪个队列憋住了，tcpdump 一个字都看不出来，必须靠设备遥测。

**调参是手工活。** PFC 的 xoff / xon 水线按端口速率和线缆时延手算，ECN 的 min / max 阈值靠经验。水线设得太松，队列先溢出；设得太紧，pause 帧满天飞。这套参数没有自动收敛的机制。

代价说完了，再说另一半。**RoCE 的好处也实在**：标准以太网加白盒交换机，管控面可以自己写；供应链多元，不必被单一厂商绑定；与既有 IDC 的工具链和人才储备能接着用；带宽演进跟以太网节奏走，每年上一档。
IB 那边也有硬优势，天生无损免调优，在网计算（SHARP）成熟，大规模部署的经验厚。这笔账在 [IB vs RoCE 路线之争](../06-selection/20-ib-vs-roce.md) 里正式算，这里不下结论。

## 判读与实操

主机侧三条，确认它真的在按 RoCEv2 跑：

```bash
# 1. 看设备与协议模式，link_layer 是 Ethernet 说明走的是 RoCE 而非原生 IB
ibv_devinfo | grep -E 'hca_id|link_layer|state'
cma_roce_mode -d mlx5_0 -p 1          # 查看当前版本，加 -m 2 可设为 v2

# 2. 看优先级、PFC 与 DSCP 映射，确认 RoCE 流量进了无损队列
mlnx_qos -i <ifname>

# 3. 抓五个包，确认外层是 UDP 4791
sudo tcpdump -i <ifname> -c 5 'udp port 4791'
```

`cma_roce_mode` 和 `mlnx_qos` 的典型输出，一台配好的机器长这样：

```text
$ cma_roce_mode -d mlx5_0 -p 1
RoCE mode: RoCE v2

$ mlnx_qos -i ens1f0
DCBX mode: OS controlled
PFC configuration:
        priority:    0     1     2     3     4     5     6     7
        enabled:     0     0     0     1     0     0     0     0
        buffer:      0     0     0     0     0     0     0     0
```

优先级 3 上 `enabled: 1`，其余全 0。这就是「只有 3 号队列无损」的字面意思，RoCE 流量该落在 3 号上。

交换机侧核对三件事，缺一不可：

```text
1) 优先级映射一致：DSCP → traffic-class → queue，所有跳相同
2) 无损队列一致：开了 PFC 的队列号、xoff / xon 水线相同
3) 拥塞标记一致：ECN 的 min / max 阈值与标记概率相同
```

判读看三点：

- **抓不到 4791 报文**。流量根本没走 RoCE，先查 `ibv_devices` 和对端是不是同一套 RDMA 栈。
- **`mlnx_qos` 里 RoCE 队列的 PFC 是 `0`**。无损机制形同虚设。链路一切正常，一拥塞就丢包。
- **两跳的 DSCP 映射不同**。「偶发慢、查不出原因」的经典来源，流量在中间某一跳被塞进了有损队列，链路上没有任何告警。

## 习题

::: tip 怎么做题

先自己写答案，三行也算，再展开对照，最后按「评分维度」逐条自评。跳过自评最省事，也最没用。

:::

**必答 Q1**：RoCEv2 的「v2」相对 v1 改了什么？为什么这一改很关键？

::: details 参考答案与评分维度

v1 把 RDMA 直接封进以太网帧（EtherType `0x8915`），只能在单个二层域内转发，过不了三层网关。v2 在外面套 UDP / IP，目的端口 4791，变成标准可路由报文，能跑在多级 Clos Fabric 上。

关键在**能不能长大**。集群从几百卡到上万卡，必然跨 spine 多级转发、跨多个二层域。v1 的二层边界把这条路封死，v2 才算给了它规模。

**评分维度**

- 说出 v1 不可路由、v2 套 UDP/IP 后可路由（必需）
- 说出「规模化的前提是跨三层」（必需）
- 提到端口 4791 或 EtherType（加分）

:::

**必答 Q2**：RoCEv2 报文里的 UDP 头承担什么职责？这条流丢了一个包，谁来兜底？兜得住吗？

::: details 参考答案与评分维度

UDP 头只提供「可路由」这个身份，端口号还顺带给 ECMP 哈希用。它不做握手、不排序、不重传。

可靠性被下移到**网卡硬件里的 IB 传输层**，靠 BTH / PSN 与 ACK / NAK 做。重传是粗粒度的 Go-Back-N 式：丢一个包，可能整段重来。

所以兜底有，但很贵。这正是必须让 PFC / ECN 在丢包**发生之前**介入的原因。

**评分维度**

- 说出 UDP 只是外壳、不提供可靠性（必需）
- 说出可靠性在网卡硬件（必需）
- 指出硬件重传代价大，因此要走「预防」而非「恢复」（必需，缺这条只算背书）

:::

**自测 Q3**：为什么国内主流厂商在以太系 RoCE 与 InfiniBand 之间，普遍选前者？

::: details 参考答案与评分维度

① 生态开放：标准以太网加白盒交换机（SONiC 一类），管控面能自研，不被单一供应商锁死。② 供应链与成本多元。③ 与既有 IDC 的工具链、运维体系、人才储备延续。④ 带宽演进跟以太网节奏走，规模弹性大。

反面也要说：IB 天生无损、免调优、SHARP 在网计算成熟。只站一边的答案不及格。

**评分维度**：两条以上正面理由给基础分。能同时讲清 IB 的优势给满分。

:::

**自测 Q4**：RoCE 流量和普通业务流量在同一张物理网上怎么共存？这套共存最脆弱的地方在哪？

::: details 参考答案与评分维度

逻辑隔离。RoCE 走专用优先级（PCP 或 DSCP 映射到无损队列），该队列开 PFC 加 ECN。业务流量走有损队列，照常丢包重传。同一块网卡、同一根线，队列分开。

脆弱处在**映射一致性**。任何一跳把 RoCE 流量映进有损队列，无损保障就在那一跳断掉，链路不会有告警，端口不会 down。

**评分维度**：说出优先级 / 队列隔离（必需）。说出映射不一致的后果（必需，这是本讲的落点）。

:::

## 小结

一台好发动机，装到别人的底盘上。

RDMA 原本躺在 InfiniBand 里，靠信用机制天生不丢包。以太网阵营把协议原样搬过来，v1 封在二层所以长不大，v2 套一层 UDP / IP 才跨得了三层。报文里分工也清楚：L2 优先级给 PFC 用，IP 头的 ECN 两位给 DCQCN 用，UDP 只提供可路由的身份，可靠性全在网卡硬件里。

代价是「无损」这个责任被转嫁给一堆配置。DCB 三件套里，PFC 与 ECN 是协议，第三件一致性不是协议，却最容易出事。整张 Fabric 里跳错一个，链路照样通、端口照样 up、带宽照样满，训练在变慢。

::: tip 本课要点

**RoCEv2 就是把 RDMA 那台发动机，装到以太网这副底盘上。**

- RDMA 原生在 **InfiniBand**（信用机制天生无损），RoCE 是移植。**v1 不路由，v2 套 UDP/IP 后可路由**（端口 4791）
- 报文分工：**L2 优先级给 PFC · IP 头 ECN 位给 DCQCN · UDP 只是外壳 · 可靠性在网卡硬件**
- 无损靠 DCB 三件套：PFC + ECN + **全 Fabric 配置严格一致**
- 代价四笔：一致性成为前提、交换机变故障源、抓包只见外层、水线参数靠手工
- RoCEv2 就是五元组 UDP 流，**哈希 / ECMP / 抓包原样适用**，缺的是设备侧队列遥测

:::

留一个思考题：PFC 与 ECN 都配对了，唯独某一跳的 DSCP 映射与别处不同。你会先在哪类指标上看到异常，为什么。
