如果要用一句话来描述这一讲，我想应该是：RoCEv2 就是把 RDMA 那台发动机，装到以太网这副底盘上。

上一讲的因果链走到了"网络必须无损"。这一讲往下走一层：RDMA 原生跑在 InfiniBand 上，今天几乎都跑在以太网上。**RoCEv2 就是中间的桥**，报文每层各管一件事，而无损这个责任被转嫁给了你熟悉的以太网。

转嫁是要付利息的，这一讲把利息算清楚。

## 学完这一讲，你应该能

- 说清 InfiniBand 与 RoCE 的关系：RoCE 是把 RDMA 移植到以太网，不是另一套技术
- 解释 RoCE v1 与 v2 的唯一关键差别，以及这个差别为什么决定它能不能规模化
- 逐层说出 RoCEv2 报文各字段由谁负责（优先级 / ECN / 可路由 / 可靠性），并对应到后面的课
- 理解 DCB 三件套与**全 Fabric 配置一致性**为什么是运维命门
- 在机器与交换机上确认 RoCEv2 真的按预期跑起来了

## 机制拆解

### 0x01 RDMA 出生在 InfiniBand，长大在以太网

RDMA 技术原生诞生在 **InfiniBand（IB）**：专用交换机、专用网卡（HCA）、专用线缆。它**天生基于信用（credit）机制做到链路级不丢包**。即插即用，省心，但封闭且昂贵。

以太网阵营不会放过这套时延能力，于是把 RDMA 协议**移植**到标准以太网上。这就是 **RDMA over Converged Ethernet（RoCE）**。

类比一下，相当于只换底盘不换发动机：传输能力还是 IB 那一套，跑的路换成了以太网。它有两代：

- **RoCE v1**：RDMA 直接封在以太网帧里（L2），**不能跨三层路由**，只能在一个二层域内玩，规模上不去。
- **RoCEv2**：外面包了一层 **UDP/IP**，变成标准 L3 可路由报文，从此可以跑在普通三层以太网 Fabric 上。今天业界说的 RoCE，基本都指 v2。

一句话概括差别：**v1 是一张网，v2 是一张能长大的网**，能跨 spine 路由。集群从几百卡涨到上万卡，这个差别就是生死线。

### 0x02 RoCEv2 报文长什么样

| 层 | 关键字段 | 谁负责 | 后续课程 |
|---|---|---|---|
| 以太网头 | 802.1p/PCP 优先级（或由 DSCP 映射而来） | 承载**优先级**，PFC 按优先级暂停 | [05 PFC](../02-lossless/05-pfc.md) |
| IP 头 | **ECN 两位**（ECT / CE） | 交换机拥塞时可改写，源端据此降速 | [06 ECN + DCQCN](../02-lossless/06-ecn-dcqcn.md) |
| UDP 头 | **目标端口 4791** | 只提供"可路由"这个身份，不做可靠性 | — |
| IB 传输头 | BTH、PSN 等 | 可靠传输、乱序处理、重传，全在网卡硬件里 | [03 RDMA](./03-rdma.md) |
| Payload | 应用内存数据 | DMA 直读直写 | — |

三个值得记住的点。

1. **UDP 只是外壳。** 可靠传输、乱序、重传逻辑都在网卡硬件（IB 传输层）里，UDP 本身不做任何可靠性，**丢了没人兜底**。这又一次呼应"网络必须无损"。
2. **优先级靠标记。** 报文带优先级（802.1p PCP，或由 DSCP 映射到队列）。通行做法是划出专用优先级跑 RoCE，普通业务走有损队列。**两类流量在同一张物理网上逻辑隔离**。
3. **ECN 位在 IP 头里。** 交换机拥塞时直接改这两个 bit，这是"流经设备可被标记"的前提，也是以太网能做拥塞控制闭环的基础。

::: info 经验映射（IDC → AIDC）

对 IDC 背景的读者来说，这是最亲切的一讲：**RoCEv2 流量就是标准五元组的 UDP 流**。

你赖以生存的五元组哈希、ECMP、探测包、tcpdump / Wireshark，在 RoCEv2 网络里**全部原样适用**。抓包能看到 UDP 4791，IB 传输头用 Wireshark 的 RoCE 解析器就能读。

看懂流量的能力你不缺，缺的是设备侧的队列、PFC、ECN 状态遥测，那是 M4 的主题。
:::

### 0x03 RoCEv2 对网络提了什么要求：DCB 三件套

把 RDMA 放上以太网，相当于把"无损"这个责任，从专用网络转嫁给以太网的一堆配置。这套配置统称 **DCB（Data Center Bridging）**，核心有三件：

| 机制 | 作用时点 | 作用 | 详见 |
|---|---|---|---|
| **PFC**（优先级流控） | 队列快满时 | 反向暂停上游，从机制上阻止该优先级丢包 | [05 PFC](../02-lossless/05-pfc.md) |
| **ECN**（显式拥塞通知） | 拥塞初期 | 给报文打标记，让源端网卡主动降速，尽量别走到"必须暂停" | [06 ECN + DCQCN](../02-lossless/06-ecn-dcqcn.md) |
| **一致性配置** | 部署与变更时 | 整张 Fabric 每一跳的 PFC/ECN 参数、优先级映射严格一致 | [07 四大故障](../02-lossless/07-fault-modes.md) |

第三件不是协议，却是最容易出事的一件。任何一台交换机配漏或配错，就是 PFC 风暴或死锁。

::: warning 一个必须提前建立的直觉

传统 IDC 的配置错误，后果往往是"某条链路不通"这类**显性故障**，监控最容易抓。

RoCE 网络的配置错误（某一跳 PFC 没开、水线配错、DSCP→优先级映射不一致），后果是"无损机制失效"或者"无意义的暂停风暴"这类**隐性问题**。链路通、端口 up、带宽正常，但训练在变慢。

要发现这类问题，观测系统必须能看见**设备队列级状态**：pause 收发计数、队列水线、ECN 标记数。端口级计数器不够用。这是第四篇（把现场变成数据）的起点。
:::

### 0x04 把三讲串成一条链

```text
同步训练要求微秒级稳定时延（02 讲）
  → 内核协议栈做不到 → 上 RDMA（03 讲）
    → RDMA 丢包恢复代价极大 → 网络必须无损
      → IB 天生无损但封闭昂贵 → RoCEv2 = RDMA over 以太网（本讲）
        → 以太网默认会丢包 → 需要 PFC + ECN 从机制上补齐
          → 这些机制自带新的故障模式 → 可观测成为刚需（07 讲起）
```

把这条链背下来。它既是篇末自测卷的主线，也是"为什么 AI 网络要无损"这类开放题最稳的答题骨架。

| 你已有的能力 | 在 RoCEv2 场景下的状态 |

## 判读与实操

### 0x05 主机侧与交换机侧各看三行

主机侧，先确认 RoCEv2 真的在用：

```bash
# 1. 看 RoCE 设备与协议模式（v1 / v2 / RoCEv1.5）
ibv_devinfo -v | grep -iE 'hca_id|fw_ver|link_layer'
cma_roce_mode -d mlx5_0 -p 1 -m        # 查看/设置 RoCE 版本

# 2. 看 DSCP / PCP 映射（流量是否真的进了无损优先级）
mlnx_qos -i <ifname> --show            # 展示 trust mode、PFC、DSCP→priority 映射

# 3. 抓一个包确认外层是 UDP 4791
sudo tcpdump -i <ifname> -c 5 'udp port 4791'
```

交换机侧，核对一致性，这是真正的命门：

```text
! 逐跳核对三件事，缺一不可
1) 优先级映射一致：DSCP → traffic-class → queue 的映射在所有跳上相同
2) 无损队列一致：enable pfc 的队列号、水线阈值（xoff / xon）一致
3) 拥塞标记一致：ECN 的 min/max 阈值与标记概率一致
```

判读要点：

- **抓不到 4791 报文**。说明流量没走 RoCE，或者根本没用 RDMA，先查 `ibv_devices`。
- **`mlnx_qos --show` 里 PFC 没开在承载 RoCE 的队列上**。无损机制形同虚设，链路看着一切正常，一拥塞就丢包。
- **两跳的 DSCP 映射不同**。流量在某些跳被塞进有损队列，这是"偶发慢、查不出原因"的经典来源。

## 习题

**必答 Q1**：RoCEv2 的"v2"相对 v1 改了什么？为什么这个改动很关键？用自己的话回答。

::: details 参考答案与评分维度

v1 把 RDMA 直接封在以太网帧里（L2），只能在单个二层域内转发，过不了三层网关。v2 在外面套一层 UDP/IP（目标端口 4791），变成标准可路由报文，能跑在多级 Clos Fabric 上。

关键性在于**可扩展**。AI 集群从数百卡发展到万卡，必然要跨 spine 多级转发、跨多个二层域，v1 的二层限制直接封死了这条路。v2 让 RoCE 能长大。

**评分维度**

- 说出 v1 不路由 / v2 套 UDP-IP 可路由（必需）
- 说出"规模化的前提是跨三层"（必需）
- 提到目标端口 4791 或 ECN 位在 IP 头（加分）
:::

**必答 Q2**：RoCEv2 报文里的 UDP 头承担什么职责？它为什么不对可靠性负责？这条流丢了一个包，谁来兜底？

::: details 参考答案与评分维度

UDP 头只提供"可路由"这个身份（连同端口号 4791 供识别与哈希），不做握手、不重传、不排序。

可靠性被下移到**网卡硬件里的 IB 传输层**（BTH/PSN、ACK/NAK、重传）。因为硬件重传是粗粒度的（Go-Back-N 式），代价远大于 TCP 的选择重传。所以"丢了没人兜底，兜底也很贵"，这就是必须靠 PFC / ECN 在丢包**发生前**介入的原因。

**评分维度**

- 说出 UDP 只是外壳 / 不做可靠性（必需）
- 说出可靠性由网卡硬件（IB 传输层）负责（必需）
- 指出硬件重传代价大，因此要预防而不是恢复（必需，缺这条只算背书）
:::

**自测 Q3**：为什么国内主流互联网厂商在以太系 RoCE 与 InfiniBand 之间，普遍选择前者？

::: details 参考答案与评分维度

① 生态开放：标准以太网加白盒交换机（如 SONiC）可自研管控面，不被单一供应商锁定。② 成本与供应链多元。③ 与既有 IDC 运维体系、工具链、人才储备延续。④ 以太网带宽演进节奏快，规模弹性大。

反面也要说公平话。IB 的优势是天生无损、免调优、在网计算（SHARP）成熟。这部分在 [IB vs RoCE 路线之争](../06-selection/20-ib-vs-roce.md) 会正式展开。

**评分维度**：给出两条以上正面理由得基础分。能同时指出 IB 的优势、不只单边站队得满分。
:::

**自测 Q4**：RoCE 流量和普通业务流量在同一张物理网上怎么共存？

::: details 参考答案与评分维度

逻辑隔离。RoCE 走专用优先级（802.1p PCP 或 DSCP 映射到无损队列），该队列启用 PFC + ECN。普通业务走有损队列，照常丢包重传。同一块网卡、同一根线，队列分开。

正因如此，"优先级映射一致性"才是运维命门。任何一跳把 RoCE 流量映射进有损队列，无损保障就在那一跳断掉，而链路上不会有任何告警。

**评分维度**：说出优先级 / 队列隔离（必需）。说出映射不一致的后果（必需，这是本讲的落点）。
:::

## 小结

这一讲可以压成一句话：**RoCEv2 就是把 RDMA 那台发动机，装到以太网这副底盘上。**

RDMA 原生在 InfiniBand 里，靠信用机制天生不丢包。以太网阵营把协议移植过来，v1 封在二层所以长不大，v2 套一层 UDP/IP 才跨得了三层。报文里的分工也很清楚：L2 优先级给 PFC 用，IP 头的 ECN 两位给 DCQCN 用，UDP 只提供可路由的身份，可靠性全在网卡硬件里。

代价是"无损"这个责任被转嫁给以太网的配置。DCB 三件套里，PFC 与 ECN 是协议，第三件一致性不是协议，却最容易出事。一整张 Fabric 里只要有一跳配漏，链路照样通、端口照样 up、带宽照样满，训练在变慢。

::: tip 本课要点

**RoCEv2 就是把 RDMA 那台发动机，装到以太网这副底盘上。**

- RDMA 原生在 **InfiniBand**（信用机制天生无损），RoCE 是移植到以太网。**v1 不路由，v2 套 UDP/IP 变可路由**（目标端口 4791）
- 报文分层分工：**L2 优先级（PFC 用）· IP 头 ECN 位（ECN/DCQCN 用）· UDP 只是外壳 · 可靠性在网卡硬件**
- 无损靠 DCB 三件套：PFC + ECN + **全 Fabric 配置严格一致**
- RoCEv2 流量就是标准五元组 UDP 流，**哈希 / ECMP / 抓包能力原样适用**，缺的是设备侧遥测
- 配置错误是隐性问题：链路正常、训练变慢。必须观测队列级状态
:::

留一个思考题：如果 PFC 与 ECN 都配对了，但整张 Fabric 的 DSCP 映射只在某一跳不一样，你会先在哪类指标上看到异常。
