如果要用一句话来描述这一讲，我想应该是：自适应路由把选路权从静态五元组，交还给交换机的实时队列深度。

前面几讲交代了两个事实。RoCEv2 跑在以太网上，必须走 ECMP。训练通信全是同质大象流，五元组完全一样。

实验里的结论已经很明确：**静态散列在这种流量面前根本不均分。** 两条等价上行，常常一条打满、一条闲着。要解这个死结，靠改五元组没用，必须让交换机在转发时刻自己看路。

先在一条能跑的命令上，看一下静态散列的盲区：

```bash
# 模拟两条 400G 等价上行，同质 AllReduce 流量下的哈希极化度
cd labs/05-clos-topo && go run . -mode=hash -flows=8
```

你会看到最差极化度直接冲到 `2.00`。两条路里有一条利用率是 `100%`，另一条是 `0%`。

- 解释流级分流、Flowlet 切片、逐包喷洒三种粒度的优劣、场景与代价
- 说出自适应路由打散流量后，接收端网卡在缓存、重组、重传上付出的硬件代价
- 指出开启自适应路由时，交换机与网卡各自该看哪三个关键指标，涵盖时延差、丢弃数、重排率

## 机制拆解

### 0x01 病因：五元组散列的静态盲盒

传统 ECMP 散列是静态的，也是盲目的。

报文进交换机，硬件拿五元组做哈希，模上链路数，算出来是几就走几号端口。

这个过程不管出端口此刻谁在排队。即使某端口的水位贴近 XOFF 水线，只要新来的报文哈希值落在此处，硬件依然把它塞进去。

这相当于早高峰的收费站：每个车道明明有指示灯，司机进站前却闭眼摇号。摇到几号就排几号，即使旁边车道空着，也绝不变道。

### 0x02 选路粒度：从 Flow 到 Packet Spraying

自适应路由（Adaptive Routing，简称 AR）只有一句：**把选路依据从报文静态身份，换成出端口实时拥塞。**

交换芯片在转发时，直接查几条等价上行的出端口队列深度。谁的队列浅、谁的时延小，就把报文甩给谁。

甩什么东西，业界有三种粒度：

| 选路粒度 | 怎么切分 | 保序能力 | 链路利用率 | 硬件开销 |
|---|---|---|---|---|
| **Per-Flow（流级）** | 完整五元组流绑定一条路 | 完美保序，绝无乱序 | 差，同质大象流依然极化 | 极低，传统交换芯片标配 |
| **Flowlet（流突发切片）** | 利用通信静默期间隙换路 | 大体保序，依赖间隔时间 | 中等，突发间隔必须大于多径时延差 | 中等，需记录每条流时间戳 |
| **Packet Spraying（逐包喷洒）** | 同一条流的报文逐包轮流分发 | 彻底破坏顺序，必然严重乱序 | 极致打满，利用率贴近 95% 以上 | 高，压力全部转嫁给网卡 |

Flowlet 在传统 Web 流量里表现不错。HTTP 请求发完，TCP 连接往往安静几毫秒。这个时间足够让前一个包到达，换路不会导致报文倒挂。

但训练流量完全没有静默期。NCCL 的 Ring AllReduce 一旦启动，GPU 端口就是持续数十秒的线速打满。**流里面找不到足够宽的间隔让你安全换路。**

万卡智算网络里上自适应路由，方案普遍直接拉满到最右侧：**Packet Spraying（逐包喷洒）**。同一个 QP 的报文，前一个走 Spine1，后一个走 Spine2。

### 0x03 代价：接收端网卡的乱序重组噩梦

带宽确实打满了，代价也转嫁出去了。因果链走到这里再次闭环：**网络侧省掉的排队，变成了主机侧的乱序重组。**

多条路径的光纤长度不可能完全相等，交换芯片的处理抖动也无法绝对对称。只要差几十纳秒，后发的报文就可能先到达接收端。

网卡按传统方式处理，遇到未按 PSN 连续到达的报文直接丢弃，逐包喷洒会把网络搞瘫痪。开启自适应路由的前提，是**网卡硬件必须原生支持乱序重组（OOO Reorder）**。

网卡内划出专门的片内 SRAM 作为乱序接收缓冲。硬件根据报文头部的 PSN 暂存并重排，再通过 DMA 直写应用显存。

::: info 经验映射（IDC → AIDC）

用熟悉的东西类比一下。Packet Spraying 相当于在交换机出端口做逐包负载均衡，也就是把四层负载均衡的轮询打到了每个数据包上。

网卡的 OOO 重组队列，相当于 TCP 的接收滑动窗口与重排队列。

区别在于，TCP 是由主机 CPU 协议栈在内存里重排，微秒级。RDMA 的重排全部在网卡芯片硬件逻辑里完成，纳秒级。
:::

::: warning 乱序重组的失效边界：Buffer 溢出即雪崩

网卡的 OOO 重组队列不是无限大的。常见 400G 网卡的片内重组缓冲通常只有几兆字节。

某条路径发生隐性故障或丢包，导致关键报文迟迟不来，后续报文持续涌入，**重组缓冲区就会被瞬间占满**。

一旦 OOO Buffer 溢出，网卡只能强行丢包。这时候监控上会出现一个反直觉的现象：**交换机端口水线平稳无丢包，网卡侧却突然报出大面积 RDMA 重传与任务超时。**
:::

## 经验映射

| 你熟悉的机制 | 对应到自适应路由 |
|---|---|
| Nginx 轮询 upstream | 逐包喷洒（Packet Spraying） |
| 基于响应时间的动态选路 | 交换芯片基于出端口队列深度的自适应分流 |
| TCP 接收窗口乱序重排 | RDMA 网卡片上 OOO 缓冲区与硬件重组 |
| 客户端缓冲打满丢弃 | 网卡片内 SRAM 耗尽导致的序列错误丢弃 |

推论很明确：**以前看网络只盯交换机、端口、队列。开启自适应路由后，观测重心必须往网卡片内状态、重组队列、时延偏差倾斜。**

## 判读与实操

### 0x04 核心遥测指标与命令

开启自适应路由的集群，观测体系需要覆盖交换机与网卡两端：

| 观察点 | 关键指标 | 采集方式 | 判读基准 |
|---|---|---|---|
| **交换机端口** | 动态选路偏转比率 | gNMI 订阅私有计数器 | 偏转率突增意味着直连链路存在隐性丢包 |
| **Fabric 织网** | 等价路径时延差（Path Skew） | INT 带内遥测或高频探针 | 最大时延差超过重组容限（通常 > 10μs）需告警 |
| **网卡端侧** | 乱序到达计数（`rx_out_of_order`） | `ethtool -S` 采集 | 高速增长属正常工作，说明喷洒已生效 |
| **网卡端侧** | 乱序重组丢弃（`packet_seq_err`） | `ethtool -S <ifname>` | **必须严格为 0**，大于 0 说明硬件重组失效 |

主机侧排查网卡乱序与重组状态的常用命令：

```bash
# 抓取网卡侧与乱序、重排、重传相关的底层计数器
ethtool -S <ifname> | grep -Ei 'out_of_order|reorder|seq_err|out_of_buffer'

# 实时观测接收端重排错误变化增量
watch -d -n 1 "ethtool -S <ifname> | grep -E 'packet_seq_err|out_of_buffer'"
```

判读要点：

- `rx_out_of_order` 上涨是常态，证明自适应路由确实起效了。
- `packet_seq_err` 出现非零增长，必须立刻介入：网络时延抖动已经超过了网卡硬件的重排能力上限。

## 习题

**必答 Q1**：为什么说自适应路由是把网络侧的排队压力换成了主机侧的乱序压力。

::: details 参考答案与评分维度

- **网络侧变化**：交换机把数据包打散到所有上联路径，不再单一排队。队列水线保持低位，消除了单端口微突发与 PFC 暂停。
- **主机侧代价**：多路径存在微小时延差异，逐包分发导致原本连续的报文乱序到达目的地。
- **压力转移**：接收端网卡必须动用片内高速重组缓冲区，将报文暂存、比对并重排后再写入显存。网络交换机里的排队行为，被转移到了网卡的重组队列中。

**评分维度**：答出两端行为差异（必需）。明确指出网络排队与网卡重组的对消关系（加分）。
:::

**必答 Q2**：某集群开启逐包自适应路由后，交换机监控全绿无水线告警，但训练任务频繁掉速超时。网卡侧 `rx_out_of_order` 巨大，且 `packet_seq_err` 每秒增加数千。请指出故障根因与排查路径。

::: details 参考答案与评分维度

- **根因分析**：交换机某条等价路径存在物理劣化，也就是光纤脏污或局部降速。该慢路径导致分发到其上的报文时延极大，形成严重的时延倾斜（Path Skew）。
- **失效链条**：时延倾斜超过网卡重组容限，超期乱序包被作为序列错误丢弃。这会引发 RDMA 重传风暴，拖垮通信任务。
- **排查路径**：
  1. 巡检所有上联光模块的收发光功率与 FEC 纠错计数，抓出误码慢链路。
  2. 检查交换芯片的容忍时延差配置，确保链路劣化时芯片能自动剔除慢路径。

**评分维度**：指出慢链路引发 Path Skew 击穿重组窗口（必需）。给出从光模块与 FEC 找慢路径的落地步骤（必需）。
:::

**思考题（不给参考答案）**：如果一张 Fabric 里的自适应路由芯片来自厂商 A，而网卡来自厂商 B。在没有统一协议标准的情况下，两者的配合最容易在哪个参数处发生分歧。请给出你的排查思路与一条判定依据。

## 小结

这一讲可以压成一句话：**自适应路由把选路权从静态五元组，交还给交换机的实时队列深度。**

静态 ECMP 的死穴在于盲目哈希，在同质流面前无路可选。自适应路由把选路权交给交换芯片的出端口队列状态，通过逐包喷洒把整网带宽打满。但天下没有免费的午餐，网络甩掉了排队，接收端网卡就必须用片上 SRAM 扛起乱序重组、报文校验、序列维护的责任。

一旦路径时延倾斜打穿了网卡重组队列，系统就会发生无 PFC 告警、无交换机丢包、无端口报错的隐性雪崩。

::: tip 本课要点

**自适应路由把选路权从静态五元组，交还给交换机的实时队列深度。**

- 静态 ECMP 盲区：同质大象流五元组完全相同，哈希结果唯一，等价上行必定极化
- 选路三档粒度：Per-Flow 保持保序但极化、Flowlet 依赖突发间隙不适用训练、Packet Spraying 彻底打满带宽
- 核心代价转移：**网络侧队列水线下降，接收端网卡承担乱序重组压力**
- 致命失效模式：单链路劣化引发多径时延倾斜，打爆网卡重组缓冲区导致丢弃
- 运维口径更替：交换机端口只看利用率还不够，必须同时监控网卡的乱序重组丢弃
:::
