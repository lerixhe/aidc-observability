一台交换机 down 掉，在万卡集群里会放大成上千条告警。

它自己的 LLDP 与 BGP 邻居批量报警。经过它的所有探测路径开始超时、丢包、时延上涨。受影响的 Rail 上流量偏离、队列水位异常。再往上是训练任务变慢与 NCCL timeout。最后这些告警广播给所有人。

**一个物理故障换来几百上千条告警，真正有用的信息只有一句：X 设备 down 了。** 值班工程师淹在这一千条里，还得自己找出那一句。

这一讲讲怎么用四层把这一句捞出来，以及每一层的输入从哪来。

## 交付

- 万卡规模下告警风暴的成因与代价
- AIOps 四层的职责与依赖顺序，哪一层最容易做成空中楼阁
- 用图的语言描述故障定位：节点、边、事件标记、共同祖先
- 三代根因定位算法的适用场景，以及「难点不在算法」的具体所指
- 自动化处置的分级与兜底

## 一个故障，一千条告警

告警放大来自三个机制。

依赖广播。一台设备挂了，它的所有邻居都报一次「对端不可达」，这是拓扑决定的数量。

路径广播。一条链路劣化，所有经过它的探测路径都报一次，覆盖这条链路的探测有多少条，告警就有多少条。

视角广播。同一次故障，路径视角看到的是时延，设备视角看到的是 down，任务视角看到的是变慢，三层各自报警，互不知道说的是同一件事。

告警收敛要压掉的正是这三种放大。压完还剩几个 incident，才轮到定位。

## 四层，顺序不能跳

| 层 | 做什么 | 关键依赖 |
|---|---|---|
| 数据基础 | 秒级遥测 + 路径探测 + 任务元数据 + 拓扑 | 没有数据层，后三层全是空中楼阁 |
| 告警收敛 | 去重、抑制、聚合；按同源与时间窗折叠，按拓扑归并为 incident | 需要拓扑与告警语义 |
| 根因定位（RCA） | 在收敛后的 incident 集合里回答「根因是哪个节点或链路」 | 需要干净的图与对齐的时间 |
| 自动化处置 | 隔离端口、切换路径、建议换件、通知训练平台做任务级规避 | 需要可靠的执行与回滚机制 |

没有收敛好的告警，RCA 被噪声淹没。没有可靠的 RCA，自动化处置等于自动放大故障。四层的建设顺序就是数据 → 收敛 → RCA → 处置，跳一步就得回头补。

## 网络本来就是一张图

设备是节点，链路是边，接口、队列、模块是节点属性，告警与指标异常是节点或边上的事件标记。这张图由 LLDP / BGP 邻居发现加配置数据自动构建，09 讲讲的「拓扑是一等公民」在这里兑现。

故障传播有个方向：沿拓扑向下流。Spine 故障，它下面所有 Leaf 的路径都异常，再往下受影响的是一批任务。

反过来推就是根因：**若干告警节点的共同上游祖先，就是根因候选。**

问题在于「共同祖先」很少唯一。一个 incident 里的告警集往往横跨几层，共同祖先可能是三四台设备。算法要做的第二件事是给候选排序，排序依据是传播路径上的证据：时间先后、异常量级、路径重叠度。

## 三代算法

| 代数 | 方法 | 特点 | 适用 |
|---|---|---|---|
| 第一代 | 故障树 / 人工规则 | 准，但维护不动，规则数量随拓扑规模爆 | 已知的高频模式 |
| 第二代 | 相关性加图搜索（公共祖先、传播路径评分） | 朴素有效，工程主流 | 绝大多数线上场景 |
| 第三代 | Random Walk / GNN | 学习「故障通常从哪类节点爆发」 | 前沿探索，大厂试点 |

第二代的实现不复杂：取 incident 的告警节点集，在图上找共同上游祖先，按「时间最早 + 异常最大 + 覆盖告警最多」打分，输出 Top-3 候选加证据链。一天能写出原型，难的是把它跑准。

## 难的是数据

图计算 RCA 的**难点不在算法，在数据质量**。三处输入错一个，结论就错。

拓扑要准。配置漂移、静态拓扑表过期、聚合口与子接口的映射写错，都会让图失真，共同祖先直接算错。

事件时间要对齐。设备间时钟差几秒，传播方向就判反，把下游当上游。

告警要收敛好。噪声节点进了图，评分被稀释，Top-3 里塞满无关设备。

这三条解释了为什么「① 数据 → ② 收敛 → ③ RCA」的建设顺序本身就是认知。算法是成熟工具，输入错了输出必然错。

## 大模型的落点

| 层 | 大模型能做什么 |
|---|---|
| 告警收敛 | 告警摘要与聚类描述，把 50 条告警写成人话 |
| RCA | 检索历史相似故障（RAG），辅助给出候选根因与证据链 |
| 处置 | Agent 调用工具（查指标、查拓扑、执行预案） |

处置那一层是 18 讲的正题，这里只立一条边界：模型负责组织和解释，不负责计算与执行。

## 经验映射

| 你已有的做法 | 在 AIOps 里的位置 |
|---|---|
| 阈值告警加静默规则 | 告警收敛的最简版 |
| 手工「路径集合与拓扑求交」排查 | RCA 的人工版 |
| 值班手册 / runbook | 处置层的雏形，待编排化 |
| 数据管道与降采样 | 数据基础那一层 |
| 缺失的部分 | 收敛产品化、图模型、处置编排与回滚 |

07 讲四大故障时已经做过一次朴素 RCA：探测发现受影响路径集合，与拓扑求交集，缩小设备候选集。这就是图推理的最简形式，手工版。要补的是把它产品化、自动化的工程，不是换一套思维方式。

## 判读与实操

一个能跑起来的最小闭环：

```text
数据：gNMI 订阅（秒级）+ 探测结果 + 拓扑图（LLDP/BGP 自动发现）+ 任务元数据
收敛：同设备同时间窗的告警折叠成一个 incident；下游告警标记为「疑似派生」
RCA ：incident 节点集 → 图上找共同上游祖先 → 按传播路径打分排序 → 输出候选根因
处置：候选根因 + 置信度 → 低危动作自动、高危动作审批 → 执行后验证 → 不达预期回滚
```

质量指标比算法选型重要。没有这几个数字，任何「我们上了图算法」都无法证明价值。

| 指标 | 含义 |
|---|---|
| 告警压缩比 | 一千条告警压成几个 incident |
| 根因命中率 | 人工确认的根因是否在候选 Top-3 内 |
| 误报率 / 漏报率 | 收敛规则与阈值的效果 |
| 处置成功率与回滚率 | 自动化是否可信 |
| 平均定位时长 | RCA 环节对 MTTR 的实际贡献 |

## 习题

::: tip 怎么做题

先自己写答案，三行也算，再展开对照，最后按「评分维度」逐条自评。

:::

**必答 Q1**：用四层框架做一段陈述：「给万卡集群建智能运维体系，你怎么分层搭建，每层解决什么？」控制在 400 字内。

::: details 参考答案与评分维度

数据基础。gNMI 秒级遥测（队列、PFC、ECN、CRC/DOM）加路径级探测加任务元数据加自动发现的拓扑图。这一层决定后面能不能做，先解决采集分级与时钟对齐。

告警收敛。同设备、同时间窗折叠，按拓扑归并为 incident，下游告警标记为派生，目标是压缩比上一个数量级。

RCA。把网络建成图，用「共同上游祖先加传播路径评分」输出候选根因与证据链。先做朴素图搜索，等数据质量稳了再考虑学习类方法。

处置。分级自动化，低危自动、高危审批，每个动作配预期验证与回滚，并有全局熔断开关。

**评分维度**：四层齐全且职责清楚（必需）。指出依赖顺序与「数据质量决定上限」（必需）。给出至少一个可量化指标（加分）。

:::

**必答 Q2**：用图的语言重新描述「30 多条路径劣化，找 PFC 风暴源点」的排障流程。节点、边、事件标记分别是什么？共同祖先搜索在找什么？

::: details 参考答案与评分维度

节点是交换机与服务器网卡，端口算节点的接口属性，光模块算节点属性。边是物理链路及其上承载的方向性转发关系，含 ECMP 的多条等价边。事件标记里，路径时延异常挂在边上，pause 计数异常挂在节点或接口上，队列水线同理。

共同祖先搜索找的是所有劣化路径在拓扑上的共同上游汇聚点，也就是那个「自身入流量正常、pause 计数最早异常上涨」的节点，它是暂停波最可能的发源方向。

**评分维度**：三类元素定义正确（必需）。共同祖先与暂停波源头的对应关系说清（必需）。提到按时间先后排序而非只看空间祖先（加分，这是避免误判的关键）。

:::

**自测 Q3**：为什么说图计算 RCA 的难点不在算法而在数据质量？

::: details 参考答案与评分维度

三处「垃圾进」。拓扑图失真，配置漂移或静态表过期，公共祖先算错。事件时序乱，时钟未对齐，传播方向判反。告警未收敛，噪声节点污染图，评分被淹没。

图搜索与传播评分本身是成熟工具，输入错则输出错。建设顺序必须是数据 → 收敛 → RCA。

**评分维度**：给出至少两个数据质量问题（必需）。强调顺序（必需）。

:::

**自测 Q4**：自动化处置最大的风险是什么？怎么设计兜底？

::: details 参考答案与评分维度

最大风险是错误处置放大的次生故障。根因误判时自动隔离正常端口或切换路径，把小故障变成大故障。

兜底四条。动作分级，可逆低危自动、不可逆高危人工审批。执行前写「预期验证」，处置后指标应如何变化，不达预期立即回滚。灰度启用，先部分集群。全量审计加全局熔断开关。

**评分维度**：说出误判放大故障（必需）。给出分级与回滚两类机制（必需）。提到熔断、灰度（加分）。

:::

## 小结

万卡规模下，一个物理故障会广播出上千条告警。放大来自三个机制：依赖广播、路径广播、视角广播。值班的被淹死，有用的信息只有一句「X 设备 down 了」。

四层架构的依赖顺序不能跳：数据基础、告警收敛、RCA、自动化处置。没有收敛好的告警，RCA 被噪声淹没。没有可靠的 RCA，自动化处置等于自动放大故障。

图计算做 RCA 的道理很朴素。网络本来就是一张图，故障沿拓扑向下传播，若干告警节点的共同上游祖先就是根因候选。算法只是把这句话写成程序，难的地方全在数据质量：拓扑要准、时间要齐、告警要收敛干净。

::: tip 本课要点

**一个故障上千条告警，捞出来的只有一句。**

- 告警放大三机制：**依赖广播、路径广播、视角广播**
- 四层框架：**数据基础 → 告警收敛 → RCA → 自动化处置**，依赖顺序不可跳
- 图 RCA：网络天然是图，**故障沿拓扑向下流，告警的共同上游祖先就是根因候选**，再按时间、量级、覆盖度排序
- 算法三代：故障树（准但难维护）→ 图搜索（工程主流）→ RW / GNN（前沿）
- 难点在数据质量：**拓扑准、时序齐、告警收敛好**。先有质量指标，再谈算法
- 处置风险：误判放大故障 → 分级加预期验证加回滚加熔断

:::

留一个思考题：如果只能先把一层做扎实，你选告警收敛还是 RCA，理由是什么。
