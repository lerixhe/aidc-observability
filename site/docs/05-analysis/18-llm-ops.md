拆开一次故障处理，工程师实际在做四件事：

| 动作 | 性质 | 适合谁 |
|---|---|---|
| 读大量非结构化文本（告警描述、日志、工单、runbook、历史复盘） | 语言理解 | 模型强项 |
| 凭经验联想「这个报错像上个月那次」 | 检索式记忆 | 模型加 RAG |
| 查一堆系统拼证据（指标、拓扑、任务状态） | 工具编排 | 模型编排、工具执行 |
| 确定性执行（重启进程、下发配置） | 状态变更 | 传统自动化 |

四件事里前三件都能交给模型，第四件不能。这就是分工原则：**理解与编排交给模型，计算与执行交给老系统。**

反着来，让模型算指标、直接执行命令，是所有失败案例的共同起点。

## 交付

- 为什么运维适合模型，以及哪些环节绝不能交给它
- 三级落地的风险递增曲线，自己的团队该先落在哪一级
- 一个网络排障 Agent 的 Loop：规划、调工具、观察、再推理、产出证据链
- 四条护栏，尤其是上下文工程与证据链强制的具体做法
- 为什么评测回放是落地前提，不是可选优化

## 三级落地

| 级别 | 场景 | 风险 | 前置依赖 |
|---|---|---|---|
| L1 摘要 | incident 自动摘要：把 50 条告警写成人话（影响面、疑似方向、建议排查项） | 零，只读，输出给人看 | 告警收敛已做好 |
| L2 检索 | RAG 知识库：runbook、历史复盘、配置文档向量化，值班时问答 | 低，答案可能过期，需带出处 | 文档资产与版本管理 |
| L3 Agent | 工具调用闭环：自主决定调什么工具、拼证据、产出候选根因加证据链 | 中，幻觉风险，需护栏 | 工具 API 化、权限分级 |

多数团队应该从 L1 起步，因为它只依赖告警收敛，而收敛本来就是 16 讲要求先做扎实的那一层。跳到 L3，工具层通常是空的。

## Agent Loop

```text
输入：「任务 X 变慢，网络侧有没有问题？」
  → 规划：先查任务元数据（哪些 Rank、哪些路径）
  → 调工具：query_topology() / query_probe_paths() / query_gnmi_counters()
  → 观察：某 rail 的 pause 计数异常上涨
  → 再推理：补查该 rail 的 CRC/DOM 与相邻端口
  → 产出：候选根因 + 证据链（每条结论引用具体工具返回值）
  → 人工确认 / 分级处置
```

这个循环和工程师手工排障的步骤一模一样，区别只在每一步换成可执行的工具调用。规划错了会绕路，工具返回太脏会跑偏，缺验证步骤会自信地给出错结论。

## 四条护栏

**上下文工程。** 不能把原始数据喂给模型。一亿个时序点塞不进上下文，塞进去也没有意义。工具先把数据聚合成摘要，比如「过去 5 分钟该设备 PFC pause 上涨 40 倍，涉及 3 条路径」，模型只吃结论级摘要。

这和探测端先做多维聚合、再上报是同一个做法：把计算下沉到离数据近的地方。谁离数据近，谁负责算。

**证据链强制。** 所有结论必须引用工具返回值，引用不上的陈述显式标记为「推测」。防幻觉的核心是**让编的无处遁形**，不是求模型别编。只要结论必须挂证据，幻觉就从隐蔽的错误变成显式的空缺。

**权限分级。** 只读工具随便调；写工具走白名单加参数校验加人工审批。这就是 16 讲「处置分级加回滚」在模型场景下的落地。

**评测回放。** 用历史故障做回放测试：输入当时的告警，看 Agent 能否得出当时的结论、证据链是否成立。没有回放的 Agent 是玄学。回放集同时也是回归测试集，提示词或工具改动都要跑一遍。

## 门槛在工具层

L3 的成本主要不在模型调用费，在**工具 API 化**。拓扑查询、路径查询、设备计数器、runbook 检索，全都要变成稳定的、有权限边界的、返回摘要的接口。

没有这一层，Agent 只能在聊天窗口里「建议你去查一下」。多数公司的 AIOps 项目停在 L1，卡住的地方是工具层，不在模型。

## 经验映射

| 你已有的能力 | 在 LLM 落地里的位置 |
|---|---|
| 告警收敛与 incident 归并 | L1 摘要的输入 |
| runbook 与复盘文档积累 | L2 知识库的原料 |
| 指标与拓扑查询 API | L3 工具层的原料 |
| 处置分级与回滚设计 | 权限分级护栏 |
| 用过编码 Agent | 对 Agent 行为与失效模式的直觉 |
| 缺失部分 | 评测回放体系、工具层的摘要粒度设计 |

用过编码 Agent 的人对这套失效模式不陌生：上下文放不下就会瞎猜，工具返回太脏就会跑偏，没有验证步骤就会自信地错。运维 Agent 踩的是同一批坑。

## 判读与实操

| 护栏 | 具体措施 | 验收方式 |
|---|---|---|
| 上下文工程 | 工具返回聚合摘要，附时间窗与口径说明 | 单次调用返回体 < 2KB 且含结论 |
| 证据链 | 每条结论附 `tool_call_id` 与关键数值 | 抽检 20 条结论，能被人工复核 |
| 权限分级 | 读写工具分注册表，写操作需审批工单 | 演练一次越权调用被拒绝 |
| 评测回放 | 30 个历史故障的告警快照加期望结论 | Top-3 命中率与证据完整率 |

判读几条常见现象：

| 现象 | 判读 |
|---|---|
| Agent 反复调同一工具 | 工具返回不含它需要的信息，摘要粒度错了 |
| 结论正确但证据链缺失 | 提示词未强制引用，或工具没返回可引用的标识 |
| 结论在相似场景间摇摆 | 缺评测回放集，无法回归验证 |
| 人工最终不采纳 | 多数是摘要信息不足，而非模型推理能力不足 |

## 习题

::: tip 怎么做题

先自己写答案，三行也算，再展开对照，最后按「评分维度」逐条自评。

:::

**必答 Q1**：三分钟陈述：「在智算网络监管控平台里落地大模型能力，你分几级、每级做什么、护栏怎么设？」控制在 400 字内。

::: details 参考答案与评分维度

**L1 摘要**。incident 自动摘要，给出影响面、疑似方向与建议排查项。纯只读，输出给人看，先解决值班被淹。

**L2 检索**。runbook、历史复盘、配置文档入 RAG，带出处与版本，回答「这类告警的处置路径」。

**L3 Agent**。工具调用编排，产出候选根因加证据链。工具层必须 API 化并返回聚合摘要。

**护栏**四条。上下文工程，只喂结论级摘要。证据链强制，结论必须引用工具返回值，推测显式标注。权限分级，读写分离、写操作审批。评测回放，用历史故障集做回归。

**评分维度**：三级清晰且风险递增（必需）。护栏至少覆盖证据链与权限（必需）。指出工具层 API 化是 L3 的真门槛（加分）。

:::

**必答 Q2**：「防幻觉的核心，是让编的无处遁形」。展开这句话背后的设计。

::: details 参考答案与评分维度

幻觉是概率模型的固有属性，用提示词说「请不要编造」无法消除，只能降低频率。那等于把可靠性寄托在不可控因素上。

设计换个方向：让编造在结构上无法通过。做法是强制证据链，每条结论必须关联具体工具调用与返回值，没有证据的只能以「推测」出现并明确标注。

模型仍可能编，但编出来的东西一眼可辨，不会伪装成事实进入决策链。再进一步，把关键计算从模型手里拿走，下沉到 SQL 与聚合引擎，模型只决定算什么、解释结果。

**评分维度**：指出幻觉不可消除（必需）。给出结构上无法伪装的做法而非提高模型能力（必需）。提到计算下沉（加分）。

:::

**自测 Q3**：为什么不让模型直接计算指标、直接执行预案？

::: details 参考答案与评分维度

计算方面，模型是概率模型，算术不保证精确，大规模数据也进不了上下文。计算必须下沉到 SQL、代码、聚合引擎，模型只决定算什么。

执行方面，输出具概率性，一次幻觉就是一次生产事故，预案执行通常不可逆。

分工原则：模型管不确定性高的理解与编排，确定性系统管正确性要求高的计算与执行。

**评分维度**：两点都答到（必需）。补出执行需审批与回滚（加分）。

:::

**自测 Q4**：设计一个网络排障 Agent 的工具清单，至少 5 个，标注读写与返回粒度。

::: details 参考答案与评分维度

| 工具 | 类型 | 返回粒度 |
|---|---|---|
| `query_task_meta(task)` | 只读 | 并行策略、Rank 分布、起止时间（结构体） |
| `query_topology(device 或 task)` | 只读 | 邻接关系、所在 rail 与平面（小图） |
| `query_probe_paths(task 或 device)` | 只读 | 受影响路径集合与时延劣化摘要（Top-N，不含原始序列） |
| `query_device_counters(device, window)` | 只读 | 聚合后的 pause / ECN / CRC / 队列摘要，带口径说明 |
| `search_runbook(symptom)` | 只读 | 相似历史故障与处置方案，带出处与时效 |
| `execute_playbook(action, args)` | 写 | 白名单动作加审批工单号加结果回执 |

考察两件事：粒度意识（给模型的都是摘要）与权限意识（读写分离、写操作审批）。

**评分维度**：五个以上工具且读写标注清楚（必需）。返回粒度明确是摘要（必需）。写工具配审批（加分）。

:::

## 小结

一次排障拆成四件事：读文本、联想历史、拼证据、执行变更。前两件是语言理解，第三件是工具编排，第四件是状态变更。前三件模型能帮上大忙，第四件绝对不能交给它。

落地分三级。L1 摘要零风险，L2 检索低风险，L3 Agent 中风险要护栏。护栏四条：只喂摘要不喂原始数据、结论必须挂证据、读写权限分级、用历史故障做回放评测。

门槛不在模型，在工具层。拓扑查询、路径查询、设备计数器、runbook 检索，全得变成稳定的、带权限的、返回摘要的接口。没有这一层，Agent 只能在聊天框里建议你去查一下。

::: tip 本课要点

**理解与编排给模型，计算与执行给老系统。**

- 分工原则：模型管语言理解与工具编排，传统系统管计算与状态变更，反着来必翻车
- 三级落地：**L1 摘要（零风险）→ L2 RAG 检索（低）→ L3 Agent 工具调用（中，需护栏）**
- Agent Loop：规划 → 调工具 → 观察 → 再推理 → 产出**证据链**
- 四条护栏：**上下文工程、证据链强制、权限分级、评测回放**
- 真门槛是**工具层 API 化加摘要粒度设计**，这也解释了多数项目为何停在 L1
- 防幻觉的方向：**让编的无处遁形**。求模型别编是伪命题

:::

留一个思考题：如果 Agent 的候选根因对了但证据链缺一条，你会让它自动处置吗。
