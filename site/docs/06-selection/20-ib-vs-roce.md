如果要用一句话来描述这一讲，我想应该是：选 RoCE 就是用运维复杂度换供应链自由度。

RoCEv2 那一讲留下了一个问题没答：既然 InfiniBand 天生无损、免调优，为什么还要在以太网上费力做无损？

这一讲把两个阵营摆在一起，公平地讲完技术事实，再讲工程选择。

## 学完这一讲，你应该能

- 列出 IB 与 RoCE 在形态、无损机制、独特能力、运维复杂度、成本上的差异
- 说出国内主流厂商选择以太系 RoCE 的四个理由，而不只是"便宜"
- 解释一个关键因果：选择 RoCE 如何直接催生了"网络自动化、可观测平台"这类岗位
- 掌握一段不站队、展示判断力的应答框架（技术层 → 工程层 → 个人层）
- 理解 SHARP 这类"在网计算"为什么是 IB 的专属红利

## 机制拆解

### 0x01 两个阵营各自是什么

| 维度 | InfiniBand | RoCEv2（以太系） |
|---|---|---|
| 形态 | 专用网络：专用交换机、网卡、线缆，全栈一体 | 标准以太网：白盒或商用交换机加标准网卡 |
| 无损机制 | **天生 credit-based**：硬件逐跳信用，**基本免调优** | PFC / ECN / DCQCN 软硬协同，**需要精细调优** |
| 独特能力 | **SHARP 在网计算**：交换机上做集合通信归约，显著减少流量 | 标准生态：SONiC、白盒、开放模型（OpenConfig） |
| 运维复杂度 | 低：Subnet Manager 自动化配置，插上就通 | 高：全网配置一致性是命门（DCB 三件套） |
| 生态 | 单一厂商主导，封闭 | 多厂商开放，带宽演进快 |
| 成本 | 高（专有硬件溢价） | 低（规模效应加竞争性采购） |

一个不可忽略的动态：**IB 阵营自己也在向以太网形态靠拢**。面向 AI 的以太网 AI Fabric 方案，用自适应路由与拥塞控制补齐以太网的短板。

"以太网不适合 AI"这个论断已经过时，方向上的分歧正在收敛为"谁的软件栈更成熟"。

::: info SHARP 为什么值得单独记

SHARP（Scalable Hierarchical Aggregation and Reduction Protocol）做的事，是把归约计算**下沉到交换机上执行**，比如 AllReduce 的求和。

数据不必全部走到终点再算，路径中间就被合并，回程流量大幅减少。用 Go 的话说，这相当于在中间层先做一次 merge，最后再到终端 reduce。

这是专用硬件的红利，标准以太网交换芯片做不了这种定制计算。讲清楚这一点，能体现你对 IB 的评价是公平的，而不是"因为没得选所以选以太网"。
:::

### 0x02 国内为什么选以太系：四个理由

1. **供应链自主。** IB 绑定单一供应商。以太系可白盒自研加多厂商竞争。对超大规模自建集群，这是战略级考量，不是成本考量。
2. **成本曲线。** 万卡以上规模，单位带宽成本以太网显著更低。而且以太网带宽演进节奏更快，换代不用等专有体系。
3. **运维体系延续。** 既有数据中心几乎全是"以太网加自研管控"，人才、工具链、经验全部可延续。换 IB 等于另起炉灶。
4. **软件定义的红利。** 以太系可定制（rail 优化、遥测深度、自研协议配合），把网络变成自己的竞争力，而不是买来的黑盒。

::: warning 这一讲最重要的一句因果

**正因为选择了 RoCE**，PFC / ECN / DCQCN 的调优、全 Fabric 配置一致性、故障定位才变得极其复杂。而这些复杂度必须靠**平台软件**去填。

换句话说：**"网络可观测、自动化平台"这类岗位，很大程度上是"选择 RoCE"这个技术路线的产物。**

IB 世界里很多能力是硬件自带的。以太系世界里，同样的能力要自己写代码解决。平台软件相当于接过了硬件本该做的事。理解了这一点，你也就理解了这类岗位为什么存在、价值在哪。
:::

这四条里，前三条是成本与供应链，第四条是技术偏好。换个说法，选 RoCE 相当于把网络当成自研系统的一部分，而不是一个采购项。

### 0x03 两套世界的运维差异

| 事项 | IB 世界 | RoCE 世界 |
|---|---|---|
| 无损保障 | 硬件信用机制，默认成立 | PFC 加 ECN 参数加全网一致性，需要持续维护 |
| 拥塞控制 | 内置，参数少 | DCQCN 端网协同，参数联动、需调优 |
| 变更风险 | 相对低 | 高（一跳配置不一致即可引发全局抖动） |
| 定位难度 | 相对低 | 高（症状现场 ≠ 根因现场） |
| 平台价值 | 较小（硬件兜底） | **极大（软件兜底）** |

::: info 经验映射（IDC → AIDC）

"经验重叠"这件事值得讲清楚。以太网的形态是同一套：Clos、ECMP、VLAN 与 QoS、SNMP 与 gNMI 管控。变的是**运维语义整体升级**。

有损范式看丢包重传、分钟级轮询、设备为中心。无损范式看 PFC/ECN 调优、秒级流遥测、rail 与任务为中心。

硬件相近，平台软件的复杂度天差地别。所以要补的是领域语义，不是从零学网络。
:::

## 经验映射

| 你已有的经验 | 在以太系 RoCE 里的价值 |
|---|---|
| 以太网 / Clos / ECMP 基础 | ✅ 直接适用 |

| 传统管控（SNMP / 网管） | 🟡 需升级到 gNMI 订阅与模型映射 |

## 判读与实操

### 0x04 被问到路线之争时的应答框架

不站队，展示判断力，最后落回自己。

1. **技术层（公平）。** "IB 的优势是天生无损、免调优、在网计算，小规模快速起步很香。RoCE 的优势是生态开放、成本、可定制，代价是把无损的复杂度从硬件转嫁给了运维和平台。"
2. **工程层（动态）。** "万卡以上规模，供应链安全与单位带宽成本会让天平倒向以太系。而且 IB 阵营自己也在做以太网方案，方向已经收敛。"
3. **个人层（匹配）。** "以太系把复杂度交给平台，这正是可观测与自动化平台的价值所在。你过去做的事恰好就是这件事，所以这条路线对你的意义是：有挑战，更有用武之地。"

| 问题 | 若答案为"是" |

## 习题

**必答 Q1**：用三段式框架（技术层、工程层、个人层）把"IB vs RoCE 之争"完整答一遍。这是可以直接拿去用的答案，请认真写。

::: details 参考答案与评分维度

**技术层**：IB 是专用网络，无损由硬件信用机制保证，基本免调优，还有 SHARP 在网计算，小规模起步很省心。RoCE 跑在标准以太网上，无损靠 PFC/ECN/DCQCN 软硬协同实现。复杂度从硬件转嫁给运维与平台，换来的是开放生态与成本优势。

**工程层**：万卡以上规模，供应链自主、单位带宽成本、既有运维体系延续三方面都指向以太系。同时 IB 阵营自己也在推以太网形态的方案，说明方向上已经收敛。真正的差异在软件栈成熟度，不在物理层。

**个人层**：以太系把无损复杂度交给了平台软件，这正是网络可观测与自动化平台存在的理由。路径级观测、实时数据管道、设备遥测这些积累，正好是这个位置需要的。挑战在于补齐无损语义，机会在于这套能力在以太系里价值更大。

**评分维度**：三段齐全（必需）。技术层公平、不贬低 IB（必需）。工程层能说出"方向收敛或软件栈成熟度"（加分）。个人层具体而非泛泛表忠心（加分）。
:::

**必答 Q2**："网络自动化、可观测平台这个岗位，是选择 RoCE 的产物"，解释这条因果链。

::: details 参考答案与评分维度

选择 RoCE 之后，无损不再由硬件默认保证，要靠 PFC/ECN/DCQCN 参数在全网每一跳一致配置。配置错了链路依然"正常"，故障表现为隐性的性能劣化。

于是需要四件事：① 秒级设备遥测，看到队列与 pause。② 全 Fabric 配置一致性校验，防一跳配错。③ 端网关联与根因定位。④ 自动化下发与回滚，人改不过来。

这些全部是软件工作，平台团队因此成为刚需，岗位就在。

**评分维度**：把"硬件保证变软件保证"的转移讲清楚（必需）。串起至少三个由此产生的工作（遥测、一致性、定位、自动化）（必需）。能对比 IB 世界里这些能力由硬件自带（加分）。
:::

**自测 Q3**：SHARP 是什么？它为什么能减少网络流量？

::: details 参考答案与评分维度

SHARP 把集合通信的归约计算（如 AllReduce 的求和）下沉到交换机执行。数据不必全部汇聚到终点再计算，在路径中间就被归约合并，回程与后续链路的流量大幅减少。

这是专用硬件的红利，标准以太网交换芯片不易做此类定制计算。

**评分维度**：说出"交换机侧归约"（必需）。说出"流量减少的机制"（必需）。指出这是 IB 的专属优势（加分，体现评价公平）。
:::

**自测 Q4**：追问"传统 IDC 不也是以太网吗，有什么本质区别？"怎么接？

::: details 参考答案与评分维度

接法：网络形态确实同源（以太网、Clos、ECMP、QoS），但**运维语义整体升级**了。

- 有损变无损：从"丢包重传"到"PFC/ECN 前置避免丢包"。
- 轮询变订阅：从分钟级 SNMP 到秒级 gNMI。
- 设备为中心变任务为中心：从"哪台设备坏了"到"哪个任务的哪条环受影响"。

所以硬件相近，平台软件的复杂度差别巨大。需要补的是领域语义，不是从零学网络。

**评分维度**：承认同源（必需）。给出至少两项语义升级（必需）。把结论落在"补语义而非从零"（加分）。
:::

## 小结

这一讲可以压成一句话：**选 RoCE 就是用运维复杂度换供应链自由度。**

IB 是专用网络，无损靠硬件信用机制天生成立，还带 SHARP 在网计算，插上就通，代价是封闭和贵。RoCE 跑在标准以太网上，无损要靠 PFC、ECN、DCQCN 三个东西在全网每一跳配得一模一样，配错了链路照样通，训练悄悄变慢。

国内厂商选以太系有四个理由：供应链自主、成本曲线、运维体系延续、软件定义红利。这不是一句"便宜"能概括的。

最值得记住的因果是：正因为选了 RoCE，无损的复杂度才从硬件转嫁给了软件。于是有了秒级遥测、配置一致性校验、端网关联定位、自动化下发回滚这些活儿，也就有了平台岗位。

::: tip 本课要点

**选 RoCE 就是用运维复杂度换供应链自由度。**

- IB：专用网络、**天生 credit 无损、免调优**、SHARP 在网计算、封闭且贵
- RoCE：标准以太网、**复杂度转嫁给运维与平台**、开放生态、成本低、演进快
- 国内选以太系四理由：**供应链自主、成本曲线、运维延续、软件定义红利**
- 核心因果：**选了 RoCE → 无损复杂度靠平台软件解决 → 可观测与自动化平台岗位存在的原因**
- 方向已收敛：IB 阵营也在做以太网 AI Fabric，差异转到软件栈成熟度
- 应答框架：技术层公平 → 工程层动态 → 个人层匹配
:::

留一个思考题：如果一家公司只有两千张卡，你会建议它上 IB 还是 RoCE，理由和万卡集群一样吗。
