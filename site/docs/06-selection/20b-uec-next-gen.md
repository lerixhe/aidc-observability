本节我们来谈谈引入 UEC 需要注意的风险以及防范措施，避免无损失效、避免性能塌陷、避免人为操作失误。

先把要防的东西说清楚。前面几讲把 RoCEv2 的坑踩了一遍：PFC 的风暴与死锁、DCQCN 的滞后、Go-Back-N 的重传代价、QP 数量对上万卡的压迫。这四个问题互相纠缠，防丢包上 PFC 引来风暴，防极化上逐包喷洒打爆网卡重组，每修一处都要在别处加补丁，补丁又要调参，参数之间还互相影响。

超以太网联盟（Ultra Ethernet Consortium，UEC）的判断是：不再修补，换一层传输层。这个判断本身有风险，风险就在下面几条里。

## 配置安全

UEC 有一些非常危险的配置项，这些配置项会对网络的稳定以及数据安全造成非常严重的影响。比如把端到端信用反压关掉，交换机队列就会重新裸奔；把选择性重传退化成整窗口重传，一个包丢了就得回退几十个包；把网卡侧乱序重组关掉，逐包喷洒立刻把链路打瘫。

如何避免人为操作失误导致这些灾难性的后果，也是运维人员特别需要注意的风险点之一。UEC 在配置文件里提供了白名单机制，用于把危险的旋钮锁起来，只允许改动那些经过评审的项。比如在设备的 security 块增加下面的内容：

```text
allow-config uet.credit-backpressure uet.selective-nack
deny-config  uet.transport-mode uet.reorder-window
```

如果还想改动被锁的项，那就不能直接改，而要走一次带工单的下发。如果想完全封杀某个改法，可以把某一项设成只读，任何写入都会被拒绝：

```text
lock-config uet.transport-mode ""
```

这条看着像洁癖，其实是这一层唯一的防线。传输层的三个开关彼此耦合，关一个的速度比查一个快得多，靠人自觉是不行的。

## 兼容性安全

UET 默认会按新链路层跑。如果当前这张网里还有一半设备是老 RoCE，或者对面那台交换机根本没实现信用字段的写入，问题就会直接暴露出来：轻则协商失败，重则静默降级成一个谁也没配置过的中间状态。任何一个初级工程师做一次逐台比对，就能把网络分成三六九等。

链路一旦可以被这样切分，域内的「无损」就彻底丧失了意义。所以运维人员务必在配置里显式指定哪些端口属于 UEC 域，避免这样的惨剧发生：

```text
uet-domain member eth1/1-eth1/32
uet-domain peer-version 1.0
```

更进一步，还可以增加准入限制，对端必须协商出同一个版本与同一套能力位才允许进域，这样即使某个端口暴露在外面，老设备也无法在域内发出任何一个包：

```text
uet-domain require-capability credit,selective-nack
```

版本控制也会影响到跨域流量，对端必须在配置文件里声明自己支持的版本才可以参与转发：

```text
uet-peer enterprise-version 1.0
```

这一条最容易被跳过，因为「同一批采购」会让人以为版本天然一致，而实际上固件小版本之间就可能差一个字段。

## 报文安全

开发者必须禁止让用户输入的内容去决定报文的语义。UEC 允许端点自定义：可以 trim 掉载荷只送元数据，可以让软件接管可靠传输，可以按事务指定不同的重组策略。这些灵活性一旦被外部输入打开，就可能会被利用以构造让重组窗口耗尽的报文，把整台网卡拖垮。

同时，我们应该让域内只接受注册过的端点身份，这样即使存在恶意端点也无法把流量打进来。身份绑定在端口上，不绑定在地址上，地址可以伪造，端口不行。

## 跨域互联

UEC 域内是一套新的链路层，意味着域内的报文不应该直接暴露到域外传输，否则会有被误解析、被丢弃、被当成异常流量的风险。如果必须要跨域，可以考虑在边界上放一台做语义转换的网关。

网关的选择不多。一是专用适配设备，功能单一，代价是贵；二是白盒加自研转码，灵活但要把两套语义都吃透。下面是网关做两次转换的思路（因为域内的字段域外一个都不认，得整段重写）：

```text
域内 UET 报文 → 网关剥掉信用与事务字段 → 还原成标准以太网帧 → 域外按普通流量转发
域外回包    → 网关补上信用与事务字段 → 重新进域
```

同样这套网关也可以用在跨机房互联上，如果两个域之间需要复制 checkpoint 或者传递训练数据，它也能派上用场。

## 换成 UET 之后的四件事

规范好看，落地要过四关，每一关都有一句坑。

**芯片代次**是最硬的一条。传输层要网卡与交换机芯片同时实现，查一下网卡能力：

```bash
$ mlxconfig -d /dev/mst/mt4129_pciconf0 q | grep -i -E 'uet|transport'
```

空结果就是没有。别指望软件升级补上，协议字段要芯片在转发路径上写，固件改不了。坑在**网卡与交换机的到位时间通常差一代**，集群里会出现「卡支持、交换机不支持」的半年窗口，那半年只能按老办法跑。

**互操作**决定它是「新孤岛」还是「可演进」。孤岛化的成本不会写在规范里：一条带外管理网、一套独立的采集链路、一批只为它存在的工具，这些都要单独付钱。

**丢包语义**最容易读反。UEC 网络不要求无损，偶发丢包是设计允许的背景值，兜底有三层：端点级信用反压把绝大多数拥塞挡在发生之前；链路级重传把误码导致的丢包在本地补回；选择性确认加单包精准重传，几十微秒内闭环，不回退整段窗口。同样的 1e-6，在 RoCE 里是事故级信号，在这里是背景值，两套环境的值班手册不能通用。

**工具链**要慢慢收敛。规范文档齐了，抓包解析、指标命名、厂商私有扩展还要时间。厂商会用私有 path 先落地，同一个「信用授予延迟」，三家三种叫法，跟第 11 讲那个模型映射层是同一件事，早做晚做都要做。

## 口径要跟着换

机制变了，指标跟着变。反压这一格从「PFC pause 收发帧数、持续时长」换成「信用授予延迟、配额耗尽等待时长」，判读逻辑从看链路反压改为看端侧配额；拥塞这一格从「ECN 标记数、CNP 包数」换成「报文头部拥塞戳、单包 RTT 漂移」，从粗粒度打标比例改为时延量；异常恢复这一格从「重传计数、网卡乱序丢弃」换成「Selective NACK 数、事务重组耗时」，从窗口回退收敛到单包修复；拓扑利用这一格从「ECMP 上行方差、极化系数」换成「逐包喷洒均衡度、多径时延分位数」，从防极化改为追求打满。

坑在这里：**告警是挂在旧指标上的**。查一遍现有的告警规则，有多少条写在 PFC pause 上，就知道迁移的改造量有多大。

## 小结

本节讲解了最基本的 UEC 防护思路，下一讲我们用一个完整的排障案例，把这些东西串到一起看。

配置安全是锁住三个耦合的开关，兼容性安全是显式划域加版本准入，报文安全是不让外部输入决定语义，跨域互联是靠网关做整段重写。四关里前三关的钱不由你决定，第四关今天就能动。

::: tip 本课要点

**UEC 不打补丁，换一层传输层。**

- 四个死穴同源：**PFC 扩散、DCQCN 滞后、GBN 惩罚、QP 爆炸**，都假设网络必须有序不丢逐跳反压
- UET 三改：**端到端信用反压替代逐跳 PFC、原生允许乱序、交换机侧注入拥塞信息单 RTT 收敛**
- 「消灭 PFC」的准确说法：**网络可以不依赖 PFC 工作**。丢包靠链路重传加选择性确认兜底
- 指标迁移：从 PFC pause 与 ECN 打标率，转向**信用授予延迟、单包 RTT、重组耗时**
- 四关：**芯片代次、互操作、丢包语义、工具链**，存量集群不会平滑升级

:::

## 习题

::: tip 怎么做题

先自己写答案，三行也算，再展开对照，最后按「评分维度」逐条自评。

:::

**必答 Q1**：为什么说 UEC 的核心使命是消灭 PFC？消灭 PFC 之后丢包了怎么办？

::: details 参考答案与评分维度

消灭 PFC 的理由：PFC 是逐跳反压，必然引发队头阻塞、拥塞扩散与死锁，是无损以太网脆弱性的根源，而且它是补丁性质的设计，只能靠 watchdog 兜底。

消灭后的流控：UEC 采用端到端信用机制，接收端向发送端授予配额，没有配额禁止发送，交换机队列不会涨满。

丢包处理三层：端点信反压把拥塞挡在发生前；链路级重传处理误码丢包；选择性确认加单包精准重传，几十微秒闭环，不回退整段窗口。

**评分维度**：答出 PFC 的固有缺陷（必需）。阐述信用反压与精准重传两重防护（必需）。提到不要求无损这个观念差别（加分）。

:::

**必答 Q2**：对比 InfiniBand、RoCEv2、UEC 三代在拥塞反馈速度上的机制差异。

::: details 参考答案与评分维度

InfiniBand：专属硬件信用流控，链路级逐跳闭环，响应快，代价是生态封闭。

RoCEv2：靠 ECN 标记与反向 CNP，报文到达终点后掉头通知，至少要几个 RTT 才降速，突发面前滞后。

UEC：交换机在转发报文头部注入时延与队列信息，接收端在回包里带回拥塞程度，源端单 RTT 内收敛，不必等独立控制包绕一圈。

**评分维度**：完整列举三代机制（必需）。准确分析 CNP 滞后与 UEC 快速反馈的差异（必需）。

:::

**自测 Q3**：UEC 网络不要求无损，那「丢包率」这个指标是不是重新变得重要了？

::: details 参考答案与评分维度

重要，但含义变了。RoCE 网络里丢包意味着机制失效，是事故级信号；UEC 网络里偶发丢包是设计允许的，指标的意义从「有没有丢」变成「重传代价有多大」。

所以看三样：选择性 NACK 的频率、单包重传的往返时延、事务重组耗时。丢包数本身只作为背景值，判断严重度看它对事务完成时间的影响。

**评分维度**：指出丢包语义变化（必需）。给出替代指标（必需）。把判断落在事务完成时间上（加分）。

:::

留一个思考题：如果 UEC 真的让 PFC 退场，值班工程师的日常巡检重心会往哪里挪。
