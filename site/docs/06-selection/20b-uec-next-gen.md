前面几讲把 RoCEv2 的坑踩了一遍：PFC 的风暴与死锁、DCQCN 的滞后、Go-Back-N 的重传代价、QPS 与 QP 数量对上万卡的压迫。

这几个问题互相纠缠。防丢包上 PFC，引来风暴；防极化上逐包喷洒，打爆网卡重组。每修一处都要在别处加补丁，补丁又要调参，参数之间还互相影响。

超以太网联盟（Ultra Ethernet Consortium，UEC）的判断是：不再修补，换一层传输层。

先看一眼 RoCEv2 的封装，它是理解后续所有取舍的起点：

```bash
# RoCEv2 走 UDP，目的端口固定 4791，头部只有端口号与校验
# 现代拥塞控制需要的时延、队列、信用信息，一个字节都没有
tcpdump -i any -nn 'udp port 4791' -c 3 -xx
```

## 交付

- RoCEv2 的四个结构性缺陷，各自为什么打补丁也压不平
- UET 用信用反压替代逐跳 PFC 的具体机制，以及取代 PFC 之后丢包怎么办
- 原生乱序与单包精准重传怎么把 Go-Back-N 的代价降到窗口外
- 对比 IB、RoCEv2、UEC 三代在拥塞反馈速度上的差异
- 可观测口径的迁移：PFC pause 退场之后看什么

## 四个死穴

| 固有缺陷 | 根本原因 | 生产后果 | 现有补丁与代价 |
|---|---|---|---|
| PFC 拥塞扩散 | 逐跳反压整个队列 | 队头阻塞、风暴、死锁 | PFC watchdog，允许丢一点换活性 |
| DCQCN 反应过缓 | 由对端经多跳回 CNP | 数个 RTT 才降速，参数震荡 | 精细微调几十个参数，全靠经验 |
| Go-Back-N 惩罚重 | 假设报文严格按序到达 | 单包丢失引发整段窗口重传 | 网卡片上乱序重组，硬件成本高 |
| 连接状态爆炸 | 每对 GPU 之间维护 QP | 万卡集群网卡 QP 上下文耗尽 | 动态建连，引入建连延迟 |

四条都出在同一个假设上：网络必须有序、必须不丢、必须逐跳反压。以太网这套假设是给通用流量设计的，AI 训练流量的形态（同步、突发、大象流、成对通信）跟它对不上，补丁只能绕着假设打。

## UET 换了三件事

UEC 不动物理层电信号，也不动标准光模块。它改的是传输层，也就是 UET（Ultra Ethernet Transport）。

**第一，端到端信用反压取代逐跳 PFC。** 发送端发包前必须持有对端授予的信用额度，额度用完自动停发，交换机队列根本涨不起来，也就没有 PFC 需要触发。

这和 InfiniBand 的信用流控在思路上同源：把反压放在端点之间，不是放在每一跳。区别在 IB 靠专用硬件，UET 在标准以太网上用协议字段实现。

**第二，原生允许乱序。** UET 从一开始就假设网络会做多径喷洒、报文会乱序到达。每个包带绝对偏移量与事务 ID，网卡流水线里直接重组，不需要把乱序当成异常处理。

这条改动同时解掉了 Go-Back-N 的代价：丢一个包，重传一个包，不必回退整段窗口。

**第三，高频拥塞反馈。** 交换机在数据包头写入时延与队列深度信息，接收端在回包里直接带回拥塞程度，源端在单个 RTT 内完成调速，不必等 CNP 一路走回发送端。

## 丢包怎么办

UEC 网络不要求无损，这是与 RoCE 最大的观念差别。既然不要求无损，丢包就得有兜底，兜底方案有三层。

端点级信反压，把绝大多数拥塞挡在发生之前，交换机队列不会因为过载而溢出。

链路级重传，个别误码导致的丢包在本地链路补回，不进端到端事务。

选择性确认与精准重传，对端只请求缺失的报文，源端只补那几个包，几十微秒内闭环，不影响同事务的其他报文。

所以「UEC 消灭 PFC」的准确说法是：**UEC 让网络可以不依赖 PFC 正常工作**。PFC 从必需机制退成可选的兼容手段。

## 可观测口径要跟着换

机制变了，指标跟着变。这张表是判断新设备上报什么字段的依据：

| 观测维度 | RoCEv2 现行指标 | UEC 指标 | 判读逻辑变化 |
|---|---|---|---|
| 反压 | PFC pause 收发帧数、持续时长 | 信用授予延迟、配额耗尽等待时长 | 从看链路反压改为看端侧配额 |
| 拥塞 | ECN 标记数、CNP 包数 | 报文头部拥塞戳、单包 RTT 漂移 | 从粗粒度打标比例改为时延量 |
| 异常恢复 | 重传计数、网卡乱序丢弃 | Selective NACK 数、事务重组耗时 | 从窗口回退收敛到单包修复 |
| 拓扑利用 | ECMP 上行方差、极化系数 | 逐包喷洒均衡度、多径时延分位数 | 从防极化改为追求打满 |

对这门课的影响很直接：13 讲那套「健康判据从丢没丢换成纠错压力」的思路继续有效，只是压力源从 FEC 换成信用配额与重组延迟。

## 现实约束

UEC 是联盟标准，落地要看三件事，跟技术优劣无关。

芯片与整机支持。传输层要网卡与交换机芯片同时实现，一代硬件换一次，存量集群不可能平滑升级。

与现有生态的互操作。UET 报文能不能穿过现有 IP 网络、能不能与普通以太网流量共存，决定了它是「新孤岛」还是「可演进」。

标准成熟度与工具链。规范文档齐了，抓包解析、指标命名、厂商私有扩展的收敛还要时间。

所以今天做选型和监控规划，仍然按 RoCEv2 的口径建指标体系。UEC 的字段先在设计里留位置，别把架构写死在「PFC 计数是核心指标」上。

## 经验映射

| 你熟悉的机制 | 对应到 UEC |
|---|---|
| HTTP/2 的流级流量控制 | UET 端到端信用控制 |
| 异步消息的选择性确认与精准重传 | UET 的 Selective NACK |
| RPC 框架里的自适应限流 | 交换芯片注入的高频拥塞度量 |
| 单连接多路复用 | 逐包喷洒的传输通道 |

一句话概括这次迁移：把 PFC、ECN、DCQCN 的调参经验，换成分布式传输里的配额、确认、重组语义。后者对后端工程师更熟，对网络工程师是新的。

## 判读与实操

判断一个环境离 UEC 还有多远，看四个信号：

| 问题 | 说明什么 |
|---|---|
| 网卡是否支持 UET 或厂商对应的 AI 传输层？ | 硬件代次，最硬的限制 |
| 交换机是否支持信用反压的协议字段写入？ | 交换机侧要求，比网卡更晚到位 |
| 现有监控是否已经采集重组延迟与单包 RTT？ | 口径准备程度，这条可以先做 |
| 现有告警有多少条挂在 PFC pause 上？ | 迁移成本，挂在 PFC 上的越多，改造越大 |

第三、四条今天就能推进。机制换代的窗口期里，先能变现的是口径：把指标体系从「PFC 中心」改成「配额、时延、重组」三者并列，换硬件排在后面。

## 习题

::: tip 怎么做题

先自己写答案，三行也算，再展开对照，最后按「评分维度」逐条自评。

:::

**必答 Q1**：为什么说 UEC 的核心使命是消灭 PFC？消灭 PFC 之后丢包了怎么办？

::: details 参考答案与评分维度

消灭 PFC 的理由：PFC 是逐跳反压，必然引发队头阻塞、拥塞扩散与死锁，是无损以太网脆弱性的根源，而且它是补丁性质的设计，只能靠 watchdog 兜底。

消灭后的流控：UEC 采用端到端信用机制，接收端向发送端授予配额，没有配额禁止发送，交换机队列不会涨满。

丢包处理三层：端点信反压把拥塞挡在发生前；链路级重传处理误码丢包；选择性确认加单包精准重传，几十微秒闭环，不回退整段窗口。

**评分维度**：答出 PFC 的固有缺陷（必需）。阐述信用反压与精准重传两重防护（必需）。提到不要求无损这个观念差别（加分）。

:::

**必答 Q2**：对比 InfiniBand、RoCEv2、UEC 三代在拥塞反馈速度上的机制差异。

::: details 参考答案与评分维度

InfiniBand：专属硬件信用流控，链路级逐跳闭环，响应快，代价是生态封闭。

RoCEv2：靠 ECN 标记与反向 CNP，报文到达终点后掉头通知，至少要几个 RTT 才降速，突发面前滞后。

UEC：交换机在转发报文头部注入时延与队列信息，接收端在回包里带回拥塞程度，源端单 RTT 内收敛，不必等独立控制包绕一圈。

**评分维度**：完整列举三代机制（必需）。准确分析 CNP 滞后与 UEC 快速反馈的差异（必需）。

:::

**自测 Q3**：UEC 网络不要求无损，那「丢包率」这个指标是不是重新变得重要了？

::: details 参考答案与评分维度

重要，但含义变了。RoCE 网络里丢包意味着机制失效，是事故级信号；UEC 网络里偶发丢包是设计允许的，指标的意义从「有没有丢」变成「重传代价有多大」。

所以看三样：选择性 NACK 的频率、单包重传的往返时延、事务重组耗时。丢包数本身只作为背景值，判断严重度看它对事务完成时间的影响。

**评分维度**：指出丢包语义变化（必需）。给出替代指标（必需）。把判断落在事务完成时间上（加分）。

:::

**思考题（不给参考答案）**：在 UEC 完全落地之前，某团队想关掉 PFC 只靠 DCQCN 在 RoCEv2 上跑 AllReduce。要让任务不崩，需要满足什么条件？

## 小结

RoCEv2 的四个死穴——PFC 扩散、DCQCN 滞后、GBN 惩罚、QP 爆炸——都出在同一个假设上：网络必须有序、不丢、逐跳反压。补丁只能绕着假设打，越打越多。

UET 换了三件事：端到端信用反压取代逐跳 PFC，原生允许乱序并把重传收敛到单包，拥塞信息随报文走、单 RTT 内调速。

「消灭 PFC」的准确说法是让网络可以不依赖 PFC 工作。丢包有链路级重传与选择性确认兜底，偶发丢包从事故级信号降为背景值。

机制换代，指标跟着换。先动口径，把 PFC 中心换成配额、时延、重组三者并列；再动硬件。

::: tip 本课要点

**UEC 的答案不是打补丁，是换一层传输层。**

- 四个死穴同源：**PFC 扩散、DCQCN 滞后、GBN 惩罚、QP 爆炸**，都假设网络必须有序不丢逐跳反压
- UET 三改：**端到端信用反压替代逐跳 PFC、原生允许乱序、交换机侧注入拥塞信息单 RTT 收敛**
- 「消灭 PFC」的准确说法：**网络可以不依赖 PFC 工作**。丢包靠链路重传加选择性确认兜底
- 指标迁移：从 PFC pause 与 ECN 打标率，转向**信用授予延迟、单包 RTT、重组耗时**
- 现实约束：**网卡与交换机芯片同时换代、与现有 IP 网络互操作、工具链收敛**，存量集群不会平滑升级

:::

留一个思考题：如果 UEC 真的让 PFC 退场，值班工程师的日常巡检重心会往哪里挪。
