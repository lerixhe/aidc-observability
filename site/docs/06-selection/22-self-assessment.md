课程讲完，最后这一讲给三样可以反复用的东西：自评矩阵、盲区清单、下一步路线。它每隔一两个月要过一遍，分数会掉。

## 交付

- 用自评矩阵在十二个维度上打分，找出真实薄弱点，而不是「感觉懂了」

## 三道综合题

真实问题从不按章节出题。下面三组各挑一题，把答案写下来再展开对照。

**综合题 A（第二篇 + 第四篇）**：某训练任务反馈「所有上报指标都正常，但任务就是慢」。列出几个你怀疑是假象的「正常」，并说明各自怎么证实。

::: details 参考答案与评分维度

「正常」的假象通常来自三处。

丢包率为 0。无损网络里最常见的故障（PFC 反压、微突发）本来就不丢包，正常值不代表健康。

带宽利用率正常。ECN / DCQCN 降速会让发送速率下降，利用率「平稳」可能正是被压制的表现。

端口 CRC 正常。看的是有没有告警而不是趋势。光模块劣化阶段 CRC 在涨但远低于阈值，单 lane 劣化甚至只降一份带宽。

证实手段四路：端口级 CRC 与 FEC 趋势、ECN 标记率趋势、路径时延 P99、单 lane 光功率与 lane 级计数。四路都要与训练步节奏做时间对齐。

**评分维度**：指出两个以上「假正常」（必需）。给出「趋势对阈值、分位数对均值」的方法论差别（必需）。补出与任务元数据对齐（加分）。

:::

**综合题 B（第四篇 + 第五篇）**：给一台 GPU 服务器和它的 8 条 rail 设计一套采集方案。采什么、什么频率、怎么存储、需不需要额外数据。

::: details 参考答案与评分维度

采什么：按 rail（网卡）分区采集。队列水线、PFC pause（按优先级）、ECN 标记、端口 CRC 与 FEC、丢包计数、DOM（光功率与温度），外加主机侧 GPU-NIC 亲和关系（`nvidia-smi topo -m`）。

频率：核心故障指标 1–5 秒 `sample`。端口流量类 10–30 秒。端口 up/down 与邻居用 `on_change`。DOM 30–60 秒。

存储：降采样时同时保留 avg 与 max，峰值不能丢。分层保留：原始精度 7 天、1 分钟聚合 3 个月、1 小时聚合 1 年。

额外数据：拓扑（LLDP/BGP 自动发现）、任务元数据（哪个任务在用这条 rail）、时钟源（NTP/PTP）。

**评分维度**：按 rail 组织的意识（必需）。峰值保留（必需）。拓扑与任务元数据关联（必需）。分级频率的理由（加分）。

:::

**综合题 C（第五篇 + 第六篇）**：把「一条 rail 劣化导致某任务变慢」建成一条自动处置链路，写明每步的自动化程度与理由。

::: details 参考答案与评分维度

1. 发现（全自动）。路径级探测加遥测阈值，秒级产出「某 rail 的若干路径劣化」。
2. 收敛（全自动）。同源告警折叠成一个 incident，下游告警标为派生。
3. 定位（全自动给候选）。路径集合与拓扑求交得到候选端口，查 CRC/FEC/DOM 排序，输出 Top-3 候选与证据链。
4. 摘要（全自动）。生成 incident 摘要与建议动作，推给值班。
5. 处置（分级）。低危可逆动作（临时降载、标记隔离观察）自动执行并验证；不可逆动作（换件、切换主干路径）人工审批。
6. 回滚与熔断（全自动）。执行后验证指标，不达预期回滚；全局熔断开关随时可回人工。

判断标准三个：可逆性、误判代价、置信度。

**评分维度**：六步齐全（必需）。分级理由能落到可逆性与代价（必需）。提到「候选加证据链」而非直接结论（加分）。

:::

## 八个盲区

1. **把「无损」理解成「绝对不丢」。** 工程上它是概率承诺，watchdog 就是主动选择丢一点来避免永久死锁。
2. **以为丢包率是最重要的指标。** 无损网络里它是最底层的关注点，日常要看 ECN 与 pause。
3. **把 PFC 当成端到端机制。** 它是逐跳的，所以才有「症状现场与根因现场分离」。
4. **只看均值与阈值。** 微突发与渐进劣化都活在分位数与趋势里。
5. **以为遥测只是「换个协议采集」。** 真正的难点是分级订阅、峰值保留、时钟对齐、模型映射。
6. **以为拓扑是排障时才查的资料。** 它必须是数据模型里的一等维度，否则无法做关联。
7. **以为 AIOps 的难点是算法。** 难点是数据质量与告警收敛。
8. **以为 LLM 能替代计算与执行。** 它负责理解与编排，计算与执行交给确定性系统。

## 要点卡

能查到位置，但看它本身不等于懂。

::: tip 全课程要点（速查）

- **02 四大差异**：大象流加 incast；丢包从背景噪声变事故信号；故障代价等于 checkpoint 回退；SNMP 分钟级变 gNMI 秒级
- **03 RDMA**：内核三笔代价（尾延迟、CPU、拷贝）→ 三大能力（旁路、零拷贝、卸载）→ **因果链：同步训练 → RDMA → 必须无损 → PFC/ECN**
- **04 RoCEv2**：v1 不路由，v2 套 UDP/IP（4791）。L2 优先级给 PFC，IP 头 ECN 给降速，UDP 只是外壳，可靠性在网卡
- **05 PFC**：XOFF 水线 → pause 帧 → 上游冻结 → XON。**按优先级、逐跳、接收方驱动**。副作用是队头阻塞与拥塞上游化
- **06 ECN + DCQCN**：Kmin 到 Kmax 打 CE → CNP → 源端降速。指标分级 **ECN 领先、PFC 滞后、丢包事故**
- **07 四大故障**：风暴等于区域性时延膨胀；死锁是**断崖超时加丢包率 0**；incast 是周期性尖刺；队头阻塞让无辜路径受累
- **08 NCCL**：每步 AllReduce。Ring 带宽最优（约 2 倍梯度量）。**流量矩阵已知，可做预期与实际比对**
- **09 拓扑**：Clos 1:1 无收拢。8 卡 8 网卡 8 条 **Rail**。双 ToR 加双平面，降速好过回退
- **11 gNMI**：`Subscribe` 三种取数方式（sample、on_change、poll），OpenConfig YANG 树，**分级订阅加时钟对齐**
- **12 INT**：报文自带逐跳记录，**队列与利用率的组合定归因**，1:4096 采样下微突发约一半概率抓不到
- **13 光模块**：十几万个、唯一模拟件 → 每天都有坏的。**路径发现 → CRC/FEC 定位 → DOM 确因**
- **14 管道**：五段链路五个丢点，**降采样必须保留 max**，不是每档都留得起
- **15 指标口径**：PFC 看**帧数、时长、范围**三个口径；**分位数不能跨实例平均**
- **16 AIOps**：四层 **数据 → 收敛 → RCA → 处置** 不可跳。图 RCA 等于告警的共同上游祖先
- **17 时序存储**：**基数才是杀手**。口径三问：降采样、峰值、乱序。实时与离线双链路
- **18 LLM**：**理解编排给模型，计算执行给传统系统**。三级落地，四条护栏
- **19 MTTR**：四段之和，定位占一半。**可逆且局部可自动，不可逆必须人确认**
- **20 IB vs RoCE**：IB 免调优但封闭。**RoCE 把复杂度交给平台**，这正是平台能力的价值所在

:::

## 经验映射

填表是对自己经验的一次盘点。左边照实写，右边用本课程的概念填，写不出来的就是缺口。

| 你已有的能力 | 智算场景的对应物 | 可直接复用 | 需补齐 | 自评信心（低/中/高） |
|---|---|---|---|---|
| 链路级主动探测（路径覆盖、ECMP） | 智算网络的路径级观测 | 引擎架构、路径枚举、防极化、频率权衡 | 目标发现按 rail 分层；口径纳入 CRC/FEC/ECN | |
| 时序数据管道（消息队列 → 流处理 → 时序库） | 遥测数据平台（实时链路） | 管道架构、聚合、告警链路 | 数据源扩展到 gNMI 订阅；分级订阅；时钟对齐 | |
| 设备管控（SNMP / Netconf / YANG / gNMI） | 设备遥测与配置一致性 | 模型理解、批量操作 | 订阅式推模型、Capabilities 探测、模型映射层 | |
| 告警体系与值班流程 | AIOps 的收敛与处置层 | 规则、静默、升级路径 | 拓扑归并、RCA、自动化编排与回滚 | |
| 容量与成本管理 | 遥测存储与保留策略 | 成本模型、预算意识 | 基数估算、分层保留、峰值保留 | |
| 文档与复盘 | RAG 知识库（LLM 落地的 L2） | 复盘方法、结构化写作 | 版本管理、可检索化改造 | |

填表时守一条规则：**右边写不出具体概念的空格，就是真正的缺口。**

比「懂网络」更有用的表述是「能把已有能力里的 X 平移到 Y 位置，缺的是 Z」。这句话既能指导学习，也能在评审场合准确表达自己的位置。

## 课程之后做什么

| 路径 | 做什么 | 为什么 |
|---|---|---|
| 动手实验 | 跑通 L1 那批实验（无特权，只需 Go）：参数化的 PFC 与 ECN 时序模型、可订阅的 gNMI mock、本地落盘的管道 | 概念跑过一遍才扎实，实验里的异常时序与真实网络同构 |
| 真实数据 | 在自己的环境里把路径级、设备级、任务级三路数据关联一次 | 关联是最难的一步，也是最值钱的一步 |
| 持续输入 | 跟进 PFC、ECN、UEC 相关的公开论文与厂商文档，关注队列水线、可编程遥测 | 这条技术线还在快速演进 |
| 输出 | 写一份自己的排障手册或复盘文档 | 能写成文档的知识才算真懂，同时也是未来 RAG 的原料 |

复习节奏：

- **每周**抽一个故障指纹（风暴、死锁、incast、队头阻塞），用现有数据找一次真实或近似案例。
- **每月**重看自评矩阵，把分数变化记下来。分数没变，通常说明这段时间没动手。
- **每季度**更新能力迁移表，检查「需补齐」那一栏有没有真的减少。

## 习题

::: tip 怎么做题

先自己写答案，三行也算，再展开对照，最后按「评分维度」逐条自评。

:::

**必答 Q1**：给自评矩阵的十二个维度打分，对最低的两个各写三句话：这个概念是什么、为什么没掌握、打算怎么补。

::: details 参考答案与评分维度

没有标准答案，按四条自评：

- 分数基于「合上讲一遍」的真实检验，而不是印象（必需）
- 对薄弱点的成因分析具体，是没跑过实验，还是没算过数量级（必需）
- 补救计划可执行，有具体动作与时间（必需）
- 把「看不懂的术语」与「没想通的因果」分开（加分）

:::

**必答 Q2**：填完能力迁移表，挑「需补齐」里性价比最高的一项，说明为什么先补它。

::: details 参考答案与评分维度

性价比用三个问题判断。卡点程度：不补它，现有能力落不了地，比如没有设备遥测，路径级探测永远停在「劣化了」。复用广度：补完能复用到几个场景，gNMI 订阅可同时用于队列、光模块、配置一致性。学习成本：有没有可跑的实验与公开文档。

通常优先级最高的是「设备侧遥测采集加模型映射」，它是路径级能力变现的必经环节。

**评分维度**：表格填写具体（必需）。优先级判断有三个理由支撑（必需）。能说出「不补的后果」（加分）。

:::

**自测 Q3**：八个盲区里，哪一个最容易被你自己忽略？为什么？

::: details 参考答案与评分维度

开放题。最常见也最容易被忽略的是「只看均值与阈值」：它不报错，不影响日常判断，只在慢故障与微突发复盘时暴露，而阈值思维在传统监控体系里根深蒂固。

是否掌握的标准：能不能说出分位数看什么、峰值怎么保留、趋势怎么建模的具体做法。

**评分维度**：盲区选择有理由（必需）。给出可操作的替代做法（必需）。

:::

**自测 Q4**：如果只允许你带走本课程的一句话，你选哪句？说明理由。

::: details 参考答案与评分维度

没有标准答案，判断标准是这句话能否同时解释机制与行为，而不只是一个结论。好的答案通常是因果链形式：「同步训练要求微秒级稳定时延，所以选了 RDMA，所以必须无损，所以 PFC 与 ECN 成为一等指标」，一条链解释全部后续设计。

**评分维度**：句子结构是因果链而非口号（必需）。能说明它如何指导实际判断（必需）。

:::

## 小结

自评矩阵有十二个维度，打分不能凭感觉，要合上页面把那一讲的核心结论讲一遍。讲不出来是一分，讲得出但说不出为什么是两分，能举例、能给数字、能说边界才是三分。

八个盲区看着分散，根子是同一个：把静态指标当成动态过程，把局部现象当成全局结论。丢包为零、利用率平稳、CRC 正常，这三个「正常」在无损网络里都不算证据。

能力迁移表的用处是暴露空格。右边写不出对应概念的地方就是真正的缺口，填完会得到一句比「懂网络」有用得多的话：能把已有的 X 平移到 Y，缺的是 Z。

::: tip 本课要点

**合上讲一遍，讲得出来才算懂。**

- 自评要**合上讲一遍**再打分，凭印象的分数没有意义
- 十二个维度里低于 2 分的，回去重读机制段，不要背要点卡
- 八个盲区同根：**把静态指标当动态过程，把局部当全局**
- 能力迁移表的价值是暴露空格：**写不出对应概念的地方就是真缺口**
- 课程之后三条路：**动手实验 → 真实数据三路关联一次 → 持续输入与输出**
- 分数长期不变，说明这段时间没动手

:::
