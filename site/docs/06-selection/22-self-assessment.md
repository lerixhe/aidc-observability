智算网络涉及的知识点是非常繁多的，虽然本课程已经疯狂扩充了不少进阶和压箱底的内容，但本课程依然无法顾及到它的方方面面，对于那些渴望进一步拓展知识的同学，在这里做一些精品学习资源推荐，顺便给一张自评表，看看自己走到了哪一步。

先说句实话。这二十六讲装不完智算网络，有几块明显没讲透：拥塞控制的端侧算法只讲了一个 DCQCN，TIMELY 与 HPCC 一句没提；集合通信与 NCCL 的调优细节只开了个头；多租户隔离与存储网络基本没碰；还有一层场内的东西也没进来，比如交换机芯片的流水线到底怎么排队、怎么裁剪元数据。这些不是不重要，是一本书的篇幅装不下。

## 自评矩阵

合上讲义，把某一讲的核心结论讲一遍，讲得出来才算懂。翻着书对答案不算。

每个维度给自己 0 到 3 分：0 是没概念，1 是能认出来，2 是能讲清并解释因果，3 是能用于判断与决策，含量化与边界。题面就是每一讲的因果链。

| 维度 | 自评问题 | 对应课 | 分数 |

| 范式差异 | 能完整讲出「同步训练 → 微秒级稳定 → RDMA → 必须无损 → PFC/ECN」的因果链吗？ | 02–04 | |
| 无损机制 | 能说清 PFC 与 ECN/DCQCN 的分工，并解释健康网络里 PFC 为什么应该罕见吗？ | 05–06 | |

打分方式不能凭感觉。合上页面，把那一讲的核心结论口头讲一遍，或者写三行，再对照该讲的「本课要点」。讲不出来是 1 分，讲得出但说不出为什么是 2 分，能举例、能给数字、能说边界才是 3 分。

低于 2 分的维度，回去重读那一讲的机制段，不要背要点卡。要点卡能查到位置，看它本身不会让你懂。

## 八个盲区

1. **把「无损」理解成「绝对不丢」。** 工程上它是概率承诺，watchdog 就是主动选择丢一点来避免永久死锁。
2. **以为丢包率是最重要的指标。** 无损网络里它是最底层的关注点，日常要看 ECN 与 pause。
3. **把 PFC 当成端到端机制。** 它是逐跳的，所以才有「症状现场与根因现场分离」。
4. **只看均值与阈值。** 微突发与渐进劣化都活在分位数与趋势里。
5. **以为遥测只是「换个协议采集」。** 真正的难点是分级订阅、峰值保留、时钟对齐、模型映射。
6. **以为拓扑是排障时才查的资料。** 它必须是数据模型里的一等维度，否则无法做关联。
7. **以为 AIOps 的难点是算法。** 难点是数据质量与告警收敛。
8. **以为 LLM 能替代计算与执行。** 它负责理解与编排，计算与执行交给确定性系统。

这八条看着分散，根子是同一个：把静态指标当成动态过程，把局部现象当成全局结论。丢包为零、利用率平稳、CRC 正常，这三个「正常」在无损网络里都不算证据。

## 能力迁移表

填表是对自己经验的一次盘点。左边照实写，右边用本课程的概念填，写不出来的就是缺口。

| 你已有的能力 | 智算场景的对应物 | 可直接复用 | 需补齐 | 自评信心 |
|---|---|---|---|---|
| 链路级主动探测（路径覆盖、ECMP） | 智算网络的路径级观测 | 引擎架构、路径枚举、防极化、频率权衡 | 目标发现按 rail 分层；口径纳入 CRC/FEC/ECN | |
| 时序数据管道（消息队列 → 流处理 → 时序库） | 遥测数据平台（实时链路） | 管道架构、聚合、告警链路 | 数据源扩展到 gNMI 订阅；分级订阅；时钟对齐 | |
| 设备管控（SNMP / Netconf / YANG / gNMI） | 设备遥测与配置一致性 | 模型理解、批量操作 | 订阅式推模型、Capabilities 探测、模型映射层 | |
| 告警体系与值班流程 | AIOps 的收敛与处置层 | 规则、静默、升级路径 | 拓扑归并、RCA、自动化编排与回滚 | |
| 容量与成本管理 | 遥测存储与保留策略 | 成本模型、预算意识 | 基数估算、分层保留、峰值保留 | |
| 文档与复盘 | RAG 知识库（LLM 落地的 L2） | 复盘方法、结构化写作 | 版本管理、可检索化改造 | |

填表时守一条规则：**右边写不出具体概念的空格，就是真正的缺口。**

比「懂网络」更有用的表述是「能把已有能力里的 X 平移到 Y 位置，缺的是 Z」。这句话既能指导学习，也能在评审场合准确表达自己的位置。

## 参考资料

### 1. Guo 等《RDMA over Commodity Ethernet at Scale》（SIGCOMM 2016）

如果你只读一篇，读这篇。它讲的是把 RoCE 真正跑在生产上之后撞到了什么：PFC 风暴、ECN 参数、队头阻塞，都是现场描出来的，不是仿真。这门课第 05 到 07 讲大半的原始材料在这里。把这篇吃透，你会明显感觉到功力大增，以后遇到无损网络的问题，总会想从这篇里找答案。

### 2. 官方规范与公开模型

我要隆重推荐下面这几处，在这里你可以获取权威资料和最新信息。

#### [IBTA 规范](https://www.infinibandta.org/ibta-specification/)

IB 的信用流控、SHARP 在网计算、RoCEv2 的封装，全在这里。规范读起来枯燥，但它是唯一不会被厂商口径带偏的地方。

#### [OpenConfig 公开模型库](https://github.com/openconfig/public)

别从文档目录读起，从你们机房里真实存在的那个指标开始，反着找它的 path，一周就能摸熟。这条路子比通读规范快十倍，因为模型只在你需要它的那一刻才有意义。

#### [NCCL 文档](https://docs.nvidia.com/deeplearning/nccl/user-guide/docs/)

集合通信行为的权威来源，环境变量那一页尤其值得反复看，很多「NCCL 慢」的问题答案就藏在那几十个开关里。

### 3. Qian 等《HPN: A New Approach to Network Design for Large-Scale AI Infrastructure》（SIGCOMM 2024）

前一篇是「怎么把以太网调成能用」，这一篇是八年后的回答：「我们不再调了，改架构」。重点看讲为什么放弃逐跳反压的那两节，它们是第 20 讲附的英文版，比二手转述精确得多。文章中关于传统数据中心的那几节与我们场景关系不大，可以略过。

### 4. 课程配套的实验

要成为这一行的熟手，最高效的路径就是掌握「造轮子」学习法。仓库里那批实验不需要特权，只要 Go：参数化的 PFC 与 ECN 时序模型、可订阅的 gNMI mock、本地落盘的管道、五跳的 INT 路径。概念跑过一遍才扎实，实验里的异常时序与真实网络同构。

```bash
cd labs/03-fault-inject && make run     # 四类故障的判读器
cd labs/07-int-path && make run        # 逐跳时延与采样捕获率
cd labs/09-slo && make run             # 三种口径与错误预算
```

### 5. Cook《How Complex Systems Fail》

十八小节，一个下午能读完。它在不同的项目里值得读三遍，每遍都会停在同一节：事故里没有单一根因。读完以后你写复盘报告的口味会变，不再执着于找到一个「真凶」。

还有一条：想知道交换机侧那些队列、缓冲、水线到底是怎么实现的，SONiC 社区与各家的白盒实践是最便宜的入口。要注意区分宣传口径与可验证机制，白皮书上写的「零丢包」和「零丢包」不是同一个意思。

## 课程之后做什么

动手实验，跑通 L1 那批不需要特权的实验，概念跑过一遍才扎实。真实数据，在自己的环境里把路径级、设备级、任务级三路数据关联一次，关联是最难的一步，也是最值钱的一步。持续输入，跟进 PFC、ECN、UEC 相关的公开论文与厂商文档。输出，写一份自己的排障手册或复盘文档，能写成文档的知识才算真懂。

复习节奏也简单：**每周**抽一个故障指纹（风暴、死锁、incast、队头阻塞），用现有数据找一次真实或近似案例；**每月**重看自评矩阵，把分数变化记下来，分数没变通常说明这段时间没动手；**每季度**更新能力迁移表，检查「需补齐」那一栏有没有真的减少。

## 习题

::: tip 怎么做题

先自己写答案，三行也算，再展开对照，最后按「评分维度」逐条自评。

:::

**必答 Q1**：给自评矩阵的十二个维度打分，对最低的两个各写三句话：这个概念是什么、为什么没掌握、打算怎么补。

::: details 参考答案与评分维度

没有标准答案，按四条自评：

- 分数基于「合上讲一遍」的真实检验，而不是印象（必需）
- 对薄弱点的成因分析具体，是没跑过实验，还是没算过数量级（必需）
- 补救计划可执行，有具体动作与时间（必需）
- 把「看不懂的术语」与「没想通的因果」分开（加分）

:::

**必答 Q2**：填完能力迁移表，挑「需补齐」里性价比最高的一项，说明为什么先补它。

::: details 参考答案与评分维度

性价比用三个问题判断。卡点程度：不补它，现有能力落不了地，比如没有设备遥测，路径级探测永远停在「劣化了」。复用广度：补完能复用到几个场景，gNMI 订阅可同时用于队列、光模块、配置一致性。学习成本：有没有可跑的实验与公开文档。

通常优先级最高的是「设备侧遥测采集加模型映射」，它是路径级能力变现的必经环节。

**评分维度**：表格填写具体（必需）。优先级判断有三个理由支撑（必需）。能说出「不补的后果」（加分）。

:::

**自测 Q3**：八个盲区里，哪一个最容易被你自己忽略？为什么？

::: details 参考答案与评分维度

开放题。最常见也最容易被忽略的是「只看均值与阈值」：它不报错，不影响日常判断，只在慢故障与微突发复盘时暴露，而阈值思维在传统监控体系里根深蒂固。

是否掌握的标准：能不能说出分位数看什么、峰值怎么保留、趋势怎么建模的具体做法。

**评分维度**：盲区选择有理由（必需）。给出可操作的替代做法（必需）。

:::

**自测 Q4**：如果只允许你带走本课程的一句话，你选哪句？说明理由。

::: details 参考答案与评分维度

没有标准答案，判断标准是这句话能否同时解释机制与行为，而不只是一个结论。好的答案通常是因果链形式：「同步训练要求微秒级稳定时延，所以选了 RDMA，所以必须无损，所以 PFC 与 ECN 成为一等指标」，一条链解释全部后续设计。

**评分维度**：句子结构是因果链而非口号（必需）。能说明它如何指导实际判断（必需）。

:::

## 小结

自评矩阵有十二个维度，打分不能凭感觉，要合上页面把那一讲的核心结论讲一遍。讲不出来是一分，讲得出但说不出为什么是两分，能举例、能给数字、能说边界才是三分。

八个盲区看着分散，根子是同一个：把静态指标当成动态过程，把局部现象当成全局结论。

能力迁移表的用处是暴露空格。右边写不出对应概念的地方就是真正的缺口，填完会得到一句比「懂网络」有用得多的话：能把已有的 X 平移到 Y，缺的是 Z。

留一个思考题：如果让你给这门课补一讲，你会补什么，为什么现在这二十六讲装不下它。
