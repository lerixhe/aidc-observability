先给一个你在现场一定会遇到的场景。集群监控全绿，训练任务却从每步 380 毫秒掉到 520 毫秒。

两个小时后有人发现，是一颗光模块的单 lane 在劣化，端口 CRC 只是从 0 涨到 12。

这门课讲的就是这件事：**怎么让那条从"指标正常"到"任务真的慢"之间的黑箱变短。**

## 本节目标

- 判断自己是否属于这门课的目标读者，以及需要提前补齐哪几项前置能力
- 完整复述一遍本课程的核心问题：为什么"指标正常"和"系统健康"在智算网络里是两件事
- 说出六模块的因果顺序，并解释为什么跳读会让后面的判读退化成背书
- 从三种读法里选出适合自己当前处境的那一种，并知道配套实验在哪

## 机制拆解

### 核心问题：正常值在这里不代表健康

传统 IDC 的可观测假设很简单。丢包涨了就是坏，时延涨了就是坏，容量满了就是坏。三个指标加上阈值告警，够用。

智算网络把这套假设推翻了。

训练是同步的。一个 AllReduce 周期里，所有 GPU 要等最慢的那一份数据。**一条链路的微秒级抖动，会变成整个任务的小时级延迟。** 但这条链路上的端口计数器，一分钟聚合之后看起来平滑如常。

这也就是本课程的存在理由：可观测的对象从"平均值"变成了"尾部与瞬时值"，从"端口"变成了"队列 × 优先级 × 路径"。

### 三条断层：IDC 经验在这里哪里失效

断层一，事件时标错位。PFC 风暴、incast 尖刺、微突发的持续时间在微秒到毫秒量级。SNMP 分钟级轮询相当于把显微镜换成望远镜，然后宣布看不到细菌。

断层二，观测粒度错位。你盯着端口的聚合丢包数，真正出事的是 8 个队列里的第 3 个，优先级为 4 的那一条流。计数器不区分这些维度，你就永远看不到它。

断层三，正常值语义错位。无损网络里丢包为 0 是设计使然，不是健康证明。真正的前兆信号是 PFC pause 在悄悄变多、ECN 标记率在爬升、队列水线开始贴顶。这些都是"正常范围"内的数字。

<Aside type="caution" title="三条断层会同时发作">
现场最常见的误判是拿断层三去解释断层一。比如"丢包为 0，说明链路没问题"，这句话在智算网络里几乎必然错。

判断依据要换成趋势与分位数：CRC 的一阶差分、ECN 标记率的斜率、P99 时延的漂移。阈值告警在这三个量上基本沉默。
</Aside>

### 读者前置：会什么可以直接开始

这门课不要求你会调交换机。它要求你具备下面四项中的至少三项。

| 前置能力 | 具体到什么程度 | 缺了怎么办 |
|---|---|---|
| TCP/IP 与以太网基础 | 能读懂 MTU、VLAN、ECMP hash、队列调度这几个词的实际含义 | 先补任意一本网络基础教材的以太网与拥塞控制章节 |
| Linux 与抓包 | 会用 `ip`、`tc`、`ethtool`、`tcpdump`，能看懂一次 netem 注入的效果 | 在容器里练一遍，代价约一天 |
| 指标与时序系统 | 知道 label 基数、聚合窗口、分位数估算的坑 | 读 M5 的时序存储选型课再回头 |
| 一门脚本语言 | Go 或 Python 能跑通一个读 CSV 算统计的脚本 | 实验都可以只读输出，不影响理解 |

反过来，三类读者会被这门课卡住。只想看协议综述的，这里每课都在讲"坏了会看到什么信号"。想要厂商选型结论的，这里只给判断框架。指望读完就会调优参数的，这里讲的是先看见，再谈调优。

### 六模块是一条因果链

六个模块不是并列的知识点，是一条单向推导。

| 模块 | 回答的问题 | 上一步的结论怎么变成下一步的前提 |
|---|---|---|
| M1 范式转换 | 为什么智算网络不能用 IDC 的那套看法 | 同步训练要求微秒级稳定 → 需要 RDMA → RDMA 不能丢包 |
| M2 无损机制 | 不丢包靠什么做到，代价是什么 | PFC 与 ECN 的分工决定了要看哪些计数器 |
| M3 流量与拓扑 | 流量长什么样，路径长什么样 | 流量矩阵已知、拓扑固定，才可能做路径级归因 |
| M4 遥测数据面 | 数据从哪采，采多细 | 有了秒级订阅与路径级元数据，才谈得上判读 |
| M5 分析与自动化 | 指标怎么定口径，告警怎么收敛 | 口径统一、根因可算，才谈得上缩短 MTTR |
| M6 选型与收口 | 路线怎么选，能力怎么自评 | 前五个模块的判据汇总成决策依据 |

跳读的代价很具体。直接从 M4 开始，你会记住"用 gNMI 订阅"，但答不出为什么要秒级、为什么 PFC 计数比丢包计数重要。这部分知识在排障现场用不出来。

<Aside type="note" title="经验映射（IDC → AIDC）">
如果你做过微服务，这套结构并不陌生。IDC 的监控相当于看服务的平均 RT。智算网络要看的是 P99 尾延迟，以及单条 RPC 链路上每一跳各自花了多久。

你已有的能力可以直接迁移：分位数思维、链路追踪、根因收敛。缺的只是设备侧语义，也就是交换机上那些计数器到底在说什么。
</Aside>

## 判读与实操

### 三种读法

按处境选，别按心情选。

| 读法 | 适合谁 | 怎么做 | 代价 |
|---|---|---|---|
| **顺序通读** | 刚接手集群，还没有具体事故要处理 | M1 到 M6 顺着读，每课做完练习题 | 约 15 到 20 小时 |
| **按故障查** | 手上正压着一个具体问题 | 直接从第 7 课的故障指纹表进入，遇到不熟的机制再回跳 | 快，但知识会留缺口 |
| **只跑实验** | 已有网络背景，想验证判断 | 从 `labs/` 目录挑实验跑，课只当参考手册 | 容易停在"跑通了"这一步 |

第三种读法有个隐性成本。实验输出需要背景知识才能读懂，"PFC pause 帧数 12 万"这个数字本身不会告诉你这是灾难还是日常。

### 每课的固定结构

七段，顺序一致。前面是结论，中间是机制，后面是能动手的部分。

1. **本节目标**：可验收的动作，不是"了解"
2. **机制拆解**：因果链，配类比与命令
3. **经验映射**：把你已有的 IDC 经验翻译过来
4. **判读与实操**：指标口径、命令、实验入口
5. **练习**：2 道必答加 2 道自测，答案折叠，配评分维度
6. **本课要点**：一屏内可复述
7. **参考资料**：机制类断言的可验证来源

练习题不给标准答案的对错判定，只给评分维度。这套材料的用法是自答、展开、按维度自评，缺口自己会显形。

### 三条使用约定

**实验都是教学级模型。** 每个 L1 实验开头都有一句声明：非硬件行为等价。模型能复现因果链与量级关系，不能替代真机验证。

**数字都要带单位与量级。** 本课程里出现的带宽、时延、比例，都是公开资料或构造示例的量级值。看到"秒级"就去想它对应哪个数量级，看到"千卡小时"就去想它等于多少电费。

**术语首现给英文对照。** 智算网络的术语中文译名不统一，PFC 有人叫基于优先级的流量控制，有人直接说 PFC。所以每个术语第一次出现时会带一次英文全称，后面只用缩写。

## 练习

**必答 Q1**：某同事说"我们集群的丢包率是 0，链路肯定是健康的"。这句话在智算网络里错在哪，正确的判断要看什么。

<details>
<summary>参考答案与评分维度</summary>

**参考答案**

丢包为 0 是无损网络的设计结果，并非健康证据。PFC 逐跳反压让队列不满就不丢，代价是上游被暂停。所以丢包率是"失效后的结果指标"，不是"劣化中的过程指标"。

正确的判断看三类过程信号。一是 PFC pause 的收发趋势，按优先级与端口拆开看。二是 ECN 标记率与队列水线，代表拥塞在多大范围内被压制。三是业务侧证据，也就是训练的每步耗时与集合通信耗时分解。

再加一条方法论：看一阶差分与分位数，少看均值。CRC 从 0 到 12 在阈值体系里是正常的，在趋势上已经是光模块劣化的第一步。

**评分维度**：指出丢包 0 是无损设计而非健康证明（必需）。给出至少两个过程信号并说明为什么它们更早（必需）。提到趋势与分位数的判断方法（加分）。
</details>

**必答 Q2**：你刚接手一个千卡集群，手上没有任何历史数据。给出第一周该采集什么、该建什么口径的最小方案。

<details>
<summary>参考答案与评分维度</summary>

**参考答案**

第一周的目标是建立基线，不是建大屏。

采集层分三档。端口级：CRC、FEC 纠正、丢包、流量，10 到 30 秒一次，覆盖全部上行口。队列级：队列水线、PFC pause 收发、ECN 标记，1 到 5 秒一次，按端口与优先级拆维度。业务级：训练每步耗时、集合通信耗时分解，直接从训练框架日志拿。

口径层先定三条。CRC 增长率按小时窗口算一阶差分。ECN 标记率的分母明确写成"该端口该优先级发出的包数"。P99 时延用固定窗口，不用滑动均值。

存储上原始秒级数据只保留 7 天，聚合结果长期保留。第一周结束时导出一次全量快照，作为后续所有异常判断的对照基线。

**评分维度**：采集分档且频率与事件时标匹配（必需）。口径定义明确到分母（必需）。提出保存基线快照（加分）。只列指标名不给频率与口径（不通过）。
</details>

**自测 Q3**：为什么本课程把"遥测数据面"（M4）排在"无损机制"（M2）之后，而不是先教你用工具。

<details>
<summary>参考答案与评分维度</summary>

工具是手段，选择采什么是判断。M2 讲清 PFC 与 ECN 的分工之后，你才知道队列水线比端口丢包更早、PFC pause 要按优先级拆。

先学工具的顺序会让你采一堆无用数据。数据量爆炸之后再回头质疑采集策略，成本远高于一开始就想清楚。

**评分维度**：说清"采什么由机制决定"（必需）。提到采错数据的返工成本（加分）。
</details>

**自测 Q4**：如果只能带走一条结论离开这门课，你会选哪条，为什么。

<details>
<summary>参考答案与评分维度</summary>

没有唯一答案，判断标准是这条结论能否迁移到别的场景。

一个可接受的答案：**在同步训练的集群里，性能指标要按"最慢的那一份"来读，不能按平均来读。** 这条能从网络延展到存储、到调度、到任何有同步屏障的系统。

**评分维度**：结论可迁移（必需）。给出迁移的理由而不是复述课程（必需）。
</details>

## 本课要点

<Aside type="tip" title="本课要点">
- 核心问题：**指标全绿而任务变慢**。正常值在无损网络里不代表健康
- 三条断层：事件时标错位、观测粒度错位、正常值语义错位。三条会同时发作
- 六模块是因果链而非并列章节。跳读会让判读退化成背书
- 每课七段固定结构，练习只给评分维度，不给标准答案
- 实验是教学级模型，能复现因果与量级，不能替代真机验证
- 三种读法按处境选：顺序通读、按故障查、只跑实验
</Aside>
