这是整个课程的地基课。它只回答一个问题：**同样是以太网，为什么 AI 训练网络需要另一套观测方法？**

如果你来自传统 IDC 或云网络，前面的路很好走——你已有的能力（链路级探测、时序管道、指标口径设计）一条都不会浪费。但你必须先把四个默认假设换掉，否则后面每一课都会读得很别扭。

## 本节目标

学完本课，你应该能做到：

- 说出 AI 训练网络与有损 IDC 网络在 **流量模型 / 丢包语义 / 故障代价 / 遥测粒度** 四个维度的差异，并解释每一项背后的成因
- 解释为什么「TCP 反正会重传」这句话在 AI 训练网络上不成立
- 把手上已有的 IDC 监控能力逐项映射到智算场景，明确指出哪些可以直接复用、哪些必须替换
- 建立最基本的指标直觉：在无损网络里，**丢包是故障信号**，日常主指标换成 PFC pause、ECN 标记率、队列水线

## 机制拆解

### 差异一：流量模型 —— 小流密布 vs 大象流同步突发

传统 IDC 监控的是**线上业务流量**：用户请求从南北向进出，服务间调用在东西向流动。这批流量的特点是流很小（KB～MB 级）、数量极多、到达随机，偶发拥塞后队列很快排空。

AI 训练集群里几乎没有「用户流量」。一台 GPU 服务器（通常 8 张加速卡）在训练时做的主要事情，是和另外几百上千台服务器交换**梯度数据**：单条流就能打满 200Gbps 以上的端口，并持续整个训练周期——典型的大象流（elephant flow）。

更麻烦的是**同步突发**：分布式训练每完成一轮计算，所有 worker 必须在同一时刻向同一个目的地汇聚数据（AllReduce）。上万张网卡在同一瞬间朝同一组端口倾泻流量，这就是 incast。它不是偶发事件，而是**每个训练步都重来一次的固定节奏**。

| 维度 | 有损 IDC（小流为主） | 智算中心（大象流为主） |
|---|---|---|
| 流向 | 南北向为主 | 东西向为主 |
| 单流特征 | KB～MB，数量极多、随机 | 单流打满端口，持续整个训练周期 |
| 负载分担 | 静态 hash 大致够用 | hash 一旦失衡，某条路径直接被单流打满 |
| 拥塞形态 | 偶发，队列很快排空 | AllReduce 周期性同步突发（incast） |

### 差异二：丢包语义 —— 从「背景噪声」到「事故本身」

这是本课最核心的一次语义翻转，请放慢速度。

- **有损网络**：丢包率 0.01% 属于正常波动，TCP 静默重传补上，上层应用无感。丢包是**排障线索**。
- **无损网络**：RDMA 把重传的活儿从内核协议栈剥离了（见 [RDMA：AI 训练为什么绕过内核](./03-rdma/)），网络一旦丢包，恢复代价极高。所以整张网被设计成**依靠 PFC / ECN 从机制上避免丢包**（见 [PFC](../02-lossless/05-pfc/) 与 [ECN + DCQCN](../02-lossless/06-ecn-dcqcn/)），工程上普遍要求丢包率低到 `1e-5` 量级甚至更低。

<Aside type="caution" title="关键推论">
在无损网络里，**「丢包」不再是日常指标，而是发生了机制性故障的信号**——PFC 失效、配置错误、死锁前兆。

与此同时，日常要盯的主指标换成了另一组：**PFC pause 次数 / ECN 标记率 / 队列水线**。你的监控面板从此要换一套口径，而不是把老面板里的阈值调紧。
</Aside>

### 差异三：故障代价 —— 从「单机影响」到「小时 × 千卡」

传统 IDC 里网络抖一下，影响的是一批请求，切流后很快恢复。而在万卡训练集群里，训练是一个**高度同步**的过程：一万张卡像一个人一样齐步走，任何一条链路故障导致个别 Rank 卡住，**全体训练都会停摆等待**。

恢复手段通常是 **checkpoint 回退**：从上一个存档点重新跑。两次 checkpoint 之间可能间隔几十分钟，这意味着一次网络故障的代价约等于「**回退时间 × 一万张卡的电费与折旧**」。所以智算网络对 MTTR 的要求从小时级压到**分钟级**——这也解释了为什么「降低智算网络 MTTR」几乎出现在每一个智算网络 SRE 岗位的描述里。

### 差异四：遥测粒度 —— 从分钟轮询到秒级订阅

传统设备采集多是 SNMP 风格：分钟级轮询端口计数器。这套粒度在无损网络里不够用：

- PFC pause 的风暴可能**在几秒内**把队列打爆，分钟级采样会完全错过；
- incast 突发是亚秒级事件，轮询看到的只是「平均值永远正常」。

所以智算网络普遍改用 **gNMI 流式订阅**（见 [gNMI + OpenConfig 遥测](../04-telemetry/11-gnmi/)）：交换机像推消息队列一样，把秒级甚至亚秒级的队列、ECN、pause 指标推给采集端。这条数据管道与「Kafka → 流处理 → 时序库」完全同构——**缺的只是数据源（设备管控面），管道能力可以直接复用**。

## 经验映射

从 IDC 转过来的能力不是负担，但需要逐项判断「能不能直接搬」：

| 已有能力 | 价值 | 说明 |
|---|---|---|
| 链路级主动探测 / 五元组 hash 路径覆盖 | ✅ **更值钱** | 大象流时代，hash 极化（多条大象流哈希到同一路径）是高频事故模式，只有路径级观测能发现 |
| 时序数据管道（采集 → 消息队列 → 存储 → 查询） | ✅ 直接复用 | 与设备侧 gNMI 订阅只是数据源不同 |
| 告警收敛 / 根因分析（RCA） | 🟡 需改造 | 指标口径变了，阈值与关联规则要重做 |
| 丢包率 / 时延 / 抖动为主的面板 | ❌ 必须替换 | 主指标应为 PFC pause、ECN 标记率、队列水线、逐路径丢包 |
| 「网络故障 → 切流兜底」的处置习惯 | ❌ 不成立 | 训练流量无法切流，只能定位并快速恢复 |

<Aside type="note" title="经验映射（IDC → AIDC）">
你过去做的「五元组哈希 ECMP 路径覆盖」，在智算网络里价值反而**更大**：大象流时代，多条大象流哈希到同一条路径（hash 极化）是真实且高频的事故模式。只有路径级观测才能发现「某条 ECMP 路径被单条大象流打满」，而这在设备级聚合指标里完全看不见。

同理，你熟悉的「30 分钟发现 → 秒级发现」只是 MTTR 的**发现**环节；智算场景要求发现 + 定位 + 恢复全链路分钟级。发现环节你已有积累，定位（设备遥测关联）与自愈（自动化处置）是需要补的两环——这正是本课程 M4 / M5 的内容。
</Aside>

## 判读与实操

把上面的结论落成一张可以贴在值班台前的对照表：

| 观测项 | 有损 IDC 的典型做法 | 智算网络的典型做法 |
|---|---|---|
| 采集方式 | SNMP 轮询，分钟级 | gNMI 流式订阅，秒级 / 亚秒级 |
| 主指标 | 丢包率、时延、抖动、带宽利用率 | PFC pause 帧数与时长的分布、ECN 标记率、队列水线、逐路径丢包 |
| 丢包的解读 | 背景噪声，先看趋势 | 故障信号，要立刻定位到端口 / 路径 |
| 视角 | 设备级聚合 + 抽样探测 | 设备级 + 路径级 + 作业级（按训练任务归因） |
| 排障目标 | 恢复业务可用性 | 缩短停机（MTTR）并保住训练进度 |

**自检动作**：翻一遍你现在维护的监控面板，逐个卡片标注「✅ 可直接复用 / 🟡 需改口径 / ❌ 需要新建」。写不出结论的，通常说明该指标的语义你还没搞清楚——那就正好是下一步要补的功课。

## 练习

<Aside type="tip" title="怎么做题">
先自己写答案（哪怕只有三行），再展开对照参考答案，最后按「评分维度」给自己逐条打分。写不出来不是问题，跳过自评才是问题。
</Aside>

**必答 Q1**：用你自己的话（不要照抄原文）解释：为什么 AI 训练网络要把丢包率压到 `1e-5` 量级以下？「TCP 反正会重传」这句话错在哪里？

<details>
<summary>参考答案与评分维度</summary>

**参考答案**

「TCP 会重传」在有损网络里成立，是因为重传由**内核协议栈**完成，代价是一次 RTT 量级的延迟，业务几乎无感。RDMA 恰恰是为了绕过内核才出现的：数据面在网卡上跑，没有协议栈帮你兜底，丢包只能由上层拥塞控制算法感知丢包后重传，代价是**毫秒级到毫秒×N 的微突发打断 + 拥塞控制窗口重置**。

更关键的后果是**同步放大**：AllReduce 的每一轮都要等所有 Rank 到齐，一个包重传带来的延迟会传导成整个训练步的等待，一万张卡一起等。所以丢包不是「损失一点带宽」，而是「全局同步屏障被拉长」——这就是必须从机制上避免丢包的根因。

**评分维度**

- 说出 RDMA 绕过内核 → 丢失了协议栈的重传兜底（必需）
- 说出重传代价在同步训练里被放大到全局（必需）
- 提到 PFC / ECN 是「避免丢包」而非「丢了再补」（加分）
- 只回答「RDMA 快、TCP 慢」而没有触及重传语义（不通过）
</details>

**必答 Q2**：假设把你维护的 IDC 监控系统原样部署到一个万卡智算集群（先不考虑它是否能采集到设备数据）：**你能立刻发现哪类问题、又会漏掉哪类问题？** 各举至少两个并说明理由。这是本课最重要的思考题。

<details>
<summary>参考答案与评分维度</summary>

**参考答案（要点，不要求一致）**

能发现的：

1. **链路彻底中断**——探测器到不了、端口 down，任何监控体系都能发现；
2. **带宽利用率异常 / 长期饱和**——端口计数器级别的现象，老体系能看见，只是粒度和阈值不一定合适；
3. **端到端时延劣化**——如果是基于探测包的方案，能感知到某条路径变慢。

会漏掉的：

1. **PFC 风暴与 PFC 死锁**——老体系根本没有 pause 帧计数与持续时长指标，风暴发生时端口利用率甚至可能是「正常」的；
2. **incast 造成的微突发与 ECN 标记**——分钟级轮询取平均，亚秒级突发被抹平；
3. **hash 极化 / 单条大象流打满某条路径**——设备级聚合指标被稀释，需要逐路径观测；
4. **单个光模块的渐进劣化**（FEC 纠错计数、误码上升）——不在老指标集里。

**评分维度**

- 能区分「现象层面能看见」与「有指标能定位」（必需）
- 漏掉项至少覆盖 PFC / ECN / 微突发 / 光模块中的两项（必需）
- 说明「为什么漏」（无指标口径 or 粒度不够），而不是只说「没做过」（必需）
- 能主动提出补救方向（新增 pause / ECN 指标、路径级探测、秒级订阅）（加分）
</details>

**自测 Q3**：AllReduce 的同步突发，和电商大促的流量洪峰，最本质的两个区别是什么？

<details>
<summary>参考答案与评分维度</summary>

**参考答案**

① **周期性**：大促洪峰是事件驱动的偶发流量，incast 是每个训练步都发生的固定节奏——正因为它可预测，才有可能通过拓扑与参数预调优（如 rail-optimized 拓扑、拥塞控制参数）。

② **同步性与木桶效应**：大促流量从大量随机入口汇聚，压力被时间与空间摊薄；incast 是上万个源在**同一时刻**朝同一目的地同步倾泻，瞬时压力远超平均负载，而且任何一个 Rank 慢都会拖住全体。

**评分维度**：两点各 1 分；额外指出「可预测 → 可预调优」或「木桶效应 → 单个慢节点即全局慢」加 1 分。
</details>

**自测 Q4**：为什么说「路径级覆盖」在智算网络里比在传统 IDC 里更值钱？

<details>
<summary>参考答案与评分维度</summary>

**参考答案**

大象流 + hash 分担的组合，让「某一条路径劣化」变得既高频又隐蔽：单条大象流哈希到某路径把它打满，或者一个坏光模块只影响个别链路。设备级聚合指标（整机丢包率、时延均值）会被稀释到看不见——一台 64 端口的交换机上，1 条路径占 1.5%，聚合指标永远「正常」。

只有逐路径观测能把「某条 ECMP 路径被单流打满」这类问题暴露出来。这正是路径级探测方案在智算网络里的核心价值：它观测的是**流量实际走过的那条路**，而不是设备的平均表现。

**评分维度**

- 说出聚合指标会稀释局部劣化（必需）
- 说出大象流使单路径饱和成为高频模式（必需）
- 能给出数量级直觉（如「1 条路径 / 64 端口 ≈ 1.5%」）或具体观测手段（加分）
</details>

## 本课要点

<Aside type="tip" title="本课要点">
- **流量模型**：南北向小流 → **东西向大象流 + AllReduce 周期性同步突发（incast）**
- **丢包语义**：丢包从「背景噪声 / 排障线索」变成「**机制性故障的信号**」；日常主指标换成 PFC pause、ECN 标记率、队列水线
- **故障代价**：网络故障 = 全体训练停摆 + checkpoint 回退，MTTR 要求**分钟级**
- **遥测粒度**：SNMP 分钟轮询 → **gNMI 秒级流式订阅**；数据管道可直接复用，缺的只是数据源
- **能力映射**：路径级覆盖在智算网络**更值钱**；发现环节你已有积累，定位与恢复是学习方向
</Aside>
