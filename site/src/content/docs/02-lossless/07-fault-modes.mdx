前四课的机制（RDMA、RoCEv2、PFC、ECN/DCQCN）现在要落到一个具体问题上：**这些机制失效时，现场长什么样？**

本课把四大典型故障按统一框架拆开：**网络里发生什么 → 路径级探测看到什么 → 看不到什么 → 要补什么才能定位**。最后那张汇总表，是这一模块的落点。

## 本节目标

- 用统一框架描述四类故障：成因、可观测信号、定位缺口
- 记住每类故障的「指纹」，例如「断崖超时 + 丢包率为 0」指向死锁
- 说清主动探测（路径视角）与设备遥测（队列视角）各自的能力边界，以及为什么必须叠加
- 拿到真实告警时，能按「先判类型 → 再看设备侧 → 再沿拓扑收窄」的顺序推进
- 把「周期性尖刺」这类现象与训练任务的节奏关联起来

## 机制拆解

### 案例一：PFC 风暴（最常见）

**网络里发生什么**：某个下游持续喊停。典型触发是三选一：一块故障或劣化的网卡、一个消费不动的应用进程、某一跳设备 PFC 配置错误。暂停帧沿链路逐跳向上游成片传播，大量链路的实际吞吐暴跌。

**特征：不丢包、无错误计数，但整张网突然集体变慢。**

| 视角 | 现象 |
|---|---|
| ✅ 路径级探测看到 | 路径**时延剧烈膨胀、抖动飙升**（探测包出端口被 pause 压住）；多条路径被覆盖时能看出「劣化呈区域性成片分布」而非单点 |
| ❌ 看不到 | 根因在哪台设备、哪个队列、谁最先喊停；是故障网卡还是配置错误；**受害者与肇事者无法区分** |
| 🔧 定位需补充 | 设备侧 **PFC pause 收发计数（按优先级）+ 队列深度**的秒级遥测，沿拓扑做多跳关联，找「暂停波源头」——第一个 pause 计数异常上涨、且自身入流量正常的设备 |

### 案例二：PFC 死锁（最凶险）

**网络里发生什么**：多台设备的队列形成**环形等待**（A 等 B 排空、B 等 C、C 等 A），谁也不放行，暂停状态永久卡死。触发常与配置或拓扑突变相关（路由收敛瞬间、链路翻转、Fabric 配置不一致）。若 watchdog 未配或失效，环路不会自愈。

| 视角 | 现象 |
|---|---|
| ✅ 路径级探测看到 | 覆盖受影响路径的探测**完全超时**（不是慢，是不通）——时延曲线从正常直接断崖，而**丢包率可能依然是 0**（报文都卡在队列里，一个没扔） |
| ❌ 看不到 | 「不通」与「链路 down」无法区分；环路在哪几台设备之间；watchdog 是否在自动恢复 |
| 🔧 定位需补充 | **watchdog 事件 + stuck 队列状态 + 端口 up/down** 遥测，结合拓扑做环检测 |

<Aside type="note" title="探测在这里的真实价值">
探测的价值不在替设备遥测定位根因，而在**秒级圈定受影响的路径集合**。

路径集合与拓扑求交集，受影响设备的候选集立刻缩小一个数量级；设备侧排查的范围从「全网」收窄到「几条路径经过的几台设备」。这就是「路径级探测 + 设备遥测」1+1>2 的地方：前者给你时间和范围，后者给你精度。
</Aside>

### 案例三：incast 丢包（训练节奏性劣化）

**网络里发生什么**：AllReduce 同步突发，上万个源在同一瞬间向同一目的地汇聚，出端口队列在**微秒级**涨满。DCQCN 能压住一部分，但极端 incast 下压不住：

- PFC 兜底成功 → 慢但不丢；
- PFC 水线没配好或响应不及时 → **真的丢包** → RDMA 粗粒度重传 → 该轮集合通信被严重拖慢。

| 视角 | 现象 |
|---|---|
| ✅ 路径级探测看到 | **周期性**的时延尖刺或丢包，周期与训练步节奏吻合（毫秒～秒级，取决于模型与并行策略）。这是 incast 最独特的指纹：**规律性周期 + 指向同一汇聚点** |
| ❌ 看不到 | 这是「哪个训练任务、哪一次 AllReduce」造成的（缺流↔任务关联）；汇聚设备在尖刺瞬间的队列状态（探测是采样，不是逐包）；「可接受的 ECN 降速」与「已丢包的事故级 incast」的区分需要设备侧数据 |
| 🔧 定位需补充 | 汇聚设备的 **ECN 标记率 + PFC pause + 丢包计数**秒级遥测（上一课的三级指标在这里用上），以及**流 ↔ 训练任务 / Rank 的关联**——把「某端口 incast」翻译成「任务 X 的 Rank 12 所在 rail 拥塞」 |

### 案例四：队头阻塞 HoL（无辜受害者问题）

**网络里发生什么**：同一优先级队列里，流 A 的目的地堵了，暂停波把同队列去往健康目的地的流 B 一起冻住。作为故障案例，它的特殊之处在于：**网络没有任何东西坏了**，纯粹是共享队列的设计代价。

| 视角 | 现象 |
|---|---|
| ✅ 路径级探测看到 | 流 B 的路径时延升高；因为做的是**路径级覆盖**，能确认「B 的整条路径只有这一段共享队列与 A 重叠」——这是定位 HoL 的关键证据，设备级监控做不到 |
| ❌ 看不到 | 肇事流 A 是谁（它可能完全不在探测路径上）；队列内多条流的交织关系需要逐流遥测才能看穿 |
| 🔧 定位需补充 | 同队列多流关联：设备侧逐队列时延 / 水线 + 路径级探测交叉定位「共享段」；证明「A 堵 → B 慢」还需两者的**时间相关性分析** |

### 汇总：本模块的落点

| 故障 | 路径级探测看到 | 看不到 | 定位必需的补充 |
|---|---|---|---|
| **PFC 风暴** | 时延膨胀、区域性成片劣化 | 根因设备/队列、肇事者身份 | pause 计数（按优先级）+ 队列深度，多跳拓扑关联找源头 |
| **PFC 死锁** | 断崖式超时，**丢包率为 0** | 与链路 down 的区分、环路位置 | watchdog 事件 + stuck 队列 + 端口状态 + 环检测 |
| **incast** | **周期性**尖刺（与训练步同步） | 哪个任务/AllReduce 肇事、尖刺瞬间队列状态 | ECN/PFC/丢包三级指标秒级遥测 + 流↔任务关联 |
| **HoL 阻塞** | 无辜路径时延升高（**路径级可证清白**） | 肇事流是谁、队列内多流交织 | 逐队列遥测 + 路径交叉定位共享段 + 时间相关性分析 |

<Aside type="caution" title="四个案例的共同结论（值得记住）">
主动探测的观测对象是**路径**，强项是**秒级发现 + 圈定受影响路径集合**；但它答不出「在哪台设备、哪个队列、为什么」。

必须叠加**设备遥测（gNMI）+ 拓扑关联 + 任务关联**。

这是**架构叙事**，不是「探测方案不够用」的短板叙事：探测是神经元末梢（快、广、粗），设备遥测是深度感知（准、窄、慢），平台负责把两者拼成根因。
</Aside>

## 经验映射

| 有损 IDC 里的直觉 | 在无损网络里必须修正 |
|---|---|
| 「丢包率涨了 → 出事了」 | 无损网络里最常见的故障**丢包率为 0**，要看时延与 pause |
| 「链路不通 → 查链路」 | 「不通但没丢包」= 死锁，是本场景特有的矛盾组合 |
| 「告警单点定位根因」 | 拥塞上游化，症状现场与根因现场分离，必须做多跳关联 |
| 「平均值看趋势」 | 微突发被平均值抹平，要看秒级甚至亚秒级的峰值 |
| 「网络问题归网络，任务慢归任务」 | 必须做流 ↔ 任务关联，否则无法回答「谁受害、谁肇事」 |

一个实用的话术模板（评审会或线上追问时都能用）：

> 「我的探测能力在智算网络里依然是最快的发现手段，尤其是死锁断崖、周期性 incast 这类设备级均值完全看不见的问题。但我也清楚它的边界——它走有损队列，只能看到『这条路径劣化了』，看不到『哪个队列被暂停』。所以需要用 gNMI 设备遥测和拓扑关联把『发现』和『定位』闭环起来。」

这段话同时展示三件事：实战能力、边界认知、补齐方向。

## 判读与实操

### 从告警到根因的四步

```text
① 判类型   看「丢包率是否为 0」「是否周期性」「是否区域性成片」三个特征 → 初判四大故障
② 拉设备侧 该路径经过的每台设备：pause 计数（按优先级）、队列水线、ECN 标记、discard
③ 沿拓扑收窄  找第一个「pause 异常上涨但入流量正常」的设备，或第一处 discard
④ 做关联   与训练任务/作业计划对齐：受影响的 Rank 属于哪个任务、哪一段并行策略
```

### 快速分诊表

| 观测特征 | 初判 | 下一步动作 |
|---|---|---|
| 时延膨胀、丢包为 0、多路径同时劣化 | PFC 风暴 | 逐跳拉 pause 计数，找源头 |
| 断崖超时、丢包为 0、路径集合集中 | PFC 死锁 | 查 watchdog 事件与 stuck 队列，做环检测 |
| 周期性尖刺、与训练步同步、指向同一汇聚点 | incast | 查汇聚设备 ECN/PFC/丢包三级指标 |
| 部分路径温和升高、其余路径正常 | HoL 阻塞 | 找共享段，做时间相关性分析 |

### 命令示例

```bash
# 路径级：连续性探测（示意）——关注时延分位与超时，而不是均值
# 设备侧：按优先级看 pause，按队列看水线与丢弃
ethtool -S <ifname> | grep -Ei 'pause|discard|out_of_buffer'
show priority-flow-control interface <intf> counters    # 交换机 CLI 语义示意
show queue-monitor interface <intf>                     # 队列水线/丢弃
```

判读要点：**先用「是否丢包 + 是否周期性」把四类故障分层**，再决定去拉哪一类数据。直接一头扎进设备计数器，很容易在没有假设的情况下被几千个计数器淹掉。

## 练习

**必答 Q1**：完整走一遍场景。「探测平台告警：某 POD 内 30+ 条路径时延在同一秒集体劣化 5 倍，丢包率不变。」请回答：① 最可能是四类故障里的哪个（或哪几个）？② 你会调取哪三类设备侧数据来确认？③ 沿拓扑怎么收窄根因范围？

<details>
<summary>参考答案与评分维度</summary>

**参考答案**

① 首选 **PFC 风暴**（多路径同时劣化 + 不丢包 + 区域性成片）；次选 PFC 死锁的早期阶段（但死锁通常表现为超时而非 5 倍劣化）。incast 也可以造成多路径劣化，但「同一秒、成片、非周期性」更像风暴。

② 三类数据：**按优先级的 PFC pause 收发计数**（确认反压发生且定位方向）、**队列水线/深度**（确认是否贴近 XOFF）、**ECN 标记率与 discard**（区分「机制在工作」与「机制已失效」）。

③ 沿拓扑：从受影响路径的汇聚方向逐跳往上游找，定位**第一个 pause 计数异常上涨、但自身入流量正常**的设备，那就是暂停波的源头附近；同时核对这几跳的 PFC 配置一致性。

**评分维度**

- 类型判断正确且有理由（必需）
- 三类数据能对应到「是否反压 / 反压强度 / 机制是否失效」（必需）
- 收窄策略是「沿拓扑找第一个异常点」而不是「逐台设备看」（必需）
- 能提出先验证配置一致性（加分）
</details>

**必答 Q2**：只用手头的数据（探测时延/丢包曲线 + 设备计数器），怎么区分「PFC 风暴」和「周期性 incast」？至少给出两个可操作的区分点。

<details>
<summary>参考答案与评分维度</summary>

**参考答案**

1. **时间形态**：incast 与训练步同步、**周期性**重复、尖刺短（毫秒级）；PFC 风暴是**持续性**劣化，起点明确、结束依赖根因消除，通常不呈现严格周期。
2. **空间形态**：incast 的劣化指向**少数汇聚点**（AllReduce 的接收侧），受影响路径集合随时间稳定；风暴呈**区域性成片**，且会沿拓扑向上游蔓延。
3. **设备侧佐证**：incast 表现为汇聚设备队列瞬时冲高 + ECN 标记率高；风暴表现为**源头附近的 pause 计数长时间持续上涨**，且与队列水线不完全同步（源头可能是消费不动的端口而非拥塞端口）。
4. **相关性**：把尖刺时间点与训练作业日志（step 时间）对齐，能对齐的是 incast。

**评分维度**：两个以上可操作区分点，且每个都说明「看哪个数据、怎么判」（必需）；能提出与训练日志做时间对齐（加分）。
</details>

**自测 Q3**：「路径完全超时 + 丢包率为 0」指向什么故障？为什么丢包率为 0 反而是重要线索？

<details>
<summary>参考答案与评分维度</summary>

指向 **PFC 死锁**（或永久性暂停）。丢包率为 0 说明报文没有被丢弃，而是全部卡在队列里等待，这正是 PFC「不丢包」机制的阴暗面：它保证了不扔，也保证了能永久堆积。

如果是链路 down，报文在本地即被丢弃，丢包率会飙升。所以「不通但没丢」是无损网络特有的矛盾组合，本身就是关键诊断特征。

**评分维度**：答出死锁（必需）；解释「卡住 vs 丢弃」的区别（必需）；提到 watchdog 缺失是长期卡死的条件（加分）。
</details>

**自测 Q4**：为什么说「路径级覆盖」在 HoL 案例里特别有价值？

<details>
<summary>参考答案与评分维度</summary>

HoL 的受害者是「无辜路径」：设备级均值看不出它劣化，而路径级探测能确认「该路径除了与肇事流共享的那一段，其余各段全部正常」，把怀疑范围锁定到共享段。

设备级监控只有单点视角，无法证明「B 慢是因为 A」这种跨流因果；路径级数据加上时间相关性，才能把因果链补全。

**评分维度**：说出「证明清白 / 锁定共享段」（必需）；说出设备级单点视角的局限（必需）。
</details>

## 本课要点

<Aside type="tip" title="本课要点">
- **PFC 风暴**：不丢包但全网络慢；探测见区域性时延膨胀；定位靠 pause 计数沿拓扑找源头
- **PFC 死锁**：断崖超时 + **丢包率为 0** 是指纹；定位靠 watchdog 事件 / stuck 队列 + 环检测
- **incast**：周期性尖刺，与训练步同步；定位靠 ECN/PFC/丢包三级指标 + 流↔任务关联
- **HoL**：无辜路径受累；**路径级覆盖能证明清白、锁定共享段**
- 总叙事：**探测 = 秒级发现 + 圈定路径集合；设备遥测 = 队列级根因；平台 = 拼图闭环**
- 实战顺序：先判类型（丢包/周期/空间形态）→ 拉设备三件套 → 沿拓扑收窄 → 做任务关联
</Aside>
