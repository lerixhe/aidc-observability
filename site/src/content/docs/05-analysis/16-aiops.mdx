前面几课解决了“数据从哪来”。本课开始回答“拿到数据之后怎么用”。

先说清一个常见缺口：很多人做过阈值预警，但没有做过告警收敛、根因定位与自愈闭环。本课的目标是**能说清每一层解决什么问题、数据从哪来、和自己的观测能力怎么拼**，而非动手写图算法。

## 本节目标

- 说清万卡规模下“告警风暴”的成因与代价
- 按依赖顺序复述 AIOps 四层架构，并指出哪一层最容易做成空中楼阁
- 用图的语言描述网络故障定位：节点、边、事件标记、共同祖先
- 区分三代根因定位算法的适用场景，并解释为什么“难点不在算法”
- 设计自动化处置的分级与兜底，说清最大风险

## 机制拆解

### 问题：万卡规模的告警风暴

传统 DC 里一台交换机故障可能产生几条告警。万卡集群里，同一个故障会产生上千条。

- 该设备的 LLDP / BGP 邻居批量告警。
- 所有经过它的路径：探测告警、丢包告警、时延告警。
- 受影响 Rail 上的流量偏离告警、队列水位告警。
- 上层应用侧：训练任务变慢、NCCL timeout。

**一个物理故障 → 几百上千条告警，且广播给所有人。** 值班工程师被淹死，而真正有用的信息只有一句：“X 设备 down 了”。

AIOps 的第一层工作，就是把这一句话从一千条告警里捞出来。

### 四层架构（三分钟答题框架）

| 层 | 做什么 | 关键依赖 |
|---|---|---|
| **① 数据基础** | 秒级遥测 + 路径探测 + 任务元数据 + 拓扑 | 没有数据层，后面全是空中楼阁 |
| **② 告警收敛** | 去重、抑制、聚合；按同源与时间窗口折叠，按拓扑归并为 incident | 需要有拓扑与告警语义 |
| **③ 根因定位（RCA）** | 在收敛后的 incident 集合里回答“根因是哪个节点/链路” | 需要有干净的图与对齐的时间 |
| **④ 自动化处置** | 隔离端口、切换路径、建议换件、通知训练平台做任务级规避 | 需要可靠的执行与回滚机制 |

**注意依赖顺序不可跳**。没有收敛好的告警，RCA 会被噪声淹没。没有可靠的 RCA，自动化处置等于自动放大故障。

<Aside type="note" title="经验映射（IDC → AIDC）">
诚实的对照：如果你做过实时数据管道与基于历史阈值的预警，那么你已经完成了 ① 的大半和 ② 的最简版，③④ 是缺口。

但要注意：**七大故障课里你已经做过一次朴素 RCA**。探测发现受影响路径集合，与拓扑求交集，缩小设备候选集，这就是图推理的最简形式。

缺的不是思维方式，是把这套手工推理**产品化、自动化**的经验。这句话说出来，比假装精通图算法可信得多。
</Aside>

### 图计算做 RCA：把“推理”变成“算法”

**第一步：网络本来就是一张图。** 设备 = 节点，链路 = 边，接口/队列/模块 = 节点属性，告警与指标异常 = 节点/边上的**事件标记**。

这张图由 LLDP / BGP 邻居发现加配置数据自动构建。这正是“拓扑是一等公民”的兑现处，拓扑相当于这张图的主键。

**第二步：故障传播假设。** 网络故障沿拓扑**向下流**：Spine 故障 → 其下所有 Leaf 的路径异常 → 众多任务告警。

反过来推：**若干告警节点的“共同上游祖先”就是根因候选**。

**第三步：算法只是把这句话自动化。**

| 代数 | 方法 | 特点 | 适用 |
|---|---|---|---|
| 第一代 | 故障树 / 人工规则 | 准，但维护不动 | 已知的高频模式 |
| 第二代 | 相关性 + 图搜索（公共祖先、传播路径评分） | 朴素有效，工程主流 | 绝大多数线上场景 |
| 第三代 | Random Walk / GNN | 学习“故障通常从哪类节点爆发” | 前沿探索，大厂试点 |

<Aside type="caution" title="工程真相（讲这个比背算法加分）">
图计算 RCA 的**难点不在算法，在数据质量**。

- 拓扑要准。配置漂移会让图失真，公共祖先直接算错。
- 事件时间要对齐。时钟未同步会把传播方向判反。
- 告警要收敛好。垃圾进垃圾出。

所以“①数据 → ②收敛 → ③RCA”的建设顺序本身就是认知加分项。本质上，这一层的活就是图上的降噪与归因，算法只是成熟工具，输入错了输出必然错。
</Aside>

### 大模型进来之后

大模型在 AIOps 四层里的落点：

| 层 | 大模型能做什么 |
|---|---|
| ② 告警收敛 | 告警摘要与聚类描述（把 50 条告警写成人话） |
| ③ RCA | 检索历史相似故障（RAG），辅助给出候选根因与证据链 |
| ④ 处置 | Agent 调用工具（查指标、查拓扑、执行预案） |

第 ④ 层是后续课程的正题，本课先建立边界认知。

## 判读与实操

### 一个可落地的最小闭环

```text
① 数据：gNMI 订阅（秒级）+ 探测结果 + 拓扑图（LLDP/BGP 自动发现）+ 任务元数据
② 收敛：同设备同时间窗的告警折叠成一个 incident；下游告警标记为「疑似派生」
③ RCA ：incident 节点集 → 图上找共同上游祖先 → 按传播路径打分排序 → 输出候选根因
④ 处置：候选根因 + 置信度 → 低危动作自动、高危动作审批 → 执行后验证 → 不达预期回滚
```

### 质量指标（比算法选择更重要）

| 指标 | 含义 |
|---|---|
| 告警压缩比 | 一千条告警压成几个 incident |
| 根因命中率 | 人工确认的根因是否在候选列表 Top-3 内 |
| 误报率 / 漏报率 | 收敛规则与阈值的效果 |
| 处置成功率与回滚率 | 自动化是否可信 |
| 平均定位时长 | RCA 环节对 MTTR 的实际贡献 |

判读要点：**先有质量指标，再谈算法选型**。没有命中率与压缩比的度量，任何“我们上了图算法”都无法证明价值。

## 练习

**必答 Q1**：用四层框架做一段三分钟陈述：“如果让你给万卡集群建智能运维体系，你怎么分层搭建，每层解决什么？”控制在 400 字内。

<details>
<summary>参考答案与评分维度</summary>

**参考答案（结构示意）**

① **数据基础**：gNMI 秒级遥测（队列、PFC、ECN、CRC/DOM）+ 路径级探测 + 任务元数据 + 自动发现的拓扑图。这一层决定后面能不能做，先解决采集分级与时钟对齐。

② **告警收敛**：同设备/同时间窗折叠，按拓扑归并为 incident，下游告警标记为派生，目标是告警压缩比一个数量级。

③ **RCA**：把网络建成图，用“共同上游祖先 + 传播路径评分”输出候选根因与证据链。先做朴素图搜索，等数据质量稳了再考虑学习类方法。

④ **处置**：分级自动化（低危自动、高危审批），每个动作配“预期验证 + 回滚”，并有全局熔断开关。

**评分维度**：四层齐全且讲清各层职责（必需）。明确指出依赖顺序与“数据质量决定上限”（必需）。给出至少一个可量化指标（加分）。
</details>

**必答 Q2**：用图的语言重新描述“30+ 路径劣化 → 找 PFC 风暴源点”的排障流程：“节点 / 边 / 事件标记”分别是什么？“共同祖先搜索”在找什么？

<details>
<summary>参考答案与评分维度</summary>

**参考答案**

- **节点**：交换机、服务器网卡（端口可视为节点的接口属性）、光模块作为节点属性。
- **边**：物理链路及其上承载的方向性转发关系（含 ECMP 的多条等价边）。
- **事件标记**：路径时延异常（边上的事件）、pause 计数异常（节点/接口事件）、队列水线异常。

“共同祖先搜索”是在找：所有出现劣化的路径（边集合）在拓扑上的**共同上游汇聚点**。也就是那个“自身入流量正常、但 pause 计数最早异常上涨”的节点。它是暂停波最可能的发源方向。

**评分维度**：三类元素定义正确（必需）。共同祖先与“暂停波源头”的对应关系说清（必需）。提到“按时间先后排序而非只看空间祖先”（加分，这是避免误判的关键）。
</details>

**自测 Q3**：为什么说图计算 RCA 的难点不在算法而在数据质量？

<details>
<summary>参考答案与评分维度</summary>

三个“垃圾进”。一是拓扑图失真（配置漂移、静态拓扑表过期），公共祖先算错。二是事件时序乱（时钟未对齐），传播方向判反。三是告警未收敛（噪声节点污染图），评分被淹没。

图搜索与传播评分本身是成熟工具，输入错则输出错。因此建设顺序必须是“①数据 → ②收敛 → ③RCA”，跳步必失败。

**评分维度**：给出至少两个数据质量问题（必需）。强调顺序观（必需）。
</details>

**自测 Q4**：自动化处置（第 ④ 层）最大的风险是什么？怎么设计兜底？

<details>
<summary>参考答案与评分维度</summary>

最大风险：**错误处置放大的次生故障**，即根因误判时自动隔离正常端口或切换路径，把小故障变成大故障。

兜底设计四条。一是处置动作分级，可逆低危自动、不可逆高危人工审批。二是执行前做“预期验证”：处置后指标应如何变化，不达预期立即回滚。三是灰度启用，先部分集群。四是全量审计与全局熔断开关。

**评分维度**：说出“误判放大故障”（必需）。给出分级与回滚两类机制（必需）。提到熔断/灰度（加分）。
</details>

## 本课要点

<Aside type="tip" title="本课要点">
- 问题：万卡规模下**一个故障 = 上千条告警**，AIOps 第一任务是捞出“一句话的真话”
- 四层框架：**数据基础 → 告警收敛 → RCA → 自动化处置**，依赖顺序不可跳
- 图 RCA：网络天然是图。**故障沿拓扑向下传播 → 告警的共同上游祖先 = 根因候选**
- 算法三代：故障树（准但难维护）→ 图搜索（工程主流）→ RW / GNN（前沿）
- 难点在数据质量：**拓扑准、时序齐、告警收敛好**。先有质量指标，再谈算法
- 处置风险：误判放大故障 → 分级 + 预期验证 + 回滚 + 熔断
</Aside>
